Start

To build Heroes, you need clang 18 or newer. There is no installer yet.

Heroes is in beta: the language still changes. The five commands below work today, and the version they build is heroes {{version}}. Until 1.0.0, a change in the middle number can change the language itself, and a change in the last number never does.

Five commands

$ git clone https://github.com/heroes-lang/heroes
$ cd heroes
$ clang -I runtime seed/heroes.c runtime/runtime.c -o heroes-seed
$ ./heroes-seed build selfhost/main.hero -o heroes
$ ./heroes run examples/gallery/03-fallible.hero
read 42
failed: not_a_digit (expected 0-9)
20

The third line takes under ten seconds on a MacBook Air, the machine every measurement here comes from. It builds a compiler from one C file generated by Heroes, which is why clang is all you need.

That C file is updated at each release, the version the project publishes, and in between only when it has to be, so it is often the compiler of an earlier day. The fourth line has it build today’s compiler from its own source, written in Heroes, which takes a few minutes on the same machine. Every command after it uses ./heroes, the compiler of today, the one this site describes.

The line containing failed is expected output: the example reports a character it cannot convert to a number. Compilation succeeded.

If you do not have clang

clang is a C compiler, the program that turns C into something your computer runs. Heroes needs version 18 or newer, because that is the oldest one it is measured on. Ask yours what it is: 

$ clang --version

Any vendor prefix is fine, so Apple clang version 21 and Debian clang version 22 both count. Only the first number matters. If you already have Heroes built, ./heroes doctor answers the same question and says what is missing when something is.

macOS. The Command Line Tools bring Apple’s clang:

$ xcode-select --install

If that gives you a number below 18, which happens on an older macOS, install a current clang beside it with Homebrew and put its folder first in your PATH, the list of folders the terminal searches for a program: 

$ brew install llvm
$ export PATH="$(brew --prefix llvm)/bin:$PATH"

The compiler calls clang by name every time it builds something, the fourth line above included, so the clang that comes first in that list is the one that answers. After that the five commands work as written. The export line lasts as long as the terminal window; to keep it, add it to the file your shell reads when it starts.

Debian and Ubuntu.

$ sudo apt install clang

If your distribution’s clang is older than 18, apt.llvm.org publishes current packages for it.

Windows.

$ winget install LLVM.LLVM

On Windows the two build lines change in two ways: the first takes one more flag, and both names end in .exe, because Windows runs a file only when its name does, and clang names the file exactly as it is told: 

$ clang -I runtime seed/heroes.c runtime/runtime.c -Wl,/STACK:67108864 -o heroes-seed.exe
$ ./heroes-seed.exe build selfhost/main.hero -o heroes.exe

Windows gives a program’s first thread 1 MB of room for function calls where macOS and Linux give 8, and this compiler calls itself deeply while reading a program. The flag gives the compiler built from the C file 64 MB, the same room the compiler gives every program it builds on Windows, the one the second line makes included. The project’s own checks build the compiler this way on Windows at every change to it.

Run it from the repository

heroes run looks for the runtime, the support code that goes into every binary, in ./runtime. So run it from the directory you cloned into. From anywhere else, say where the runtime is: 

$ HEROES_RUNTIME=~/heroes/runtime heroes run hello.hero

When heroes run cannot find the runtime it says so and names the variable to set. If something else is missing, ./heroes doctor names it.

Your own program

This program needs only one file with a main function, where execution starts. No import statements or project file are required. 

$ printf 'function main()\n    print("we can be heroes")\n' > hello.hero
$ ./heroes run hello.hero
we can be heroes

heroes run compiles the file and launches it, leaving its working files in a build/ folder in the current directory. The second run of an unchanged file reuses what is in there.

One command, fifteen verbs

All the tools are available through heroes: lex, parse, check, build, run, test, fmt, add, fetch, doctor, mutate, probe, measure, grammar, this. There is no second binary, no build file and no plugin.

heroes fmt formats code using fixed rules for indentation, line breaks and order. The project’s source files, including the compiler, already follow those rules: the formatter returns them unchanged, byte for byte. This reduces formatting differences when you compare versions. Test files containing deliberate errors are preserved as written.

Every example on this site is a file in examples/, with the command that runs it and the output it prints.

If something goes wrong

./heroes doctor reports what is missing on your computer. Error messages say what the compiler expected and where in the code. The guide explains how to read them. If something is wrong that these do not explain, report it on the issue tracker: a program that should compile and does not, or one that compiles and gives the wrong answer, is the most useful thing this project can receive. A security problem, above all a Heroes program that crashes on a bad memory access or corrupts memory, does not go into a public report: send it with the private form on the repository’s Security tab, and SECURITY.md says how.
