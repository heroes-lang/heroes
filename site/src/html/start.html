Start

There is no installer. You need a C compiler, and that is the whole list.

The repository is still private, so the first line below does not work yet. Everything it names is already there. The addresses are final and they open with the code.

Four lines

$ git clone https://github.com/heroes-lang/heroes
$ cd heroes
$ clang -I runtime seed/heroes.c runtime/runtime.c -o heroes
$ ./heroes run examples/gallery/03-fallible.hero
read 42
failed: not_a_digit (expected 0-9)
20

The third line takes under four seconds on a MacBook Air, which is the machine every measurement on this site comes from. It compiles Heroes out of one C file that Heroes wrote: the compiler is written in Heroes, so the repository ships what it emits and clang is the only thing you need.

That middle line saying failed is not the build breaking. It is the example meeting a character it cannot read and saying so, which is what it was asked to do.

Run it from the repository

heroes run looks for the runtime, the support code that goes into every binary, in ./runtime. So run it from the directory you cloned into. From anywhere else, say where the runtime is: 

$ HEROES_RUNTIME=~/heroes/runtime heroes run hello.hero

It says exactly that when it cannot find it, and it prints the way out. If something else is missing, ./heroes doctor names it.

Your own program

A file needs nothing around it. No import lines at the top, no project file listing the other files. It needs a main, which is where the program starts. 

$ printf 'function main()\n    print("we can be heroes")\n' > hello.hero
$ ./heroes run hello.hero
we can be heroes

heroes run compiles the file and launches it, leaving its working files in a build/ folder beside you. The second run of an unchanged file reuses what is in there.

One command, eleven verbs

Everything the toolchain does goes through heroes: lex, parse, check, build, run, test, fmt, doctor, mutate, measure, this. There is no second binary, no build file and no plugin.

heroes fmt prints the one canonical form of a file: same indentation, same line breaks, same order. Every Heroes file in the repository comes back from it unchanged, byte for byte, so a difference between two versions of a file is a difference in what the program does.

Every example on this site is a file in examples/, with the command that runs it and the output it prints.

Heroes is not packaged yet: no installer and no public release, so the way in is a C compiler and one command. Installing it with one line is work that is scheduled and not done.
