Start

There is no installer. You need clang 18 or newer, and that is the whole list.

The repository is still private, so the first line below does not work yet. The addresses are final and they open with the code. What works today is on this site: the specification to hand to a model, and every program with the output it really prints.

Four commands

$ git clone https://github.com/heroes-lang/heroes
$ cd heroes
$ clang -I runtime seed/heroes.c runtime/runtime.c -o heroes
$ ./heroes run examples/gallery/03-fallible.hero
read 42
failed: not_a_digit (expected 0-9)
20

The third line takes under four seconds on a MacBook Air, the machine every measurement here comes from. It builds the compiler from one C file that the compiler wrote itself, which is why clang is all you need.

That middle line saying failed is not the build breaking. It is the example meeting a character it cannot read and saying so, which is what it was asked to do.

Run it from the repository

heroes run looks for the runtime, the support code that goes into every binary, in ./runtime. So run it from the directory you cloned into. From anywhere else, say where the runtime is: 

$ HEROES_RUNTIME=~/heroes/runtime heroes run hello.hero

When heroes run cannot find the runtime it says so and prints that line. If something else is missing, ./heroes doctor names it.

Your own program

A file needs nothing around it. No import lines at the top, no project file listing the other files. It needs a main, which is where the program starts. 

$ printf 'function main()\n    print("we can be heroes")\n' > hello.hero
$ ./heroes run hello.hero
we can be heroes

heroes run compiles the file and launches it, leaving its working files in a build/ folder beside you. The second run of an unchanged file reuses what is in there.

One command, eleven verbs

Everything the toolchain does goes through heroes: lex, parse, check, build, run, test, fmt, doctor, mutate, measure, this. There is no second binary, no build file and no plugin.

heroes fmt prints the one canonical form of a file: same indentation, same line breaks, same order. Every source file in the project, the compiler included, comes back from it unchanged, byte for byte, so a difference between two versions of a file is a difference in what the program does. The only files it leaves alone are the test fixtures written to be refused, because there the text is the fixture.

Every example on this site is a file in examples/, with the command that runs it and the output it prints.

If something goes wrong

./heroes doctor names what is missing on your machine. Every error message carries what was expected and where, and how to read one is its own page. There is no issue tracker yet: it opens with the code, and the build log is where that is announced.
