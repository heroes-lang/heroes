The build log

· changes

One entry for each stage of the project, newest first. Full reports, including decisions, reviews and problems encountered, are in the repository, which is open to read.

  1. A hole that was not where the name said The milestone went hunting for programs heroes check accepts and heroes build refuses, and found that only one of its four faces was that gap, and it was already closed, by a sitting held the same day as the one that named it. The real hole was a walk down the code that gave up after sixteen levels, defended by an argument that was true: the runtime guard exists and it fires. The argument was missing one sentence, that a guard which licenses a compile-time silence is a guard the compiler leans on to be quietly wrong. Ten defects opened by its own sittings and ten closed, one of them opened by the author asking why the CI was red; and the specification came out shorter than it went in, two rules richer. What the compiler stops
  2. Three words for what is borrowed from C A binding now says, on every function that touches a handle, one of three things: acquires and who takes it back, consumes, borrows. None of the three is inferred by the compiler. The form that infers by itself fell when the C pragmatist opened nineteen headers of real libraries: in twelve, the same library hands out a handle to keep with one function and to look at with another, without saying so. The spelling that names who releases was proposed by the reader, who had no way to weigh it, and it turned out to be the cheaper one too. And the rule that every tool re-reading a program has to be taught a new form fired three times, once on a defect nobody had seen. Handles and the three words
  3. The label goes on the handing over, not on the thing Writing on a handle’s type who closes it, so the compiler closes it by itself: refused, because one function hands the same connection over and another only shows it, and a label on the type cannot know which of the two gave it. The C pragmatist compiled it: a program that reads three rows read zero and said all went well. The compiler engineer cast the sitting’s only formal veto. And the count taken before arguing found, in passing, that comparing two handles always answered yes: the commonest line anybody borrowing something from C writes, the one that asks whether anything came back, had never worked. The no, in full
  4. The library’s own name becomes the type A pointer a C library hands you can carry the name the library gives it: record Db tag sqlite3. Hand one where another belongs and the compiler stops you on that line. Three defects opened by three people on three different days were one question: what does a bare address not tell you? Not what it points at, not which one it is, not whose it is. The tool built before the fix said half the cases were already caught: it caught none, and the half were accidents of the test. In the end a sitting convened over one word kept the word, and the completeness critic found a conversion hidden at the boundary and emptied the last places in the examples where a bare address escaped into the open. Handles
  5. The reasons had rotted under the answers Every entry on the list of postponed things received a date and a verdict: it enters, it is refused for good, or it waits with a checkable condition. Nine entries, nine sittings, and nine times the answer was fine and the reason written under it had rotted. One had a clock that had already run out; one said a thing could not be done, and eight programs did it that afternoon; one described a part of the compiler this project has never had; one was contradicted by the same document, forty pages earlier. The decision that every postponed entry gets a verdict is the author’s, and five entries became no’s in a single day. Postponed is not refused
  6. Every ceiling says which way it may move The author said he kept hitting his head on the ceilings and asked which of them still made sense. Almost all had been set to the exact height of the thing measured, on the day somebody measured it. One was worse than the others. The rulebook the assistant reads before every piece of work was being weighed on a borrowed scale, and by that scale it sat under the limit by nine units; on the scale the reader actually uses it was eighteen hundred over, and every instrument said all was well. Now next to each number is written which direction it may move, and something notices when it should have moved and did not. The repository
  7. The name of a thing is no longer text typed by hand A program cannot ask a value what it is made of: three no’s, and each time the written reason was false, so the reasons were replaced with measurable ones. Then came the part nobody planned. A program sending data out had to write the names of its own fields as text, and one wrong letter went out into the world with nothing complaining. Four of the five seats invented something that was not on the list, in pairs, without seeing each other: Point::x is the field’s name, and the compiler knows whether it exists. The reader and the engineer proposed it in the same hour in two spellings, and the author chose the spelling the machine had not already built, for a reason about reading. With the names as text, four typos and none caught; with the names as names, five of five. The no to reflection
  8. The grammar went where the prose was The author asked for the language written down formally, in a file of its own. Five seats looked at it from five directions and every one broke the same half: the part that would have been copied out by hand. The reader, allowed only the specification, found it already said the thing the proposal was built to fix; the historian came back with every attempt of that kind, in every other language, abandoned. So every rule of syntax now stands in the section of the specification that explains it, in Wirth’s notation, and the part a machine can work out for itself is worked out by heroes grammar, every time it is asked. The specification
  9. The records are no longer one file each The author asked whether two pieces of work could run at once, and the answer was a measurement: two sessions never meet in the compiler, they meet in the records, on the one line both have to write. So every entry of a record is a file, and the old file stays where it was as a map, line by line, because a hundred and sixty-one citations pointed at line numbers nobody could check. The blind spot the project had documented as unfixable became a check that runs with every verification. The repository
  10. fold’s type says which of the two is the pile The function that combines two things receives the accumulator and the element, and if they are of one type either order compiles and the program answers something else. Now the type says which is which, and the compiler checks that the function you hand over agrees. The panel had said this was the price of a rule already written; the author said close it anyway. The gentle version caught two of the project’s seven real cases, the strict one seven, at the price that anyone writing a function for fold calls its two parameters acc and item: the author read both numbers and chose the strict one. A reader who had never seen the project wrote those two words three times in three programs without once stopping to choose them. Functions as values
  11. A function type carries the names that can be confused The half of the hole the panel had priced and refused, the author said to build anyway: a function’s type carries the names of the arguments that can be swapped, and changing one makes it another type. Then the panel judged a thing that already existed and three of the five seats sent it back: the spec warden over a sentence with one false reading, the C pragmatist with a callback that ignores an argument, which is what callbacks do all day, and the engineer for two reasons outside the design, a tree that did not compile and a price counted with the wrong ruler. With the right one it is four hundred and thirty-two lines against a budget of about a hundred and fifty, and the number was put in front of the author. The classic swap, through a function held in a variable, went from one in six caught to six in six. Functions as values
  12. Three routes refused by three seats, and the fourth built in twenty-five lines A label written in a call made through a function held in a variable is refused: the function has no names to compare it with. Something happened at the sitting that had never happened: three of the four ways out were refused, each by a different seat and none on cost. The spec warden refused a sentence because a running program said it was a lie; the C pragmatist refused a rule that would have deleted a working program, and brought three measurements where the same small mistake reached the memory; the engineer refused the elegant fix because it was not a fix but a rebuilding of eleven rooms of the house. Then that same engineer built the route nobody had listed, and closed half the hole. The other half is the postcard above. Functions as values
  13. The naming rule reaches the built-in functions If two of a function’s arguments are of one type, you have to say which is which. The compiler enforced it on everything the author wrote and on nothing it provided itself. A reader who had only the specification found it, by writing the same call two ways and being told off for neither. The tool that imitates the classic mistake, swapping two arguments of one type, was producing three hundred and sixty-seven programs the compiler accepted and should not have: a hundred and fifty-nine were this one call. After the repair there were seventy-five, and none of them was it. Records and functions
  14. Thirteen numbers over thirteen doors The author read the language’s own description and said it looked like a room nobody had ever tidied: every rule was there, each where it had been dropped. The tidying cost less than nothing. Twenty sentences that said the same thing twice became one each, and the document came out lighter, with thirteen numbered sections in the order Naur’s committee chose and Wirth kept for forty years. And because the author asked for it, six readers who had seen neither the plan nor the repository were handed the two texts unlabelled: they found three additions, all foreseen, nothing missing, and one sentence that had been ambiguous in the old text. The specification
  15. Text with holes in it A string can now carry values: f"line {n}: {word}" writes each hole as to_str would. Any expression may stand in a hole, {{ writes one brace and a lone } is a brace, and a plain string is unchanged. The compiler refuses a hole whose value has no text, and its note says what to write instead. The example
  16. The ruling on interpolation Three counts decided how a string may hold a value, and the counts corrected the first guess twice. Admitting any expression costs fewer words in the specification than admitting only a name, and the brace was already at work in the compiler’s own strings: a string with holes announces itself with an f, and a plain one is unchanged. The specification
  17. Bytes a C library may keep A program can hand a C library text it will keep, and say when it is done with it: x: cstr @ s.lease(), then end_lease(@x). Every rule proposed to forbid such programs was measured and refused in turn; what closed the hole was a way to say it, not a ban. A lease nobody ends stops the program when main returns, with the count of what was left open. The C boundary
  18. A lent string stays where it was lent A string lent to C with .cstr() may stand only as an argument of the call that reads it. Kept anywhere else, it outlived the bytes it pointed into and the program read freed memory; the compiler now refuses that shape, with its reason, before anything runs. The C boundary
  19. The repository is open The compiler’s source, the specification and every record the project keeps can now be read by anyone. The licence is Apache 2.0, so the code can be used, changed and built on. Questions and problem reports are welcome; changes sent in are not accepted, and the repository explains why in one paragraph. The repository
  20. Freeing strings returned by C An extern declaration can name the function that frees a string allocated by a C library. The compiler calls it automatically. The change also exposed an incorrect count of the functions used in the SQLite example. The SQLite example
  21. Checking thread stack space Threads started by Heroes now report when they run out of space for function calls. A reviewer verified that a thread created by a C library is stopped by an earlier check that names the Heroes function involved. How to use threads
  22. Separate memory for each thread Each Heroes thread, an operation running in parallel, manages separate memory. The review found a missing check in callbacks, functions called back by C: it allowed a list to cross the C interface without being reported. Thread examples
  23. Passing Heroes functions to C libraries You can pass a Heroes function to atexit or pthread_create. The callbacks required by qsort and signal are not supported yet. The compiler reports the limit at the declaration. A reviewer examined the full SQLite header and found different obstacles from those suggested by the initial examples. The C boundary
  24. Larger examples to test the compiler More complex programs were added to cover the gap between small examples and the compiler. Two reviewers rejected the proposed optimisation. One then identified excessive memory use by temporary values that the proposal had not considered. The programs
  25. An error when passing array elements A comment described a crash as impossible, but one line could reproduce it. Passing an array element to a function that modifies it gave C the address of the whole array. The examples covered record fields but missed this case. What the compiler stops
  26. Documenting modules The documentation lacked an explanation of how to organise a program’s files. A chapter on modules was added. Read the chapter
  27. Expanding the examples New programs were chosen to test more parts of the language. The first found a defect: it passed type checking, but compilation failed with an internal error. The chapters
  28. Organising source files into directories The compiler’s files were organised into directories. Directory structure replaced long filename prefixes, allowing shorter names. The compiler in its own language
  29. Using paths for modules Modules can be found in subdirectories using a path. Previously, all files had to be in the same directory. The panel examined the new rules over several reviews. Modules and files
  30. Running commands without a shell The compiler started tools by building a string for the shell, the program that interprets commands. On Windows, the same options were interpreted differently and created a directory with the wrong name. The problem led to passing arguments directly to the process. Why the language is shaped this way
  31. Compiling one module at a time Compilation generated one large C file even after a small change. Code generation was split by module so results for unchanged parts could be reused. One C file per module
  32. Archiving the first compiler The first compiler was archived. The work revealed that it also contained several tools used to measure and check the project. The current compiler
  33. Writing the test tools in Heroes The tools that check the compiler were rewritten in Heroes. They run commands, read the results and compare them with expected output, testing the compiler as a person would use it.
  34. Distributing the compiler as a C file Building the compiler requires compiling one generated C file with clang. The repository includes this file, so a computer without Heroes can build the compiler.
  35. The compiler written in Heroes The compiler was converted from Rust to Heroes, together with its tests. Compiling its own source exposed defects in both the new version and its predecessor. Examples and tests with expected results checked the conversion. How to verify the compiler
  36. Converting the first module The first trial converted one file and recorded any limits encountered. The expected limit had already been removed by another change. The lexer, which divides source text into recognisable elements, worked without the predicted obstacle.
  37. Completing support for C structures More C declarations became usable from Heroes. The work corrected compiler rejections that prevented forms already allowed by the language.
  38. Passing structures to C functions C structures group several fields into one value, but Heroes could not yet pass them to functions. This limitation blocked many operations in a real library.
  39. Checking C function parameters The compiler checked C function results but not their parameters. Declaration checks were extended to input types.
  40. Finding defects with complete programs The first complete programs found new compiler defects. They included a JSON reader, Markdown converter, spreadsheet, maze solver, assembler, log analyser and game.
  41. Integers of different widths Heroes introduced eight integer types with explicit widths. The word int is rejected because it does not specify a type. This required revisiting an initial design restriction.
  42. Making numeric bases explicit A reviewer wrote 0700 for file permissions and asked how it was interpreted. The question exposed the need for clear rules to distinguish numeric bases.
  43. Using constants from C headers C library options can be named in the program. Previously, programs had to copy their numeric values by hand. Reading the value from the header removes that duplication.
  44. Checking declarations against headers An example returned 1 where 1.41 was expected: C declaration checking had a defect. Verification must compare the Heroes declaration with the actual header through clang.
  45. Defining module names Programs can be split into files. Rules were defined for name conflicts and imported modules that are not used.
  46. Completing generics and core operations Generic functions and core operations were completed. Open questions were checked with the compiler, including how types are represented during execution.
  47. Maps and fallible results Implementing maps depended on values that represent a result or an error. Looking up a key can return its associated value or an error if the key is missing.
  48. Representing recursive data Heroes can represent an expression tree without mutable references between values. Each node holds its children through an array.
  49. Managing string memory The compiler introduced reference counting to free memory. Checks challenged the initial rule, which released each string at the end of the block that created it.
  50. Producing the first executable A Heroes program was compiled into a native executable. The work also raised the question of which exit status to use when a program is valid but the compiler does not yet support everything it needs.
  51. Choosing the internal representation The compiler’s intermediate representation of a program was defined. LLVM guidance led to starting with memory locations, reads and writes, leaving optimisation to a later pass.
  52. Measuring the first checks Name, type and missing-case checks were tested by introducing mistakes into working programs. Comparing them with the Heroes-specific checks disabled measured the effect of those rules.
  53. Connecting names to declarations Name checking rejected two declarations in a calculator program. The program defined map and fold, but both names were already reserved by the language.
  54. Parsing and formatting code Writing the parser, which recognises code structure, revealed a contradiction in the specification. fn was both a forbidden word and the prescribed form for a function type. Parameters of that type could not be declared.
  55. Splitting source into tokens The first compiler component divides source text into tokens, the elements the compiler recognises. Implementation exposed problems that the design alone had not revealed.
  56. Preparing the project and tests The Rust project, test tools and first example programs were prepared. The specification became the reference. Its initial size limit was still an estimate and changed when tokens were counted.
  57. Reviewing the plan Five reviewers critically examined the plan before implementation. They assessed language design, compiler engineering, simplicity, use by models and teaching.
  58. The initial idea The project began with a document and a discussion about the language. The aim was a compiled language that used C libraries and was designed for models that generate code.
