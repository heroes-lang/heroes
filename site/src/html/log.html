The build log

· changes ·

Newest first, one entry per milestone. This is the postcard version. The full diary, with the decisions, the reviews, the predictions and what broke, is in the repository, still private and opening with the code; until that day these are the whole of it.

  1. M-declared-freer: the count nobody had run A C library hands your program a string it allocated. An extern declaration can now name the function that frees it, and the compiler calls that for you. The example that binds SQLite had said eighteen bound functions in a comment since the day it was written, with the command to check it on the line below; the true answer was seventeen, until the freeing function this milestone added made it eighteen by accident. The program that found it
  2. M-thread-stacks: the guard that guarded the wrong threads A thread that runs out of room used to die in silence. The ones this language starts now say so; the ones a C library starts never reach that guard, and a judge proved it. That judge deleted one line from the generated C, rebuilt, and got the old silent death; with the line in place, a Heroes function on such a thread is stopped at its first instruction by a different refusal, which names it. Threads, and what may cross
  3. M-isolated-threads: one line, open the whole time Each thread gets its own memory, so ordinary code in one thread can no longer corrupt another’s. The danger stops existing instead of being locked around. One function decides what a C header may say, and it never looked inside a callback, so a list could cross into C and back with the compiler reporting nothing. Ten programs that use them
  4. M-c-callbacks: eight examples said one thing, the real header said another A Heroes function can now be handed to a C library that asks for one. atexit and pthread_create get called back; qsort and signal do not yet, and the compiler says on your line which wall each hits. A judge refused the eight hand-picked examples, measured the real SQLite header, and found the obstacle everyone had named was one case in forty. The C boundary
  5. M-corpus-depth: the judges refused the change and found a bigger one Nine more example programs, chosen for shape rather than for features: the corpus had nothing between a 671-line program and the compiler. Two judges vetoed the optimisation the sitting was convened for, and one of them then found where one example program’s stack space really went: more than half of it to temporaries the proposal had never looked at. The programs
  6. M-robustness-guards: the comment said it could not happen A comment in the compiler explained why a particular crash was impossible. The crash was real, and one line of ordinary code produced it. Passing one element of an array to a function that writes into it handed C the address of the whole array, and the example programs had done that with a field a hundred and fifty times and with an index not once. What the compiler stops
  7. M-documentation-site: where the files go This site had twelve chapters and not one of them said where a program’s files go. That is the part of the language that had changed most recently. Read the chapter
  8. M-corpus-coverage: the library nobody called The job was twenty more programs, chosen so that between them they use every part of the language. The first one found a hole in the compiler. Not a subtle hole: a program the checker said was fine, which then refused to build, with the compiler blaming itself rather than the person who wrote it. The chapters
  9. M-selfhost-nesting: the prefixes were load-bearing The compiler’s own hundred and seventy files were named like a filing cabinet nobody had bought, and the job was to buy the cabinet. Put them in folders, let the names get short. The compiler in its own language
  10. M-package-layout: a module may be a path The language had one rule about where files live: a module is one word, and every file a program reads sits beside the file that names it. Breaking that rule took three review sittings. Modules and files
  11. M-argv-execution: the shell stops being the boundary The compiler used to talk to the machine by writing a sentence and handing it to a shell. On Windows the shell reads a different language, so the very first sentence made a directory named after one of its own options, and everything after that was downstream of the mistake. Why the language is shaped this way
  12. M-separate-compilation: the cache that cannot lie Building the compiler used to mean writing out one enormous C file, nearly eight hundred thousand lines of it, even after changing a comma. The job was to split that into one piece per module, so that touching one file rebuilds one piece. One C file per module
  13. M-bootstrap-archive: the attic The old compiler went into the attic, and half the project’s instruments turned out to be living in it. Not the tests of the language, but the instruments that measure it. The third language dies
  14. M-harness-port: the net, in Heroes Everything that checks the compiler was written in the language being retired, so the net was rewritten in the language itself. A program that uses the compiler the way a person does, in hundreds of checks: type a command, read what comes back, compare it to what was promised.
  15. M-selfhost-fixpoint: the seed The way in became one clang command, and taking the ladder away caught the compiler cheating. The repository now carries the compiler as one generated C file, so a machine that has never heard of this language builds it with nothing but a C compiler.
  16. M-selfhost-port: the fixpoint The compiler crosses into its own language, and the child corrects the parent. 53,013 lines of Rust became 34,812 lines of Heroes, tests included on both sides, since in Heroes they live in the file they test, module by module, with the goldens and the program corpus as the net. The fixpoint
  17. M-selfhost-probe: the wall that was not there Port one file, expect to fail, write down what the language cannot say. The wall had been quietly removed three days earlier by a milestone about something else, and nobody had gone back to re-read the plan’s premise, so the lexer went from “this will fail on file one, cheaply” to working, in an afternoon.
  18. M-complete-structs: a refusal is a claim From 191 bindable C declarations to 349, and not one step was a new capability. Each was a refusal with no way out.
  19. M-struct-passing: the same size is not the same thing A third of everything a real C library offers had been out of reach. Bundles of values travelling as one thing could not cross the boundary.
  20. M-binding-fidelity: half a promise Declare a foreign function wrongly and the program will not build. It was true in one direction only. What a C function hands back had been checked since the boundary existed; what it takes had never been checked at all.
  21. M-program-corpus: programs as an instrument Seven real programs written, six compiler faults fell out. A JSON reader, a Markdown converter, a spreadsheet, a maze solver, a small assembler with its own machine, a log summariser, a game.
  22. M-sized-integers: the feared thing, one paragraph long Eight widths arrive, and the word int stops being a word. The design document had refused this in its strongest terms: never in this version, the highest-risk thing we could add.
  23. M-literal-bases: what 0700 means A reviewer wrote down the way everyone writes file permissions and asked what it meant. Nobody had ever asked.
  24. M-header-constants: no digit left to be wrong A library’s settings have names and numbers, and the language could only say the numbers. To name one option a program had to write 10002, with a comment above it explaining that the library’s documentation adds two to ten thousand: arithmetic done by hand, checked by nothing.
  25. M-ffi-ladder: 1, where it should print 1.41 The promise the whole language was arranged around was false for the pair its own second example uses. The arrangement: when a program borrows a C function, the compiler does not describe that function, it points at the library’s description and lets clang check the two against each other.
  26. M-module-namespace: the cheapest change was a verb Programs split into files, and eleven of thirteen decisions cost nothing. Multiple files need rules: what happens when a file’s name collides with one it imports, what happens when an import is never used.
  27. M-generics-library: three vetoes, none by argument The language reaches feature-complete, and every open dispute is settled by a compiler rather than a debate. Should the runtime’s per-type description gain a sixth entry?
  28. M-optional-map: the last two types, entangled Fallible values and maps could not be built in either order. Looking a key up in a map returns the value or an error, so the map needed that type first.
  29. M-value-aggregates: a tree that contains itself Recursive data, in a language whose data model has no pointer and no reference type. There is nothing to put in a field that stands for “somewhere else”, and yet the example the design was written around is a tree of expressions holding its own children.
  30. M-strings-ownership: the check that refuted its own design The compiler learned to count references, and the watchdog fired twice in an hour. The rule was: a value that owns a string is released at the end of the block that created it.
  31. M-scalars-run: the first native binary A program becomes an executable, and the longest argument was about a number between zero and two. When a program is correct and the compiler simply is not finished yet, what exit code should it use?
  32. M-ir-lowering: desugaring, and the middle of the compiler The textbook representation lost to a decade of evidence nobody had gone looking for. LLVM, whose whole existence is single-assignment form, tells the authors of new languages not to build it: use stack slots and loads and stores, and let a later pass clean up, because that is what clang itself does.
  33. M-typed-frontend: the frontend, and the thesis gets a number Names, types, exhaustiveness, and the first measurement, whose useful half is the column that shows nothing. 379 deliberate mistakes injected into working programs, and the column that mattered was the one showing what a conventional language catches: nothing.
  34. M-name-resolution: the resolver A 317-line calculator refused to resolve, at exactly two lines. It declares its own map and fold, and the language reserves both names.
  35. M-syntax-tree: the parser, the tree, the formatter The parser’s first act was to discover the language could not write down the type of a function. fn was in the registry of foreign words: an error with the repair pre-written, and also in the spec’s own syntax for a function type, so a function-typed parameter failed to lex and every one of them in the language was unwritable.
  36. M-token-stream: the lexer The first real code, and three things it found by being written. Source text now becomes tokens, the pieces the compiler chops it into.
  37. M-day-zero Foundations, and four programs written before the compiler. Git, a Rust workspace, a golden-test harness green with zero tests, and the language spec frozen as the measurement baseline (budget: 1500 tokens, still unmeasured: the counting came later, and changed the number).
  38. before the code The plan meets five hostile experts. Before a single token was lexed, the build plan was reviewed by five adversarial judges: language design, compiler engineering, simplicity, LLM ergonomics and didactics.
  39. the beginning A 2000-line design document and one question. The language arrived as a long design conversation: a compiled language that takes its libraries from C, built for the reader that is not human.

These are the postcards. The letters, panels, measurements, journals and every U-turn are in the repository, which opens with the code. A feed carries these entries, and the day the repository opens there will be one saying so.
