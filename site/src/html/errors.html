Errors

· always crashing in the same car ·

An error message here is a finished product, made with the same care as the rest. Every error below came out of the compiler, copied and pasted.

A model does not have the project open in front of it. It gets one message and has to fix the program with that and nothing else, or spend a whole round re-reading files, which is the most expensive thing that can happen. So every error message carries the exact place that is wrong. Where the thing it clashes with is declared elsewhere it names that line, and where the repair is known it comes with the message.

The classic inversion

Two parameters of the same type, arguments the wrong way round. It type-checks perfectly in most languages and does the wrong thing. Here the names are mandatory precisely because the types cannot help: 

error[needs_label]: two of `copy_text`'s parameters are `str`, so every one of them is named at the call site — this one is `from`
  at tests/golden/check/swapped-arguments.hero:16:21
     |
  16 |     print(copy_text("a", "b"))  #~ needs_label needs_label
     |                     ^^^
  fix (certain): write `from: `

error[wrong_label]: `copy_text` has nothing called `to` at this position — it is `from`
  at tests/golden/check/swapped-arguments.hero:18:21
     |
  18 |     print(copy_text(to: "b", from: "a"))  #~ wrong_label wrong_label
     |                     ^^
  fix (certain): write `from:`

The #~ needs_label notes are in the source on purpose: they are how the test suite checks that the underline lands where the message says it does. And the caret is the span, not the line: in a long call the wrong argument is pointed at rather than described.

Two kinds of fix, only one applied automatically

A fix tagged certain is one the compiler worked out rather than guessed: the type it just inferred itself, the one similar name that exists at that point in the program. The heroes check --apply command applies those and leaves the rest alone, so what comes out is nearer, not necessarily finished. A fix tagged guess is a suggestion for the reader, and no tool ever applies it for you: guessing a repair a model would apply blindly is worse than explaining.

The same messages also come out as JSON, the format programs read easily, for when the reader is not a person but another program.

The loop, as commands:

$ heroes check program.hero           # diagnostics, on stderr
$ heroes check --apply program.hero   # certain fixes applied
$ heroes check --apply --in-place program.hero
$ heroes run program.hero

heroes there is the binary you built: ./heroes, one clang command away from a fresh clone. How to build it →

One family waits for the build. A declaration borrowed from C is checked against the library’s real header, and the thing that reads that header is clang, which runs at heroes build. So a file whose only mistake is a misspelled C function passes heroes check without a word and is refused a moment later, on the same line, with the header’s own answer attached. Words from other languages, refused with the answer attached

The likeliest mistake from a model on autopilot is a keyword imported from somewhere else. Each one is a compile error carrying its own solution, which makes it a single-turn repair rather than a conversation: 

tests/golden/check/reserved-words.hero:2:1: error[reserved_word]: `struct` is not a word in this language — use `record`: `record Point`
tests/golden/check/reserved-words.hero:3:1: error[reserved_word]: `let` is not a word in this language — bind with `=`: `x = 5`
tests/golden/check/reserved-words.hero:4:1: error[reserved_word]: `const` is not a word in this language — use `constant`: `constant MAX: i64`
tests/golden/check/deleted-int.hero:23:8: error[reserved_word]: `int` is not a word in this language — an integer says its width: `i64`, and also `i8` `i16` `i32` `u8` `u16` `u32` `u64`

That is the one-line-per-diagnostic form; the fuller rendering above is what the command prints. Three of those four carry a certain fix and --apply rewrites those three. It leaves let exactly where it is, because the honest repair there is a different binding form and not a word swap, and applying a guess is the one thing this design refuses. That is the trade in one file: a tool you can point at your source without reading the result, and a shorter list of things it will do.

An unfinished program is not a broken one

??? is a legal expression anywhere. The compiler type-checks everything around it and then reports what belongs in the gap: the expected type, what is in scope, and which functions return it. It produces no binary, and it exits zero, because a skeleton under construction is not an error: 

hole at examples/gallery/09-holes.hero:24:5
  position: statement — any type, or none
  this function returns: Entry
  in scope:
    entries: [Entry]
hole at examples/gallery/09-holes.hero:28:74
  expected type: str
  in scope:
    entries: [Entry]
  functions that return it:
    summary_of(entries: [Entry])
      # The hole can be one argument of an otherwise finished line.

That is what lets a program be written skeleton-first: sketch the shape, let the compiler tell you what each gap needs, fill them in. The hole is a question the compiler answers, not a failure it reports. Two holes, two different questions: the first stands where a whole statement is missing, so the answer is what the function has to return; the second stands inside a line that is otherwise finished, so the answer is one type and the functions that produce it.

How it is measured

heroes mutate measures these claims. It takes working programs and injects one plausible mistake at a time, and counts how many the compiler turns into compile errors. Then it runs the same corpus against the same compiler with the thesis rules switched off. The difference between the two columns is the only part that means anything.

The table is one completed run, and the command above it is how you get your own. It covers every program in examples/, and every operator the tool has, including the ones where the design does nothing and the two it fails at: 

$ heroes mutate examples

mistake injected                       mutants  caught  without the rules
two arguments swapped in a call           1907     80%                58%
a positional argument needing a label     1331     66%                 0%
a shadowed name                            945     95%                 0%
a lazy catch-all on a variant              457    100%                47%
a local that takes a module's name        1700    100%                96%
a dropped ?                                236     95%                82%
a forgotten @ on a declaration             758     99%                99%
a dropped variant case                     133    100%               100%
a bitwise & where && was meant             227    100%               100%
a name that was never declared             822    100%               100%
a typo in a name                         10443    100%               100%
mixed integer and float arithmetic        1492    100%               100%
a typo in an error code                     59      0%                 0%
a typo in a digit                           68      3%                 3%

The percentage is of the mutants that still parse. Where a planted mistake also breaks the grammar, that mutant measures the part of the compiler that reads text rather than the part that reasons about it, so it is set aside rather than counted as a win: 323 of the 20,578 above, and 102 of them in the first row. Counting them as caught would take that first row from 80 to 81 per cent, which is the direction the honest choice costs.

The project refuses to average these into one figure, and the tool prints that refusal every time it runs. The reason is in the table. The first four rows are the measurement: a label that is needed and a shadowed name go to zero or near it without the thesis rules, because nothing else in a conventional language is looking for either. The middle rows are caught by names and types anywhere, so averaging them in would credit this design with work it did not do. The forgotten @ is excluded from any summary on the project’s own instruction: the mistakes it plants are caught by construction, and the few it misses are mutations that changed nothing.

Three rows are worth reading against what this site claims on its front page. Swapping two arguments in a call is caught four times in five, not always: where the two share a type the label is mandatory and the swap cannot compile, and where the types differ the label is optional and nothing is looking. And the last two rows are caught almost never, in either arm. A typo inside an error code is a string with a letter changed, and no rule constrains how a string is spelled. A typo inside a number is a number, and 10 is as legal as 100. Those two are the honest edge of the whole design: nothing in a type system can see them.

A number that only flattered the design would be useless.
