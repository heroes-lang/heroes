Examples

Browse every example in the repository, with its source code, command and recorded output where available.

The applications written with Rebel also have a catalogue of their own, with the tool each one is modelled on: the applications.

The test corpus is the collection of programs used to check the compiler. On every commit, the tests build and run them in three configurations; examples that need an unavailable C library are skipped. Where a page shows recorded output below the command, the tests compare the program’s output with that text byte for byte.

Start with the first group, which introduces one idea at a time in reading order. These files are checked for compilation errors and formatting, but their output is not recorded or tested. The groups between it and those written with Rebel make up the test corpus, with programs such as a JSON reader, a small language interpreter, a SQLite ledger and calculations using raylib.

The examples are two groups, kept apart so a name cannot be read as the other’s. Every program above the shelves written with Rebel is in examples/ and uses no library: where it needs a function a library would give, it carries its own. The last three shelves, rebel/examples/, hold programs written with Rebel, the library this project writes, each named under rebel/ and each a project with its own catalogue. The tools and the services are programs somebody would use, each recorded running a scripted session that reaches nothing outside the machine. The twins are programs of examples/ written again with Rebel, each printing byte for byte what its original prints, and a twin’s page and its original’s link each other.
