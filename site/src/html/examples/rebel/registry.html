A Heroes package index, in small, and its client: signed packages published, versions resolved as Rust’s Cargo resolves them, archives fetched and verified.

A publisher packs a package’s folder into a reproducible archive, signs a statement of its name, version and digest with an Ed25519 key, and uploads both. The server opens the archive as a stranger’s, checks its heroes.toml against a JSON Schema and the signature against the publisher’s registered key, keeps the archive under its SHA-256 digest and the version in SQLite, and indexes it for search. The client lists and searches packages, resolves a range of versions to the highest one not withdrawn, fetches an archive and verifies its digest and its signature against its own list of trusted keys, and shows what changed between two versions.

The output on this page is its demo: the whole of it run on the machine itself, in a folder it makes and removes, printing a transcript that is the same on every run. Windows’ own cryptography offers no Ed25519, so there the program is built and its demo not run. Rebel’s web and http serve and fetch, semver reads and resolves versions, archive and compress/zstd pack, crypto/keypairs signs, json/schema checks the manifest, and diff and json/patch show what changed.
