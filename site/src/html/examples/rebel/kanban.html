A desktop kanban board in Tauri’s shape: a web page in the system’s own web view for its face, this program and SQLite behind it.

Its interface is a page, HTML, CSS and a script in web/, shown in the system’s own web view (WebKit on macOS, WebView2 on Windows, WebKitGTK on Linux), the part of a browser that draws a page, and served from the program’s own memory at app://localhost, never from a network port. Its logic is this program, which keeps the boards, their columns and their cards in SQLite. Every act of the person, a card added, dragged to another column, edited, a search or an undo, is a call from the page’s script to the program over a bridge, and the program answers and then tells the page the board changed.

The output on this page is its demo: the window and the page made as on the desktop but with no screen, a scripted session of the page’s calls sent through the same handler, a database under a fixed clock, and the requests a page may and may not make, a file outside the program and another site among those refused. The page’s own files are shown under Input, since the program reads them from the folder its arguments name. Rebel’s ui makes the window and its menu, ui/webview the web view, its files, its rules and its bridge, sql/sqlite keeps the boards, markdown and html/sanitize turn a card’s notes into safe HTML, and search ranks the cards a search finds.
