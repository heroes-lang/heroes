An identity server, a small Keycloak: sign-up, passwords, one-time codes, passkeys, and one login for many applications.

People sign up with a password and prove their address by a link sent by mail, add one-time codes from an authenticator app enrolled with a QR code, and add passkeys (WebAuthn), the logins a phone or a security key keeps. The applications its configuration names let them log in through OpenID Connect, the protocol a site uses to hand its login to another server: the server issues signed tokens (JWTs, small signed records of who logged in), publishes the keys that check them, replaces a refresh token at each use and notices one used twice. The people of an organisation’s LDAP directory are imported every night and log in with their directory password.

The output on this page is its demo: every flow run once on the machine itself, against stand-ins of a mail server and a directory that the program carries, with a fixed clock and random numbers drawn from a fixed seed, so the transcript is the same on every run. Rebel’s web and http serve it, oauth2 plays the application on the other side, jose signs and checks every token, webauthn checks the passkeys, ldap reads the directory, and crypto hashes the passwords with Argon2id.
