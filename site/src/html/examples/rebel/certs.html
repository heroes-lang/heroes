A certificate manager in the manner of certbot: it obtains, keeps, renews and revokes the certificates a site needs to serve HTTPS.

It keeps an account with a certificate authority that speaks ACME, the protocol Let’s Encrypt uses, its key in the system’s keyring, where the operating system keeps secrets, and obtains a certificate for each set of domains its configuration names. It proves each name either with a file served from the web site or with a DNS record it writes, the request built and signed here. Every version is kept in certbot’s own layout, a certificate is renewed when the authority’s renewal window opens or few days are left, one can be revoked, and the program can serve HTTPS with one.

The output on this page is its demo, fed the configuration shown under Input: two months of a site’s certificates lived in seconds against stand-ins it starts on the machine itself, a DNS server, its own responder for the file proofs, and a certificate authority. Where the machine has no keyring the program may reach, the keys go to files only the user may read, and that is the one line that differs. Rebel’s acme speaks to the authority, x509, asn1 and pem read and write certificates, dns sends the record updates, tls serves HTTPS, and keyring keeps the private keys.
