A backup tool in the family of restic and borg: deduplicated, compressed and encrypted, kept in a folder or in an S3 bucket.

A folder is saved as a snapshot into a repository, kept in a folder or in a bucket of any S3 service, the storage protocol Amazon defined and many others speak. Every file is cut into chunks where its content says, so an edit changes only the chunks around it; each chunk is named by a keyed hash and stored once however many files and snapshots hold it, compressed by Zstandard where that helps, and sealed by AES-256-GCM under a key only the repository’s password opens. A run reads only the files that changed and stores only the chunks the repository lacks. Snapshots are restored with every chunk checked, forgotten by a retention policy and pruned, exported as tar archives, and copied offsite still sealed.

The output on this page is its demo: a folder backed up, edited and backed up again, restored and compared, old snapshots forgotten and pruned, the repository checked, a tar archive exported and read back, the repository copied to an S3 stand-in the program starts on the machine itself and restored from there, and last one byte of the repository changed for the check to find. Rebel’s crypto/seal seals, compress/zstd compresses, hash and crypto name the chunks, s3 reaches the bucket, and archive writes the tar.
