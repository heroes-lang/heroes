A translation tool in gettext’s family, for a Heroes program and its HTML templates: messages extracted, catalogues kept, checked and compiled.

It extracts the messages the program’s sources ask Rebel’s i18n to translate and those its templates mark in Jinja’s gettext forms, and keeps for each language a catalogue in the format of gettext, the system much free software uses for its translations, merged with the sources as they change, its plural forms computed from CLDR’s rules (the Unicode project’s data on how each language counts). It checks what a reader would see wrong, shows each message as a reader of each language sees it, dates, money, sorted lists and links included, reviews the changes between versions, reports coverage, imports and exports catalogues as CSV, XLSX, JSON and YAML in whatever encoding a translator’s tool wrote them, and compiles them to the .mo files gettext reads.

The output on this page is its demo: a sample shop written in a folder of its own, a long series of commands run over it at one fixed moment, and the folder removed. Rebel’s i18n reads and writes the catalogues and their plural rules, i18n/numbers, i18n/dates and i18n/collate write the previews, unicode/encodings finds and reads a file’s encoding, regex finds the templates’ messages, diff guesses a changed message’s old self, and csv, xlsx, json and yaml carry the formats translators work in.
