A small git: a version control system in git’s model, its objects named as git names them, which its demo checks against git itself.

Every file, folder and snapshot is an object named by the SHA-1 of its kind, size and content, so the names are git’s own, stored compressed, first one file each and then, after gc, in a packfile whose objects are stored mostly as differences from each other. A staging index in git’s binary format holds what the next commit takes; status walks the work tree, leaving out what ignore files name; diff writes unified differences; log draws the commit graph; merge fast-forwards, or merges three ways and marks conflicts for the person to resolve; fsck checks every object’s hash. The repository is the folder .vcs, laid out as git lays out .git.

The output on this page is its demo: a whole session in a folder it makes and removes, printing a transcript that is the same on every run, one line of it asking this machine’s git, where one is installed, to name one object of each kind and saying whether the two agree. Rebel’s crypto computes SHA-1, compress does zlib, diff writes the differences and drives the merge, graphs walks the commit graph and finds the merge base, containers/ordered holds the index, and bytes reads and writes the binary formats.
