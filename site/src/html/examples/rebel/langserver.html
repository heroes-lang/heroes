A language server for Kite, a small language the program defines itself, answering an editor with errors, types, definitions and fixes.

An editor underlines mistakes while a person types, shows the type of a name when the pointer rests on it, jumps to a definition and renames a name everywhere it stands. It does none of this alone. It asks a language server, a separate program that knows the language, through the Language Server Protocol, the one VS Code, Neovim and Helix use. The messages are JSON-RPC, requests and answers written in JSON, each after a Content-Length header that says how many bytes follow, and they travel on the server’s standard input and output. The language served is Kite, small and with its types checked before a program runs: it has records, values made of named fields, functions and let bindings, names given to a value. langserver defines it itself and holds its lexer, which cuts the text into tokens, the pieces it is read in, its parser, which builds the tree, its scopes, which say where a name can be read, and its type checker. Each change the editor sends is a stretch of text replaced, incremental sync, and after each one the server analyses the document again and publishes the mistakes it finds. It also answers hover, the box that appears over a name, go to definition, find references, rename, completion, the document’s outline, formatting and quick fixes.

The output on this page is its demo: a client stand-in starts this same program as a child process, joined by two pipes, the channels through which one process reads what the other writes, and prints every message that crosses them, --> what the client sends and <-- what the server answers. The client opens a document with two mistakes, takes the fix the server offers for a misspelt name, fixes the other by hand, asks for hover, a definition, the references and completion after a dot, renames a binding, has a rename to a name already taken and one to a word Kite keeps for itself refused, formats a second document and ends the session as the protocol asks. The protocol counts the characters of a line in UTF-16 units, the unit of JavaScript’s strings, in which an emoji counts two: the demo asks about a name written after two emoji, and a place counted in bytes would point somewhere else. Rebel’s jsonrpc and json read and write the messages, scanner cuts Kite’s text into tokens, diff offers the nearest name to a misspelt one and sends formatting as the fewest changed lines, graphs finds the records that hold themselves, and process and os start the server as a child.
