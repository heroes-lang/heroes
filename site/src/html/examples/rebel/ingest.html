An event pipeline like Kafka Connect and Kafka Streams, in small: events cut into windows of time, archived to S3 and summed in PostgreSQL.

A member of a Kafka consumer group, Kafka being a server that keeps streams of events in order, reads the events producers write, in JSON or MessagePack, and cuts them into fixed windows of time by when each event happened, waiting a while for events that arrive late. Each closed window is written to S3 storage twice, an LZ4 copy for quick reading and a Zstandard copy for the archive, each checked before it is stored, and its counts, sums and percentiles go to PostgreSQL in one transaction with a ledger of every object written. A write that still fails after its retries is kept as a job to replay later, and the pipeline’s place in the stream moves only past what has been written.

The output on this page is its demo: a Kafka broker, an S3 service and a PostgreSQL server that the program carries, started on the machine itself, a scripted morning of events produced, the pipeline run until it has caught up, a day exported, the one write the S3 stand-in refuses on purpose replayed, and an account printed. Rebel’s kafka, s3 and sql/postgres speak to the three services, compress/lz4, compress/zstd and compress/bzip2 compress, stats computes the percentiles, and jobs keeps the writes to replay.
