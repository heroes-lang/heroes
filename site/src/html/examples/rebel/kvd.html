A small key-value server in the manner of Redis, with its client: it speaks RESP2, Redis’s protocol, and keeps its data in a snapshot and a log.

The server holds keys in memory with values of five kinds: strings of bytes, lists, tables of fields, sets, and sets ordered by score, the last on a skip list written in the program itself, a list of several levels that finds an element by skipping most of the others. A key may expire: whoever looks for it after its time does not find it, and a periodic round draws a few keys that expire at random and takes out the expired ones, as Redis does. A transaction runs several commands in a row with no other client stepping in, and runs none of them where a key watched with WATCH changed meanwhile; a client subscribes to a channel and receives what another publishes there. Every change is written to a file that is only ever added to, the log, and run again at start; a snapshot of the whole content, written also by a thread of its own (a line of execution working beside the rest) while the server goes on answering, makes the part of the log before it needless. One thread serves every client, waiting on all of them at once with poll. The client, kvd cli, runs one command, a file of commands, a pipeline (several commands sent in one write) or a prompt, where commands are typed one at a time, and writes the replies as redis-cli does.

The output on this page is its demo: two clients talk to a server the program starts on a thread of its own, on the machine itself, with a clock moved by hand. Strings, lists, tables, sets and a leaderboard; keys that expire, one when it is next read and the others by the periodic round; a message one client publishes and the other receives; a transaction cancelled because the other client changed the watched key, and the same transaction run again, this time to the end; a snapshot, a restart that reads the snapshot and the log back, and a sudden stop in the middle of a write, whose half-written command is dropped when the server starts again. Rebel’s net and poll serve the connections, redis is the client and reads the commands, containers/indexed and containers/deque hold the keys, tables and lists, fs and hash write the snapshot with its check, and random draws the round’s keys.
