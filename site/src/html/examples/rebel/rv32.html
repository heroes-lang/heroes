A RISC-V emulator, a program that plays the part of a processor, with the assembler that writes its programs, a disassembler and a debugger.

RISC-V is an open instruction set, the list of instructions a processor understands, and rv32 runs its base part for 32-bit whole numbers, with multiplication and division; even a division by zero gives the value the specification sets. The machine has its registers, the small cells of memory inside the processor, and a bus, the line that joins the processor to the rest, which checks every address: behind it stand the memory, a serial port the program writes and reads text through, and a timer that interrupts the program at a set time, at the same addresses QEMU, another emulator, uses. An invalid instruction or an access outside the memory hands control to a part of the program written to handle it, or stops the machine and says where. The assembler turns a program’s text, written in the form the GNU assembler reads too, into the numbers the processor runs, and saves them in an image, the file the machine loads, together with the names the text gives its code and data and a checksum, a number computed from the contents that changes if the file is damaged. The disassembler goes the other way, and the debugger stops the program where it is asked to and shows its registers and memory.

The output on this page is its demo, run on the programs and the commands shown under Input: every sample assembled, a program with mistakes and a damaged image refused, then the primes, a sort, the Fibonacci numbers, some work on text, the edge cases of multiplication and division, the timer and a program that writes outside the memory, each run from its image; last, Fibonacci’s image turned back into text and followed step by step in the debugger. In the processor a result too large for 32 bits starts again from zero, like a car’s odometer, while Heroes stops a program whose arithmetic overflows. So the machine’s arithmetic is a module of functions written for it. Rebel’s scanner cuts the program’s text into tokens, the pieces the assembler reads it in, math gives the 64-bit multiplication that starts again from zero, bytes and hash write the image and its checksum, containers/ordered keeps the names by address and the points where the debugger stops, containers/deque the last instructions run, and flags reads the command line.
