A small web server built from the core packages, which answers each connection on a thread of its own and says what it served.

The program takes net for its network connections, the open lines two programs talk over, and net/http for the requests a browser sends and the answers a web server gives back. Both are core packages, fetched into its folder with heroes add core like every package. Run with no words, the program plays both sides in one process. A client on a thread of its own (a second line of work that runs beside the first, inside the same program) sends two requests over one connection. The server answers /hello, turns /nowhere away with a 404, the code a web server gives for a page it does not have, and the output is the same on every run.

Run as serve 8080, it waits for connections on port 8080, the number that tells a machine which program a connection is meant for, and only from the machine itself. It keeps serving until Ctrl-C or a request to end, then lets every connection finish what it holds and says how many requests it answered.

A Heroes thread runs a function of one number and gives back one, so a connection cannot be handed to a thread as it is. The program gives the connection up for a number, the thread takes it back with that number, and a number never taken back is reported when the program ends, as a connection never closed is. The comment at the top of the file says why the loop that starts a thread for each connection belongs to the program and not to the package.
