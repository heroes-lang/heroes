Control flow

Two loops, one conditional, and no clever forms.

There is one way to ask a question and two ways to repeat something. No do…while, no three-part for(;;) header, no switch with fall-through, no ternary operator, no loop labels. Each of those is a second way to write something the language already has, and every second way is a place a reader can be surprised.

if, and only bool

A condition is a bool or it is a compile error. There is no rule about zero being false or an empty string being false, because there is no truthiness at all: 

$ heroes check loops.hero
error[not_bool]: an `if` condition must be `bool`, found `i64` — there is no truthiness in this language
  at loops.hero:13:12
     |
  13 |         if x
     |            ^

if, else if and else are the whole set, the condition takes no brackets, and the body is what is indented under it. if is also an expression, so a value can be chosen with one instead of by assigning in two branches, which is why the language has no ternary and does not miss it.

for x in xs: walking a sequence

There is no index, no counter and no end condition to get wrong: the loop takes each element in turn and the variable is a fresh copy each time round.

The @ on best is the other half of this chapter and gets the next chapter to itself. In one line: best: i64 @ floor declares a name that is allowed to change, and best @ x changes it. A name bound with = cannot change, ever, so the mutable parts of a program are exactly the lines with an @ on them and you can find them by looking.

Leaving early: break

Skipping one: continue

Both jumps apply to the loop they are written in. There are no labels to break out of an outer loop, so when you need that, the inner loop becomes a function and return does the work, which also gives the thing you were doing a name.

while: repeating on a condition

A while takes a condition and nothing else. The classic three-part header packs the start, the test and the step into one line where the step is easy to forget; here the step is a statement in the body, in the order it happens.

Counting: a range is a function call

range is not syntax. It is an ordinary function that returns a list of numbers, from included and to excluded, and both arguments are named for the reason chapter 2 gave: they are both i64, so the compiler cannot tell them apart and makes you say which is which. The off-by-one you would normally reread twice is written down.

_ is the loop variable when there is nothing to call it. It is the same _ that discards a payload in a match: it binds nothing, so it can never be an unused name, and an unused name is an error here, which is what makes _ worth having.
