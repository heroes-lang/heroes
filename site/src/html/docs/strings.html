Strings

Bytes and characters are two jobs, and the type system will not let you confuse them.

A str is UTF-8 text that never changes once it exists. len() counts bytes, not letters, and so does slice. In UTF-8 a letter can take between one and four bytes; ignoring that produces string bugs.

Indexing gives you a byte

s[i] gives you a u8, a number from 0 to 255, because that is what a byte is. It is compared against ' ' in single quotes, which is how you write a single character and counts as a number too. With double quotes you would have a string, and the two do not mix: 

$ heroes check strings.hero
error[type_mismatch]: expected `u8`, found `str`
  at strings.hero:12:12
     |
  12 |         if s[i] == " "
     |            ^^^^^^^^^^^

In a language with one string type and implicit conversions, that line compiles and compares a number to a string by some rule you have to remember. Here the two jobs have two types and the mistake stops the build.

chars() gives you characters

chars() walks whole characters and hands each one back as a one-character str, which is why this function compares against " " in double quotes while the previous one used ' '. Use the byte loop for a protocol or a scanner; use chars() for anything a person will read. The syntax makes the choice between bytes and characters explicit.

Slicing in the middle of a character is not silently allowed either: it stops the program rather than producing text that is no longer valid UTF-8.

Splitting, with no library to hide in

There is no built-in split because Heroes has no standard library. This example splits on spaces in twelve lines, and the if i > start is the part a library would have decided for you: two spaces in a row produce no empty word here, and that is a choice visible in the code rather than in someone’s documentation.

slice(from:, to:) takes bytes, to excluded, and names both because they are the same type, the same rule that makes range name its ends.

Putting them back together

These two do the same kind of work at very different prices. join walks the list once and builds the answer in one pass. The loop underneath it builds a new string on every round, because a str never changes and + can only make a third one out of two, so a long list costs the sum of every intermediate result. join and repeat exist for exactly that reason, and a handful of initials will never notice the difference.

Six escapes, and no others

In a string: \n, \t, \r, \\, \". In a character literal, \' replaces the last of them. That is the whole list, and anything else is rejected on the spot with the repair attached: 

$ heroes check strings.hero
error[unknown_escape]: `\d` is not an escape sequence — the escapes are \n \t \r \\ \"; write `\\` for a literal backslash
  at strings.hero:45:24
     |
  45 |     return words.join("\d")
     |                        ^^
  fix (certain): escape the backslash: `\\d`

Most languages pass an unknown escape through as the letter itself, which means a regular expression pasted into a string keeps working until the day one of its escapes collides with a real one. Here the collision is impossible, and the fix is machine-applicable: the compiler can write \\d into your file for you.
