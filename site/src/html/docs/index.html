The repository is still private, so the links on this page that point into it do not answer yet. The specification is in there, and so is the file named under every code block in these chapters. The repository opens once a round of consolidation is finished, and every link here is already written for that day.

How to read this

The specification sets the rules; it is not a teaching text. It reads the way a rulebook reads, and it stays under five pages so the whole language fits in a prompt. These thirteen chapters explain it one idea at a time, in order. Together they cover the language; the specification, on this site, is where to look when you want the rule rather than the explanation.

Every code block here is cut from a file in examples/ when the site is built. The block names that file underneath, and the build refuses to ship a block that no longer matches it. Each of those programs is compiled and run in three configurations on every commit. All of them, with their output →

Errors, which are part of the language

A diagnostic here is a finished part of the language. That page shows what the compiler prints, the repairs it can apply to your file, the holes it still has, and the measured catch rate per kind of mistake. Every error on it is real output, not trimmed to look better. Errors, and how to read one →
