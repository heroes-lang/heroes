Maps

Looking up a key returns a value or an error.

A map associates keys with values. Its type is written {K: V}, where K is the key type and V is the value type. A lookup can find the key or fail; the result type represents both cases.

m[k] is a V?, not a V

Write the lookup on its own and the compiler tells you what you have: 

$ heroes check maps.hero
error[type_mismatch]: expected `i64`, found `i64?`
  at maps.hero:9:12
    |
  9 |     return scores[name]
    |            ^^^^^^^^^^^^
  fix (guess): `.must()` — abort on the error case, giving `i64`

i64? is the fallible type from chapter 4: an integer or an error. If the key is missing, the error code is missing_key. You must handle that possibility before using the number.

Four ways to handle a lookup

.default(v) returns the stored value or v if the key is missing. In this example, the result has type i64.

.is_err() returns true if the key is missing. It does not extract the value. To check that the key is present, the example negates the result with !.

.must() returns the stored value and stops the program if the key is missing. Here the preceding line has already checked that the key exists. Use this form when you have verified that the lookup succeeds.

match handles both results and lets you read the error’s contents. Both branches are required.

Building one

You can write all the pairs together or declare a mutable map with @ and add them one at a time. m[k] @ v inserts the value for key k, replacing the previous value if it exists. An empty map needs an explicit type: m: {str: i64} @ {}.
