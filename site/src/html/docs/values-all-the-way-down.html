Values all the way down

Building and traversing trees while keeping copies of values independent.

In Heroes, changing a copy of a value does not change the original. You can still build a tree whose branches have the same type as the tree by using a container such as an array.

Why a field cannot directly contain its own type

If a case directly contains another value of its own type, the compiler reports the problem and suggests a solution: 

$ heroes check trees.hero
error[no_size]: `variant Expr` contains itself, so it has no size
  at trees.hero:16:16
     |
  16 |         inner: Expr
     |                ^^^^
  note: every value is an independent copy, so `Expr` holding one more `Expr` would need one at every depth
  note: `[T]` holds its contents elsewhere, so it is how a type contains itself
  fix (guess): hold them in an array: `[Expr]`

A record or variant includes the storage for its fields. If a field directly contained another Expr, which contained another, one value would require infinite memory. Heroes rejects this definition.

Using an array for branches

The representation of [Expr] has a fixed size: its array elements are stored separately. The Expr type can therefore contain other Expr values through the array without having infinite size. Here negate uses a list with one element. Maps can also represent recursive structures.

With Heroes values, you cannot build reference cycles. The runtime, the code that supports execution, frees memory when its reference count reaches zero. No garbage collector is needed to find cycles, and no weak annotations are needed to mark weak references.

Walking it is one match and one for

value_of and sum_of call each other. You can declare them in either order without forward declarations.

The initial value is 0 for a sum and 1 for a product. So value_of(.add(parts: [])) returns 0 and value_of(.multiply(parts: [])) returns 1. The tests below check these results.

Building one

The return line needs no annotation, because the function signature already says Expr. The binding above it does, and leaving it out gets an error that names where the type could have come from: 

$ heroes check trees.hero
error[cannot_infer]: `.multiply` does not say which variant it belongs to — the type has to come from the context (a signature, an annotation, or the value being returned)
  at trees.hero:81:24
     |
  81 |     three_times_four = .multiply(parts: [.number(v: 3), .number(v: 4)])
     |                        ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

Checking empty cases

The tests check the result of the empty cases. The four assertions detect accidental changes to the behaviour of value_of. 

$ heroes run examples/gallery/11-trees.hero
14

This example represents and calculates two plus three times four using a tree of values. The Heroes compiler uses larger structures of the same kind to represent the programs it reads.
