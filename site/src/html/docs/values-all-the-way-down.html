Values all the way down

A tree that contains itself, in a language with no pointers.

Every value here is an independent copy and nothing points at anything. This chapter answers one question: how does a tree hold its own branches when a branch is the same type as the tree?

First, why the obvious way cannot work

Write a case that holds one more of itself and the compiler stops you, explains the arithmetic, and offers the way through: 

$ heroes check trees.hero
error[no_size]: `variant Expr` contains itself, so it has no size
  at trees.hero:16:16
     |
  16 |         inner: Expr
     |                ^^^^
  note: every value is an independent copy, so `Expr` holding one more `Expr` would need one at every depth
  note: `[T]` holds its contents elsewhere, so it is how a type contains itself
  fix (guess): hold them in an array: `[Expr]`

A record or a variant holds its fields inside itself. If one of those fields were another Expr, that one would hold another, and the size of the type would be infinite. In a language with pointers you would reach for one here without noticing you were making a decision. There are none, so the decision is visible.

The array is the indirection

[Expr] has a fixed size whatever it contains, because an array keeps its elements elsewhere. So Expr is finite, the tree is as deep as you like, and none of it is a pointer you can hold, compare or leave dangling. negate takes a one-element list because that is the recursive shape the language can express.

Because nothing can hold a reference, no cycle can be built. That is what lets the memory underneath be reference-counted with no collector, no cycle detector and no weak annotations to get right.

Walking it is one match and one for

value_of and sum_of call each other, and neither is declared before the other. Declaration order never matters, so mutual recursion needs no announcement, no header and no forward declaration.

The two starting values are 0 for a sum and 1 for a product. That is why value_of(.add(parts: [])) is 0 and value_of(.multiply(parts: [])) is 1, which the tests below pin down rather than leave to folklore.

Building one

The return line needs no annotation, because the function signature already says Expr. The binding above it does, and leaving it out gets an error that names where the type could have come from: 

$ heroes check trees.hero
error[cannot_infer]: `.multiply` does not say which variant it belongs to — the type has to come from the context (a signature, an annotation, or the value being returned)
  at trees.hero:81:24
     |
  81 |     three_times_four = .multiply(parts: [.number(v: 3), .number(v: 4)])
     |                        ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

What the tests fix in place

Every shape that contains itself has an empty case, and what it should mean there is a decision somebody has to make. Writing it down as four assertions means the next person to touch value_of finds out at once if they changed it by accident. 

$ heroes run examples/gallery/11-trees.hero
14

Two plus three times four. That is a compiler’s smallest interesting data structure, in ninety lines, with no pointer anywhere in it. And the same shape scaled up is what this project’s own compiler uses to hold the programs it reads.
