Failure is a value

There is no null, and there are no exceptions.

An operation may find no value or fail. Many languages represent these cases with null, which means no value, or exceptions, which interrupt normal execution. If the code does not handle them, the problem may only appear when the program runs.

Heroes uses a type that represents both outcomes: a value or an error. It has no null or exceptions. A function’s declaration tells you whether it can fail, without requiring you to read its body.

A type that means “or an error”

i64? means an integer or an error. Before using the integer, you must handle the possibility of failure. In a function with this return type, ok(v) returns a value and fail(code, msg) returns an error:

The error contains a code and a message. The code, such as "not_a_digit", is a stable name in snake_case: lowercase words separated by underscores. The program uses it to distinguish errors and decide how to handle them. The message explains the problem to the reader and can be improved without changing the code.

Returning an error to the caller: ?

To return an error to the caller without handling it here, add ? to the call. The symbol marks the point where the function can return early:

digit_of(text[i])? calls digit_of. If the result is an error, it immediately exits the current function and returns that error to the caller. Otherwise, it uses the returned number and continues the loop.

The example also uses a mutable variable, a range, and calls with a dot.

Handling the result: match

Use match to handle the two possible results directly and access their contents:

Each branch names a case with a leading dot and binds a name to its contents: .ok v makes the value available as v. The symbol _ discards contents you do not need. Both branches are required; the program will not compile if one is missing. A catch-all branch, which handles all other cases, is not allowed. This rule requires you to revisit the code if the set of possible cases changes.

What changes in the code

The return type tells you whether a function can fail. In calls, ? marks where an error can end the current function. To get the value, handle the error with match or .default(), or explicitly use .must() and accept that the program will stop on failure.
