Bindings and mutation

The @ symbol marks mutable variables and the operations that change them.

To understand a program, you need to know which operations change its data. In Heroes, the @ symbol identifies those operations.

= binds a fixed value, @ a mutable one

x = 5  # a name for a value, forever
v: i64 @ 0  # a cell that may change, and the type is required
v @ v + 1  # changing it

= binds a name to a value that cannot be reassigned. @ declares a cell, a variable whose value can change, and also assigns a new value to it. Later in this chapter, you will see how the same symbol marks parameters that a function can change.

You must declare a cell’s type. Its value can change, but its type stays the same. If you try to change a name bound with =, the compiler reports an error: 

$ heroes check mutation.hero
error[not_mutable]: `start` was bound with `=`, which binds once, forever — a cell is declared with its type: `start: <type> @ <value>`
  at mutation.hero:31:5
     |
  31 |     start @ start + 1
     |     ^^^^^
  fix (guess): declare `start` as a cell: `start: <type> @ <value>`

The fix is tagged guess, a suggestion to review, rather than certain, a definite correction. You may have intended to declare a cell or used the wrong name. The compiler can apply only certain fixes automatically.

Each visible name has one definition

You cannot reuse a name while its earlier declaration is visible at that point in the program: 

$ heroes check mutation.hero
error[shadowed_binding]: `start` is already in scope, bound at line 30 — shadowing is an error here: a name means one thing for as long as it is visible
  at mutation.hero:31:5
     |
  31 |     start = r.pos + 1
     |     ^^^^^

Reusing a visible name is called shadowing: the new declaration hides the earlier one. In languages that allow it, you can end up using the wrong value without a compile error. Heroes rejects shadowing.

Every value is a copy

b is a copy of a: adding an element to b does not change a. This holds for arrays, maps, strings and records, including nested values. To avoid unnecessary copies, the compiler can share memory until a value changes. This internal detail does not affect how copies behave in your program.

In b @ b.push(4), push returns a new array. @ assigns the result to b.

When a function does need to change its argument

A function can also change an argument, such as the current reading position in a text. Mark that parameter with @:

The call must also include @, or the program will not compile: 

$ heroes check mutation.hero
error[marker_mismatch]: `advance` changes this argument, so the call site writes `@` too
  at mutation.hero:26:17
     |
  26 |         advance(r)
     |                 ^
  fix (certain): mark the argument: `@x`

Reading advance(@r) tells you that the function can change r. You do not need to open the definition of advance to find out.

The behaviour is copy in, copy out: the function works on its own copy, then replaces the caller’s value with the updated copy when it returns. This also happens on an early return.

A function can change its argument and return a value. Here word_at advances the position past the word and returns the word it read. A call with a dot, r.word_at(), is not allowed when the first parameter is @: write word_at(@r) to make the change visible.

A binding nobody reads is an error

$ heroes check mutation.hero
error[unused_binding]: `spare` is bound and never read — remove the binding, or read it
  at mutation.hero:55:5
     |
  55 |     spare = 5
     |     ^^^^^

The compiler reports a name that is declared but never read: it may be left over from an edit or indicate a forgotten result. To discard a result deliberately, write _ = f(x). The symbol _ binds no name and can be reused.
