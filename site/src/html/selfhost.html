Written in itself

· a new career in a new town ·

The Heroes compiler is written in Heroes. So building it takes a Heroes compiler, and what comes out has to be identical to what you started from.

A language stays a toy until it can write its own compiler. Doing that takes data of different shapes nested inside each other, tables to keep names in, lists, functions that call themselves, serious error handling and programs split across several files. If a language can carry that, the argument about whether it is real is over. It was the finish line from the first day.

The test is not a suite of tests. The repository ships the compiler as one generated C file, seed/heroes.c, which is how a machine with no Heroes on it gets a first compiler. Build that, then ask the compiler it gives you to translate its own source into C, and compare the two files: 

$ clang -I runtime seed/heroes.c runtime/runtime.c -o heroes
$ ./heroes build selfhost/main.hero --emit-c -o out.c
$ cmp out.c seed/heroes.c
sha256  03075edd6a7cf785b804c8be637fc9f87e203ace60a20bd322da0f0953c08f4c

  seed/heroes.c   the C the repository ships: the way in
  out.c           what the compiler writes when it compiles itself

  23,327,212 bytes · 800,433 lines · not one byte between them

cmp prints nothing, which is how it says the two files are the same. So the C in the repository is not a copy somebody keeps up to date by hand: it is what the compiler writes, and the compiler built from it writes it again. Those three lines are the whole proof, and they are three lines anybody can run.

It was first proved with three compilers rather than two, and that was the crossing: the C written by the original compiler, the C written by the compiler that C built, and the C written by the compiler built from that. Three generations, one hash, not a letter between them. The first of the three was written in another language and is gone now, which is why the check that runs today is the two-file one above.

What it is, and what getting here cost:

  • 169modules of Heroes
  • 49,637lines
  • 0workarounds left in the ported code
  • 2,570program outputs compared, never a difference

That is the whole compiler, not a subset. There is the part that breaks the text into words and the part that works out the structure. There is the part that ties every name to its declaration and the part that checks the types. There is the in-between form the program is rewritten into, with its checker, and the pass that decides who owns each value and when to release it. Then the translation into C, the checks against foreign libraries, the error messages, the command that puts code back in order, and the command line.

What self-hosting found

Pointed at its own source, the new compiler refused it, claiming that a piece of its own structure contained itself, which was false. That one wrong complaint was the thread, and pulling it produced five real faults in the new compiler and, more surprising, four in the old one. Including this: the underline that shows a reader where an error is was covering the little note written on that same line for the sole purpose of checking that underline. The child corrected the parent.

A compiler pointed at its own source is a corpus no test suite reproduces: 49,637 lines holding every shape the language has, in the proportions real code has them. That corpus is how five of the port's faults were found, and they were one trap worn five ways: a loop jump inside a match arm skipped the line that keeps a hand-maintained index up to date. The Rust original walks the same list with an iterator: there is no index to forget, so it could never have made this mistake.

Twenty million letters behind three words

The very last thing standing between the two files being identical was a message the old compiler had written down for whoever would do this work, in three separate places:

this list comes out in order here, and the new one will owe an explicit sort

Three sorts, unpaid. The result was 20.8 megabytes of C whose lines all matched and whose sequence did not, on 3,330 lines out of 724,197. A map has no order: the language says so, and measurably means it, so the note was correct on the day it was written and stayed correct for months until somebody needed it.

What it costs, since a hash is not the whole story

The project measured itself against ten other compiler source trees, and the uncomfortable row is tinycc: 68,000 lines for all of C, where the Rust bootstrap spent 30,000 on a subset and delegated every backend question to clang. Per unit of language covered, this compiler is expensive. The counterweight is in the same table and is the reason the port was possible at all: a comment ratio of 0.51, comment lines against code lines, nearly double the next highest of them.

One C file per module · repetition ·

For a long time, building the compiler meant writing out one enormous C file, 798,556 lines of it, every single time, even after changing a comma. Now each module becomes its own C file, compiled on its own, and the compiled piece is kept so the next build can reuse it.

The difficulty was deciding when a kept piece may be reused. The two obvious answers are wrong: a timestamp is not evidence, and neither is the generated C on its own. When a program borrows a number from a C library’s header, the compiler does not write the number down: it writes the name, and lets C fill it in later. So editing the header changes the answer and does not change one character of the generated text. Before the repair, a program printed 1 while the file on disk said 2, then printed 1 again while it said 7. Exit code zero, no complaint, nothing to see. A wrong answer wearing the face of a right one is the worst thing a build system can hand you, because nobody re-reads a green build.

So the compiler stopped guessing. It asks clang, as clang works, which files it actually opened, and then checks that every one of them still says what it said. The same hole turned out to exist in a second place nobody had looked at, where it was worse: it would have let one binary be built half against one version of the system’s own libraries and half against another.

Hunting for the time led somewhere else entirely. Checking the compiler’s own source took a minute and a half, and almost all of it sat inside one small function whose job was to answer which line is this. It answered by counting from the top of the file, and it was asked once for every declaration and once for every comment, on a file over a million characters long. But nobody wanted a line number. The question was only ever whether a comment sits directly above a declaration, and that is a question about two lines next to each other. Asking for the distance instead of the position, plus three more copies of one related habit, took the minute and a half down to 5.3 seconds. No design changed.

Then the third language died · ashes to ashes ·

Two things were owed after the hash, and both have been paid. The generated C had to be shown building from a clean checkout with nothing but a C compiler, the way Go shipped 1.4 and the way Zig ships its bootstrap. It does, in one line: 

$ clang -I runtime seed/heroes.c runtime/runtime.c -o heroes

And the compiler the first one was written in has been archived: nothing builds it, nothing lints it, and it is kept only as a record. The whole picture is now Heroes → C → native binary, with no third language anywhere in it.
