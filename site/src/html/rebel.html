Rebel

The library this project writes for Heroes. A program uses it, or does not.

What it is

Heroes imposes no standard library. The language gives a program its built-ins, reading and writing a file, the command line and little more, and everything beyond them a program takes from a C library or from a package of Heroes code it carries. Rebel is such a package, a broad one: text and numbers, files and folders, time and time zones, the network and the web, data formats from JSON to spreadsheets, compression, cryptography and databases, written from scratch in Heroes by this project.

It is optional, which is what its name says. Nothing of Rebel is compiled into the compiler or into the runtime, the piece of program that sits underneath every Heroes program; the compiler itself is written without it; and a program that does not take it carries none of it. The repository calls it the non-standard standard library.

Go’s, Rust’s and Python’s libraries are its inspirations and its yardstick: a package of Rebel is complete when every capability those three offer in its area is offered here, or refused in writing with the reason. Its names, its tree and its code are its own. A program that uses Rebel owes nothing for it, as it owes nothing for the runtime, the exception in the licence that covers one covering the other, with one exception of its own: two pieces of Rebel are the work of others and keep their notices, the Public Suffix List in http/suffixes and the tables taken from tiktoken in tokenizer/tables. Their notices travel with those files, so a program whose catalogue lists neither package carries neither.

How a program takes it

A program names each package of Rebel it uses with the entry’s name in angle brackets, the way any package is named. These are the first lines of a small jq, a tool that filters JSON, written with Rebel:

Its catalogue, the file heroes.toml beside the program, holds one entry for Rebel and a line listing the packages the program uses. heroes add rebel writes the entry and heroes add rebel/csv adds a package to the line. The program then carries the packages it lists and the modules those use, and nothing else of Rebel: a program that reads CSV this way carries a few dozen files and under a megabyte of it, where the whole of Rebel is more than sixteen hundred files and thirty megabytes. A use of a package the line leaves out is refused, with the command that adds it.

The Heroes index on the web, the place heroes add rebel reads from, is not built yet. Until it is, a program takes Rebel from the folder of this repository that holds it, by its path: 

$ heroes add --path ../../../packages/rebel/0.1.0/files --as rebel
added rebel ../../../packages/rebel/0.1.0/files
wrote heroes.toml
$ heroes add rebel/csv
added rebel/csv
wrote heroes.toml

The chapter on packages takes the same program through both routes, the index and the folder, with what the compiler says at each step.

Or it does not take Rebel at all. A program that would rather bind a C library itself does, as the programs in examples/ do, and the rules Rebel follows for its own packages bind no program. The programs written with Rebel stand beside the others on the examples page.
