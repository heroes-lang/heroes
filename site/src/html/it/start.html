Inizia

Per compilare Heroes serve clang 18 o una versione più recente. Non c’è ancora un installer.

Il repository è ancora privato: il primo comando non è ancora utilizzabile. Lo sarà quando il codice verrà reso pubblico. Nel frattempo puoi leggere la specifica e gli esempi, con l’output registrato quando disponibile.

Quattro comandi

$ git clone https://github.com/heroes-lang/heroes
$ cd heroes
$ clang -I runtime seed/heroes.c runtime/runtime.c -o heroes
$ ./heroes run examples/gallery/03-fallible.hero
read 42
failed: not_a_digit (expected 0-9)
20

La terza riga richiede meno di quattro secondi su un MacBook Air, la macchina da cui viene ogni misura di questo sito. Costruisce il compilatore da un solo file C generato da Heroes, ed è per questo che ti basta clang.

La riga con failed è un risultato previsto dell’esempio: il programma segnala un carattere che non riesce a convertire in numero. La compilazione è riuscita.

Eseguilo dalla cartella del repository

heroes run cerca il runtime, cioè il codice di supporto che finisce dentro ogni binario, in ./runtime. Quindi eseguilo dalla cartella in cui hai clonato. Da qualunque altro posto, digli dov’è: 

$ HEROES_RUNTIME=~/heroes/runtime heroes run hello.hero

Se il runtime manca, heroes run lo segnala e mostra il comando da usare. Per controllare gli altri requisiti, esegui ./heroes doctor.

Il tuo programma

Per questo programma basta un file con una funzione main, da cui inizia l’esecuzione. Non servono dichiarazioni import né un file di progetto. 

$ printf 'function main()\n    print("we can be heroes")\n' > hello.hero
$ ./heroes run hello.hero
we can be heroes

heroes run compila il file e lo lancia, lasciando i suoi file di lavoro in una cartella build/ nella directory in cui ti trovi. La seconda esecuzione di un file non modificato riusa quello che c’è dentro.

Un comando, undici verbi

Tutti gli strumenti si usano tramite heroes: lex, parse, check, build, run, test, fmt, doctor, mutate, measure, this. Non c’è un secondo binario, non c’è un file di build e non ci sono plugin.

heroes fmt formatta il codice secondo regole fisse per indentazione, ritorni a capo e ordine. I sorgenti del progetto, compilatore compreso, seguono già queste regole: il formattatore li restituisce identici, byte per byte. Questo riduce le differenze dovute alla formattazione quando confronti due versioni. I file di test che contengono errori intenzionali vengono conservati così come sono.

Ogni esempio di questo sito è un file in examples/, con il comando che lo esegue e l’output che stampa.

Se qualcosa va storto

./heroes doctor segnala cosa manca sul tuo computer. I messaggi d’errore indicano cosa si aspettava il compilatore e in quale punto del codice. La guida spiega come leggerli. Il sistema per segnalare problemi, o issue tracker, sarà accessibile quando il codice diventerà pubblico. L’annuncio comparirà nel diario.

Poi: scrivi il tuo primo programma, un’idea alla volta. Oppure leggi tutto il linguaggio in un file e chiedi un programma al tuo modello.

Heroes non ha ancora un installer o una versione pubblica. Per compilarlo servono un compilatore C e un comando. L’installazione con un solo comando è prevista, ma non è ancora disponibile.
