Inizia

Per compilare Heroes serve clang 18 o una versione più recente. Non c’è ancora un installer.

Heroes è in beta: il linguaggio cambia ancora. I cinque comandi qui sotto funzionano già oggi, e la versione che costruiscono è heroes {{version}}. Fino alla 1.0.0 un cambio del numero di mezzo può cambiare il linguaggio stesso, mentre un cambio dell’ultimo numero non lo cambia mai.

Cinque comandi

$ git clone https://github.com/heroes-lang/heroes
$ cd heroes
$ clang -I runtime seed/heroes.c runtime/runtime.c -o heroes-seed
$ ./heroes-seed build selfhost/main.hero -o heroes
$ ./heroes run examples/gallery/03-fallible.hero
read 42
failed: not_a_digit (expected 0-9)
20

La terza riga richiede meno di dieci secondi su un MacBook Air, la macchina da cui viene ogni misura di questo sito. Costruisce un compilatore da un solo file C generato da Heroes, ed è per questo che ti basta clang.

Quel file C si aggiorna a ogni release, la versione che il progetto pubblica, e nel frattempo solo quando serve, quindi spesso è il compilatore di qualche giorno prima. La quarta riga gli fa costruire il compilatore di oggi a partire dai suoi sorgenti, scritti in Heroes, e sulla stessa macchina ci mette qualche minuto. Da lì in poi ogni comando usa ./heroes, il compilatore di oggi, quello che questo sito racconta.

La riga con failed è un risultato previsto dell’esempio: il programma segnala un carattere che non riesce a convertire in numero. La compilazione è riuscita.

Se non hai clang

clang è un compilatore C, cioè il programma che trasforma il C in qualcosa che il tuo computer esegue. A Heroes serve la versione 18 o più recente, perché è la più vecchia su cui è misurato. Chiedi al tuo quale sia: 

$ clang --version

Il prefisso del fornitore non conta, quindi vanno bene sia Apple clang version 21 sia Debian clang version 22: conta solo il primo numero. Se hai già compilato Heroes, ./heroes doctor risponde alla stessa domanda e dice cosa manca quando manca qualcosa.

macOS. I Command Line Tools portano il clang di Apple:

$ xcode-select --install

Se ti dà un numero sotto il 18, cosa che succede su un macOS più vecchio, installa un clang aggiornato accanto a quello con Homebrew e metti la sua cartella per prima nel tuo PATH, l’elenco delle cartelle in cui il terminale cerca i programmi: 

$ brew install llvm
$ export PATH="$(brew --prefix llvm)/bin:$PATH"

Il compilatore chiama clang per nome ogni volta che costruisce qualcosa, quarta riga compresa, quindi risponde il primo clang di quell’elenco. Dopo, i cinque comandi funzionano così come sono scritti. La riga con export vale finché resta aperta la finestra del terminale; per tenerla, aggiungila al file che la tua shell legge quando parte.

Debian e Ubuntu.

$ sudo apt install clang

Se il clang della tua distribuzione è più vecchio del 18, su apt.llvm.org ci sono i pacchetti aggiornati.

Windows.

$ winget install LLVM.LLVM

Su Windows le due righe di compilazione cambiano in due punti: la prima vuole un flag in più, e tutti e due i nomi finiscono in .exe, perché Windows esegue un file solo se il suo nome finisce così, e clang dà al file esattamente il nome che gli chiedi: 

$ clang -I runtime seed/heroes.c runtime/runtime.c -Wl,/STACK:67108864 -o heroes-seed.exe
$ ./heroes-seed.exe build selfhost/main.hero -o heroes.exe

Windows dà al primo thread di un programma 1 MB di spazio per le chiamate di funzione, dove macOS e Linux ne danno 8, e questo compilatore si richiama in profondità mentre legge un programma. Il flag dà 64 MB al compilatore che nasce dal file C, lo stesso spazio che il compilatore dà a ogni programma che costruisce su Windows, compreso quello che esce dalla seconda riga. I controlli del progetto costruiscono il compilatore in questo modo, su Windows, a ogni modifica.

Eseguilo dalla cartella del repository

heroes run cerca il runtime, cioè il codice di supporto che finisce dentro ogni binario, in ./runtime. Quindi eseguilo dalla cartella in cui hai clonato. Da qualunque altro posto, digli dov’è: 

$ HEROES_RUNTIME=~/heroes/runtime heroes run hello.hero

Se il runtime manca, heroes run lo segnala e nomina la variabile da impostare. Per controllare gli altri requisiti, esegui ./heroes doctor.

Il tuo programma

Per questo programma basta un file con una funzione main, da cui inizia l’esecuzione. Non servono dichiarazioni import né un file di progetto. 

$ printf 'function main()\n    print("we can be heroes")\n' > hello.hero
$ ./heroes run hello.hero
we can be heroes

heroes run compila il file e lo lancia, lasciando i suoi file di lavoro in una cartella build/ nella directory in cui ti trovi. La seconda esecuzione di un file non modificato riusa quello che c’è dentro.

./heroes new hello scrive un primo programma in una cartella nuova, hello/main.hero: una main, una funzione con il commento che dice che cosa restituisce, e un test, un blocco che la controlla, che ./heroes test hello/main.hero esegue. Con --package scrive invece un pacchetto, codice che altri programmi raggiungono con use, nella forma che descrive il capitolo sui pacchetti. Rifiuta un nome dove c’è già una cartella o un file, e allora non scrive niente.

Un comando, sedici verbi

Tutti gli strumenti si usano tramite heroes: lex, parse, check, build, run, test, fmt, add, fetch, new, doctor, mutate, probe, measure, grammar, this. Non c’è un secondo binario, non c’è un file di build e non ci sono plugin.

heroes fmt formatta il codice secondo regole fisse per indentazione, ritorni a capo e ordine. I sorgenti del progetto, compilatore compreso, seguono già queste regole: il formattatore li restituisce identici, byte per byte. Questo riduce le differenze dovute alla formattazione quando confronti due versioni. I file di test che contengono errori intenzionali vengono conservati così come sono.

Ogni esempio di questo sito è un file in examples/, con il comando che lo esegue e l’output che stampa.

Se qualcosa va storto

./heroes doctor segnala cosa manca sul tuo computer. I messaggi d’errore indicano cosa si aspettava il compilatore e in quale punto del codice. La guida spiega come leggerli. Se qualcosa non torna e questi non lo spiegano, segnalalo sull’issue tracker, il sistema per segnalare problemi: un programma che dovrebbe compilare e non compila, o che compila e dà la risposta sbagliata, è la cosa più utile che questo progetto possa ricevere. Un problema di sicurezza, soprattutto un programma Heroes che va in crash su un accesso sbagliato alla memoria o la corrompe, non va in una segnalazione pubblica: si manda con il modulo privato della scheda Security del repository, e SECURITY.md spiega come.

Poi: scrivi il tuo primo programma, un’idea alla volta. Oppure leggi tutto il linguaggio in un file e chiedi un programma al tuo modello.

Heroes non ha ancora un installer. Per compilarlo servono un compilatore C e le due righe qui sopra che lo costruiscono. L’installazione con un solo comando è prevista, ma non è ancora disponibile.
