Inizia

Non c’è nessun installer. Serve clang 18 o più recente, e la lista finisce lì.

Il repository è ancora privato, quindi la prima riga qui sotto non funziona ancora. Gli indirizzi sono definitivi e si aprono insieme al codice. Quello che funziona oggi è su questo sito: la specifica da dare a un modello, e ogni programma con l’output che stampa davvero.

Quattro comandi

$ git clone https://github.com/heroes-lang/heroes
$ cd heroes
$ clang -I runtime seed/heroes.c runtime/runtime.c -o heroes
$ ./heroes run examples/gallery/03-fallible.hero
read 42
failed: not_a_digit (expected 0-9)
20

La terza riga prende meno di quattro secondi su un MacBook Air, la macchina da cui viene ogni misura di questo sito. Costruisce il compilatore da un solo file C che il compilatore ha scritto da sé, ed è per questo che ti basta clang.

Quella riga in mezzo che dice failed non è la compilazione che si rompe. È l’esempio che incontra un carattere che non sa leggere e lo dice, che è quello che gli è stato chiesto di fare.

Eseguilo dalla cartella del repository

heroes run cerca il runtime, cioè il codice di supporto che finisce dentro ogni binario, in ./runtime. Quindi eseguilo dalla cartella in cui hai clonato. Da qualunque altro posto, digli dov’è: 

$ HEROES_RUNTIME=~/heroes/runtime heroes run hello.hero

Se non lo trova te lo dice con queste parole, e stampa la via d’uscita. Se manca qualcos’altro, ./heroes doctor lo nomina.

Il tuo programma

Un file non ha bisogno di niente intorno. Nessuna riga di import in cima, nessun file di progetto che elenchi gli altri file. Gli serve un main, che è il punto da cui il programma parte. 

$ printf 'function main()\n    print("we can be heroes")\n' > hello.hero
$ ./heroes run hello.hero
we can be heroes

heroes run compila il file e lo lancia, lasciando i suoi file di lavoro in una cartella build/ accanto a te. La seconda esecuzione di un file non modificato riusa quello che c’è dentro.

Un comando, undici verbi

Tutto quello che fa la toolchain passa da heroes: lex, parse, check, build, run, test, fmt, doctor, mutate, measure, this. Non c’è un secondo binario, non c’è un file di build e non ci sono plugin.

heroes fmt stampa l’unica forma canonica di un file: stessa indentazione, stessi ritorni a capo, stesso ordine. Ogni file Heroes del repository torna da lì identico, byte per byte, quindi una differenza tra due versioni di un file è una differenza in quello che il programma fa.

Ogni esempio di questo sito è un file in examples/, con il comando che lo esegue e l’output che stampa.

Se qualcosa va storto

./heroes doctor ti dice cosa manca sulla tua macchina. Ogni messaggio d’errore porta cosa si aspettava il compilatore e dove, e come si legge è una pagina a sé. Non c’è ancora un tracciatore di problemi: si apre insieme al codice, e il registro dei lavori è dove viene annunciato.

Heroes non è ancora impacchettato: nessun installer e nessuna release pubblica, quindi la via d’ingresso è un compilatore C e un comando. Installarlo con una riga è lavoro in programma e non fatto.
