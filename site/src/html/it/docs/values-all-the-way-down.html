Heroes / Guida / capitolo 11

Valori fino in fondo

Costruire e percorrere alberi mantenendo indipendenti le copie dei valori.

In Heroes, modificare una copia di un valore non cambia l’originale. Puoi comunque costruire un albero i cui rami hanno lo stesso tipo dell’albero: basta usare un contenitore come un array.

Perché un campo non può contenere direttamente se stesso

Se un caso contiene direttamente un altro valore dello stesso tipo, il compilatore segnala il problema e suggerisce una soluzione: 

$ heroes check trees.hero
error[no_size]: `variant Expr` contains itself, so it has no size
  at trees.hero:16:16
     |
  16 |         inner: Expr
     |                ^^^^
  note: every value is an independent copy, so `Expr` holding one more `Expr` would need one at every depth
  note: `[T]` holds its contents elsewhere, so it is how a type contains itself
  fix (guess): hold them in an array: `[Expr]`

Un record o un variant include lo spazio dei propri campi. Se un campo contenesse direttamente un altro Expr, e questo un altro ancora, servirebbe una quantità infinita di memoria per un solo valore. Heroes rifiuta questa definizione.

Usare un array per i rami

La rappresentazione di [Expr] ha dimensione fissa: gli elementi dell’array sono memorizzati separatamente. Il tipo Expr può quindi contenere altri Expr attraverso l’array senza avere dimensione infinita. Qui negate usa una lista con un solo elemento. Anche le mappe possono rappresentare strutture ricorsive.

Con i valori Heroes non puoi costruire cicli di riferimenti. Il runtime, il codice di supporto all’esecuzione, libera la memoria quando il conteggio dei suoi riferimenti arriva a zero. Non serve un garbage collector che cerchi cicli, né annotazioni weak per indicare riferimenti deboli.

Percorrerlo è un match e un for

value_of e sum_of si chiamano a vicenda. Puoi dichiararle in qualsiasi ordine, senza dichiarazioni anticipate.

Il valore iniziale è 0 per la somma e 1 per il prodotto. Perciò value_of(.add(parts: [])) restituisce 0 e value_of(.multiply(parts: [])) restituisce 1. I test qui sotto verificano questi risultati.

Come se ne costruisce uno

La riga del return non ha bisogno di annotazione, perché la firma della funzione dice già Expr. Quella sopra invece sì, e a toglierla il compilatore protesta, e ti dice da dove quel tipo sarebbe potuto arrivare: 

$ heroes check trees.hero
error[cannot_infer]: `.multiply` does not say which variant it belongs to — the type has to come from the context (a signature, an annotation, or the value being returned)
  at trees.hero:81:24
     |
  81 |     three_times_four = .multiply(parts: [.number(v: 3), .number(v: 4)])
     |                        ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

Verificare i casi vuoti

I test verificano il risultato dei casi vuoti. I quattro assert permettono di rilevare una modifica involontaria al comportamento di value_of. 

$ heroes run examples/gallery/11-trees.hero
14

L’esempio rappresenta e calcola due più tre per quattro usando un albero di valori. Il compilatore Heroes usa strutture dello stesso genere, più articolate, per rappresentare i programmi che legge.
