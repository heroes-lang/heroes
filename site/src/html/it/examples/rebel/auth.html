Un server di identità, un piccolo Keycloak: registrazione, password, codici monouso, passkey e un solo accesso per molte applicazioni.

Le persone si registrano con una password e confermano il proprio indirizzo con un link ricevuto per mail, aggiungono i codici monouso di un’app di autenticazione configurata con un codice QR, e aggiungono passkey (WebAuthn), gli accessi custoditi da un telefono o da una chiave di sicurezza. Le applicazioni indicate nella configurazione le fanno entrare con OpenID Connect, il protocollo con cui un sito affida il proprio accesso a un altro server: il server rilascia token firmati (JWT, piccoli documenti firmati che dicono chi è entrato), pubblica le chiavi che li verificano, sostituisce un token di rinnovo a ogni uso e si accorge di uno usato due volte. Le persone della directory LDAP di un’organizzazione vengono importate ogni notte ed entrano con la password della directory.

L’output di questa pagina è la sua demo: ogni procedura eseguita una volta sulla macchina stessa, contro sostituti di un server di posta e di una directory che il programma si porta dietro, con un orologio fisso e numeri casuali estratti da un seme fisso, così il resoconto è lo stesso a ogni esecuzione. I pacchetti web e http di Rebel lo servono, oauth2 fa la parte dell’applicazione dall’altro lato, jose firma e verifica ogni token, webauthn verifica le passkey, ldap legge la directory e crypto calcola l’hash delle password con Argon2id.
