Thanks

· sons of the silent age ·

Heroes draws on ideas from other languages and research. This page names the authors and each contribution.

These credits name the people and teams who designed the languages. They were not consulted about Heroes and are not responsible for how it uses their ideas.

The foundations and tools

The compiler translates Heroes into C11 and uses clang to produce executables and check C library declarations against their headers, the files that describe functions and types. The first compiler, used to reach the one written in Heroes, was written in Rust.

  • C: Dennis Ritchie, who designed it; Ken Thompson, who wrote B, the language C came out of, and Unix with Ritchie; and Brian Kernighan, who co-wrote the book that taught it to everyone. Heroes uses C to access existing libraries.
  • LLVM, clang: Chris Lattner. Heroes uses clang to check C function declarations against library headers.
  • Rust: the Rust team, and Graydon Hoare, who started it. The first compiler used a restricted set of Rust features, chosen to make conversion to Heroes straightforward.

The value model

In Heroes, changing a copy does not change the original. Values cannot form reference cycles, so memory can be freed by counting the references still in use. No garbage collector is needed to find cycles. This model draws on the work cited below.

  • Hylo, formerly Val: Dimitri Racordon, Denys Shabalin, Daniel Zheng, Dave Abrahams and Brennan Saeta, the authors of Native Implementation of Mutable Value Semantics. The sentence Heroes depends on is theirs: references cannot be stored in variables or fields, hence all values form disjoint trees. This restriction avoids the need to detect cycles or annotate how long references remain valid.
  • Swift: Chris Lattner, Doug Gregor, John McCall, Ted Kremenek and Joe Groff. Copy-on-write, which delays copying data until a change requires it, reference counting, inout parameters (this language’s @), and leading-dot variants. Heroes draws on these ideas without introducing class or the weak and unowned reference forms.
  • APL, J, K: Kenneth E. Iverson, Roger Hui and Arthur Whitney. These languages show how to work with whole values without exposing mutable references in the code.
  • R: Ross Ihaka and Robert Gentleman. MATLAB: Cleve Moler. Two examples of copy-on-write values used in statistics and numerical computing.

Safety without a garbage collector

Heroes aims to prevent invalid memory access and data corruption. The projects below explored safety without a garbage collector, the system that finds and frees unused data.

  • Cyclone: Dan Grossman, Michael Hicks, Trevor Jim and Greg Morrisett. References only as function parameters, which deletes lifetime annotations from the language. This project uses their rule twice: it is the discipline the Rust bootstrap compiler was written in, and it is why the port to Heroes was mechanical. The rule has their name on it in the repository.
  • Modula-3: Luca Cardelli, James Donahue, Lucille Glassman, Mick Jordan, Bill Kalsow and Greg Nelson. A model for concentrating unsafe operations in an identifiable part of the program that can be reviewed.

Keeping the language small

Wirth’s languages provided a reference for keeping the specification short. For the Heroes compiler, the limit instead applies to individual files: they should remain understandable to a reader.

  • Pascal, Modula, Oberon: Niklaus Wirth, with Jürg Gutknecht on Oberon. record and variant come from here. So does the calibration: the Oberon report at sixteen pages is how long a specification is allowed to be. Pascal-P4, at roughly four thousand lines, once showed how little a self-hosting compiler needs; that is history, not a size this project holds itself to. Wirth also wrote an entire operating system in a language with no raw pointers, and nothing argues harder for this whole approach.

Types and alternatives considered

  • ML: Robin Milner and the group at Edinburgh, among them Michael J. C. Gordon. Product and sum types, which group fields or represent alternative cases. Heroes expresses them with record and variant.
  • The arrow: Alonzo Church. -> in a function type is familiar notation, and it reached Heroes through ML, Haskell, Rust, Swift and Python’s type hints without changing shape. It was kept exactly as it was found.
  • The subroutine: David Wheeler, on EDSAC in 1951. Somebody had to invent the idea of calling a piece of code from more than one place.
  • Type inference: J. Roger Hindley and Robin Milner. This one is a thank-you for something Heroes does not use: whole-program inference can make it harder to connect an error to its cause. Knowing precisely what was being given up, and why, is what their work makes possible.

What the language feels like to use

These languages influenced Heroes’ syntax, checks and commands. Readers who know them will find many familiar choices.

  • Go: Robert Griesemer, Rob Pike and Ken Thompson. One canonical format with no options, unused variables as errors, a line that ends without a semicolon, and the initial choice to omit generics.
  • Nim: Andreas Rumpf. The foreign-function mechanism, reusing previous compilation results for each module, and nim r, which is heroes run. Also the standing warning the project repeats to itself: copy Nim’s surface, never its implementation.
  • Zig: Andrew Kelley. Tests in the same file as the code they check, and NUL-terminated strings, which use a zero byte to mark the end as C expects.
  • ABC: Leo Geurts, Lambert Meertens and Steven Pemberton, at CWI in Amsterdam. Indentation as the syntax, with no braces at all. Guido van Rossum worked on ABC for years before carrying that into Python, and Peter Landin had named the rule in 1966. Heroes takes it for two reasons at once: a brace nobody writes is a token nobody spends, and the models that write code have read so much Python that this is one piece of layout they already know.
  • Python: Guido van Rossum, and Tim Peters for import this, which became heroes this, included in the compiler. It is here.
  • Odin, Jai: the author of Odin, who publishes as gingerBill, and Jonathan Blow. One uniform way to write a declaration, whatever is being declared.
  • Ruby: Yukihiro Matsumoto. The reading rhythm (named blocks, named arguments, dot chains), used as a guide to readability, without adopting metaprogramming, the ability to alter code behaviour through other code.

Error messages and unfinished code

  • Rust: the Rust team, and Elm: Evan Czaplicki. Between them they proved that the quality of an error message changes the whole experience of a language, and that it is a design deliverable rather than plumbing. Heroes aims to include the information needed to fix an error without opening other files.
  • Idris: Edwin Brady. Agda: Ulf Norell, and Catarina Coquand on the first version. Typed holes, unfinished expressions for which the tool reports the expected type: in Heroes, ??? is a legal expression, and the compiler answers it by saying what belongs in the gap.

Immutability at scale

  • Erlang: Joe Armstrong, Robert Virding and Mike Williams. Immutable values and isolated processes provide a reference for managing data. In Heroes, independent values also help readers understand a function without looking for changes elsewhere.

Generating C code

Heroes generates C and lets a C compiler handle the work needed for each machine. The languages below followed this approach before Heroes.

  • cfront: Bjarne Stroustrup. C++ began as a program that emitted C.
  • Nim: Andreas Rumpf. Named further up this page for the way it calls C functions, and it belongs here as well, because the two are one decision. Nim’s compiler writes C when nobody asks it for anything else, and C++, Objective-C and JavaScript are alternatives a user turns on. A compiler that writes C can include the header of any library it wants to call, which is what makes that foreign-function mechanism work at all. Heroes took the same road for the same reason.
  • Vala: Jürg Billeter, Raffaele Sandrini and Rico Tzschichholz. Chicken Scheme: Felix Winkelmann. Cython: Robert Bradshaw and Stefan Behnel. Three examples of languages that generate C.
  • Early Haskell: designed by a committee, among them Paul Hudak, John Hughes, Simon Peyton Jones and Philip Wadler. Early implementations of this high-level language also used C.

Choices to consider carefully

The project also studied the limits and costs of other languages’ choices. These precedents help determine which approaches to adopt and which to avoid.

  • Lua, with Nelua and Pallene: Roberto Ierusalimschy, Luiz Henrique de Figueiredo and Waldemar Celes. The precedent for a small language that compiles, and the cost of converting data from a universal table before and after C calls. Heroes gave up the universal table for that reason.
  • APL again, in the other direction: ultra-compact notation is the one place where this project cites Iverson against itself: Heroes prefers more explicit forms to help models read and generate code.
  • R and MATLAB again: both document the cost of copying shared data when it changes. In Heroes too, a change may require copying the structure, a cost to consider inside loops.
  • Unison: Paul Chiusano and Rúnar Bjarnason. Code stored as a tree with names as labels: the origin of an idea that was explored here at length and then dropped in favour of one readable syntax.
  • Ada: Jean Ichbiah for Ada 83, and Tucker Taft for Ada 95 through 2012. One refusal was borrowed whole: passing the same variable twice to one call when both can be written to. Ada allowed it for three decades, watched what happened, and made it illegal in 2012. Heroes made it illegal on day one, on their evidence, and the compiler offers the same repair.

And the name

David Bowie, for “Heroes” (1977). The name keeps the album’s quotation marks. Bowie also inspired the section titles and the book from which the language grew. Musical references stay in the project’s prose and do not appear in error messages or library names.
