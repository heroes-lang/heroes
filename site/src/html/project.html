It compiles itself, and here is the proof

The Heroes compiler is written in Heroes. A language stays a toy until it can write its own compiler. Doing that needs nested data, tables of names, recursion, real error handling and programs split across files. If a language carries all of that, the argument about whether it is real is over.

The proof is not a test suite. The repository ships the compiler as one generated C file, which is how a machine with no Heroes on it gets a first compiler. Build that, ask the compiler it gives you to write its own source out as C, and compare: 

$ clang -I runtime seed/heroes.c runtime/runtime.c -o heroes
$ ./heroes build selfhost/main.hero --emit-c -o out.c
$ cmp out.c seed/heroes.c
                       (cmp prints nothing: not one byte differs)

  seed/heroes.c   the C the repository ships: the way in
  out.c           what the compiler writes when it compiles itself

  over 22 megabytes of C, and more than 700,000 lines of it

cmp prints nothing, which is how it says the files are the same. So the C in the repository is not a copy anybody maintains: it is what the compiler writes, and the compiler built from it writes it again. The middle line takes under a minute on a MacBook Air. Three lines, and anybody with the repository can run them.

What pointing it at itself found

The new compiler refused its own source, claiming a piece of its own structure contained itself, which was false. Pulling that thread produced five real faults in the new compiler and four in the old one. One of the four was this: the underline that shows a reader where an error is was covering the note written on that line to test that underline. The child corrected the parent.

A compiler pointed at its own source is a corpus no test suite reproduces. It holds every shape the language has, in the proportions real code has them, which is how five of those faults surfaced. They were one trap worn five ways. A loop jump inside a match arm skipped the line that kept a hand-maintained index up to date.

The last thing standing between the two files was a message the old compiler had written down in three places for whoever would do this work: this list comes out in order here, and the new one will owe an explicit sort. Three sorts, unpaid. The result was a file whose lines all matched and whose order did not, on a few thousand of them. A map has no order: the language says so and measurably means it. The note was right the day it was written, and stayed right until somebody needed it.

How a change to the language gets decided · five years ·

Nothing reaches the language because it is elegant. A change to the syntax, the semantics, a class of error message or the shape of the compiler goes to a panel of five seats first. Each seat is given different material on purpose, and four of them can refuse outright. A change that adds no syntax, touches no error message and moves no word of the specification, the kind that lives only inside the compiler or its runtime, goes to two of the five.

  • The readerGets the specification and sample programs, and never the design document or the code. Its verdict is an experiment about whether the language can be read, not an opinion. veto
  • The compiler engineerGets the actual source tree and prices the change in code that has to be written and kept. veto
  • The C pragmatistGets the C a real binding would need and compiles it, or shows why it cannot be compiled. veto
  • The spec wardenGets the measured token count before and after, never an estimate, and guards the budget the whole language has to fit in. veto
  • The historianHas to search the web and cite dates and sources: unsourced precedent is inadmissible. It advises and cannot refuse.

The panel never blocks the work. It adopts the strongest and most complete resolution it can find, never the cheapest and never a compromise. It marks that as awaiting the author’s word, and the work goes on. Where the strong answer and the cautious one disagree, it takes the strong one and writes down the other, so the author can still choose it.

Every sitting is a file in the repository, with the briefs, the verdicts and the vetoes. There are more than a hundred of them. A change to the language that has no sitting behind it has no way in.

Twenty lines

heroes this prints these. They ship inside the compiler, so they are the one piece of the project that cannot go out of date with the documentation. 

The Zen of Heroes

 1. This language begins with a tribute to David Bowie.
 2. It is made for language models; people can read it too.
 3. A model may have read everything; each page must still explain itself.
 4. What the eye can see is all there is: sound and vision.
 5. There is one way to say each thing; every program sings in the same voice.
 6. That way may not be obvious at first; the Starman already knows it.
 7. The semantics are familiar; the syntax is new.
 8. Turn and face the strange: every strange choice here is deliberate.
 9. Nothing changes behind your back; every change signs its name.
10. Every plausible mistake must become a compile error before the program runs.
11. Unless you mark the unfinished place with ???.
12. An honest hole beats a confident guess.
13. A compile-time error is an answer; a runtime error is an ambush.
14. An error should tell you how to fix the program. Anything less is a complaint.
15. Repeating a word is cheap; forgetting one can cost the whole program.
16. The specification stays small under pressure; every word must earn its place.
17. Crashes and leaks are bugs. Ashes to ashes: what Heroes takes, it returns.
18. When pretty code and safe code disagree, safe code wins.
19. There is no standard library; C is the man who sold the world.
20. We can be heroes, just for one day.

Line 10 is the thesis, line 19 is the founding constraint, and line 18 is the tie-break when two rules pull opposite ways. The rest is how it feels to work here. Why the language is built this way →

The first command in the proof at the top of this page is the one the continuous integration runs on every push that touches the compiler, on Linux, and on every milestone tag on three platforms. The other two, the check that the compiler reproduces its own C, run on the Linux leg alone whatever started the run, because the C the compiler emits is the same on every platform. The record of every decision, sittings and measurements included, is kept in the repository, which is still private and opens with the code.
