Why Heroes

· rebel rebel ·

Two constraints, settled before the grammar was. The code must be readable by a model, and the language carries no standard library.

Models fail in catalogued ways · sound and vision ·

Code is increasingly written by language models, and they fail in specific, repeating ways. They swap two arguments of the same type. They forget a case. They rename something they never declared. They reach for a keyword from another language. A language can treat all of that as a run of accidents, or take it as the brief.

A language designed so that every plausible LLM mistake is a compile error will produce working programs in fewer total tokens than a conventional language, even if each program costs more tokens to write.

That is measured, not asserted. Take working programs, plant one plausible mistake in each, and count how many become a compile error rather than a program that runs and quietly does something else. Then pass the same pile to a build with the thesis rules switched off. The gap between the two columns is the whole measurement. The measured table →

Why removing errors beats shortening code

real cost = program tokens × (1 + rewrite rate)

The two factors are not comparable. A more compact syntax saves maybe five per cent of a file. One correction round costs five hundred to two thousand tokens, because the model reads the error, re-reads the file, rewrites a function and recompiles. On a three-thousand-token program, one correction round eats ten syntax savings.

So the instinct is wrong. It says shorten everything. The formula says remove the errors, and shorten only where it costs nothing. Heroes is wordy where you declare things and terse where you use them: it spends words where an error lives, and nowhere else.

The founding constraint

The project did not start from a grammar. It started from a refusal: there is no standard library, and there never will be one. Writing a modern one is more work than writing the compiler, and it is what kills one-person languages. So Heroes keeps a bare minimum and takes the rest from the enormous amount of C that already exists. 

maths beyond arithmetic    →  libm          files, sockets   →  libc
regular expressions        →  PCRE2         HTTP             →  libcurl
JSON                       →  cJSON         SQL              →  SQLite
graphics, audio, terminal  →  SDL, raylib, ncurses

Borrowing one looks like this. Everything turns on the name on the first line: that is the header, the file where the library declares the shape of its functions, and it is what clang checks your declaration against.

The obvious worry about a language with no library of its own is that whoever writes the program, a person or a model, will confidently borrow a C function that does not exist. That is a compile error too, and the answer does not come from any list this compiler keeps: 

error[ffi_unknown_name]: `math.h` declares no `sqrtt` — clang read the header and could not find it
  at ffi-demo.hero:2:5
    |
  2 |     function sqrtt(x: f64) -> f64
    |     ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
  note: an `extern` names what the header already has (§4.19): check the spelling, or name the header that does declare `sqrtt`

Clang had the real header open. Get a width wrong instead of a name and the answer comes from the same place, on the same line, before anything runs. That is what the refusal buys: the library is not described here, so it cannot be described wrongly here.

Without that header nothing would verify what you wrote. And look at pow(base:, exponent:): two values of the same type, so the call has to name them. The rule holds at the C boundary too, which is where swapping two arguments costs most.

The bare minimum is about thirty names, always the same ones: print, len, push, slice, sort, the conversions between types, and map, filter, fold. That list changes only by a recorded decision, never by accumulation.

One consequence the rest of the design obeys: how comfortable the C boundary is ranks alongside how clear the language is, not below it. A library Heroes cannot reach is C code its author has to keep writing by hand, which is what this refusal exists to prevent. The programs that bind C →

Why the compiler emits C

Heroes translates your program into C and lets a C compiler produce the executable. The reason is the constraint above. A function borrowed from C has to be checked against the real library’s header, not against a description the Heroes compiler invents. Going through C means clang does that on every build, for free. An earlier design aimed straight at machine code, and it was dropped once somebody noticed the founding constraint had already decided the question. Speed did not decide it: speed is neither a goal here nor an excuse.

Seven words can begin a line

A file is a list of declarations, each starting with the word for what it declares. constant for a fixed value, function, record for a group of named fields, variant for a value that comes in several forms. Three more declare nothing about your data: use for another file, test, and extern for what comes from C. The list ends there. No classes, no interfaces, and nowhere a global variable anybody can modify.

The order you write declarations in never matters, and two functions can call each other with nothing announced in advance. Underneath, the language is smaller still: what the compiler really handles is seven constructs, and everything else reduces to those before it is done.

The rules it lives by · fashion ·

  • A line is understood by looking at that line. Its meaning is decided by the line and the function around it, never by something written three files away. No inheritance, no macros, no exceptions, no implicit conversions, no null.
  • One way to write anything. A formatter with one canonical form, one word for loops, and argument names required where types cannot tell two arguments apart.
  • Errors written to be read by a machine. Every message carries what was expected and where; where the thing it clashes with is declared elsewhere it names that line, and where a repair is known it comes tagged certain or guess. Writing ??? leaves a declared gap and asks what belongs in it.
  • A program must not corrupt memory. It is allowed to stop. Integer overflow at any width, a division by zero, an index past the end of a list, a slice that would cut a character in half, recursion too deep, and .must() on a value that failed: each of those ends the program on the spot, loudly, on the line it happened. What none of them does is carry on with memory that is wrong. Where two designs are acceptable and one can be made to reach an address nobody checked, the other wins, whatever it costs in elegance or in words.
  • Small enough to compile itself. The whole specification fits under a hard ceiling of 4,096 tokens, which a test asserts on every commit: five pages, written to be handed to a model rather than shelved. Read it →

The obvious objections · quicksand, avoided ·

Why no null, and no exceptions?
Both produce the one kind of trouble no compiler can flag: the case you forgot to handle. Here a value that might be missing says so in its type (i64?), an operation that went wrong returns a value saying so, and passing that failure up to your caller is marked on the line with ?. Anything that jumps the program from one place to another without showing it is banned outright. The chapter on this →
Why must arguments be named when two parameters share a type?
Swapping two arguments of the same type is a model classic, and since the types match nobody notices: the program compiles and copies backwards. copy(from: a, to: b) costs four characters and spends them exactly where that error lives. Where the types already tell the arguments apart, names stay optional.
Why refuse one integer type, then ship eight widths?
In C, the rules for turning one kind of number into another are the first source of trouble and the bulkiest thing to write down. For a long time the answer here was one integer type. Then the widths were asked for anyway, and the expensive half had already been paid: what makes eight number types dangerous elsewhere is the conversion that happens on its own, and those were banned here from day one for an unrelated reason. So the widths cost about a paragraph of specification, every conversion is still written by hand, and the word int is an error that lists the sizes to choose from.
Why is the formatting rigid, exactly four spaces, tabs an error?
So that "nearly right" is a compile failure instead of a silently different program. A canonical formatter takes every style decision away from the writer, which means any textual difference between two programs is a difference in meaning.
Why is every assignment a copy?
So that a piece of data never has two names. If nobody else holds what you hold, no function changes it behind your back and two parts of a program running at once cannot trample each other. Nor can you build a circle where two values keep each other alive, which is what makes it possible to free memory by counting holders, with no garbage collector.
The price is real and the specification writes it down rather than hiding it. + on a str copies both sides, so a concatenation loop is quadratic and join exists to build in one pass. Growing an array in place is the case where nothing else holds it. What is not a price is handing a big value to a function: underneath, a copy shares the memory and splits only when somebody writes, so passing five thousand rows costs nothing until one of them changes. One of the programs on this site does exactly that, several times per query. The chapter on this →
Can two things run at once?
Yes, and threads arrive from C like everything else. The rule at the boundary is the one values already force: a thread gets its own memory, and whatever crosses into it or back out is copied rather than shared. So there is nothing to lock and nothing to race, and the compiler refuses a thread body that tries to carry a list across. What this is good at is sending a small thing and getting a number back. What it is bad at is shuttling large values in and out to do very little with them, and that is a real limit rather than a missing feature. The program that does it →
Is it not just a smaller version of an existing language?
The semantics are familiar on purpose: values that copy, no inheritance, failure in the type. What is new is the constraint every rule was chosen under, and the fact that the whole language has to fit in a prompt with room left for your program. That budget is what refuses the features a bigger language would have taken. How a change gets decided →
