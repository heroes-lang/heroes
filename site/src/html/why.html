Why Heroes

· rebel rebel ·

Two constraints, settled before the grammar was: the code must be readable by a model, and the language carries no standard library.

The code must be readable by a model · sound and vision ·

Code is increasingly written by language models, by LLMs, and models fail in specific, catalogued, repeating ways: they swap two arguments of the same type, forget a case, change a name they never declared, invent a keyword from another language. A language can treat all that as a run of accidents, or take it as the brief to design from.

A language designed so that every plausible LLM mistake is a compile error will produce working programs in fewer total tokens than a conventional language, even if each program costs more tokens to write.

A token is the scrap of text that measures what it costs to put a model to work, roughly a word. The claim is measured like this: take working programs, put one plausible mistake in each, and count how many turn into a compile error rather than a program that runs and quietly does something else. Then pass the same pile of programs to a build of the compiler with the thesis rules switched off, which serves as the yardstick. The gap between the two columns is the whole measurement.

One formula decides the trade-offs

real cost = program tokens × (1 + rewrite rate)

The two factors in that multiplication are not comparable. A more compact form saves maybe five per cent of a file's tokens. One correction round costs five hundred to two thousand, because the model takes the error, re-reads the file, rewrites a function and recompiles. On a three-thousand-token program, one correction round eats ten syntax savings.

The instinct says shorten everything and be careful. The formula says remove the errors, and shorten only when it costs nothing. So Heroes is wordy at the point where you declare things and terse at the point where you use them: it spends words where an error lives, and nowhere else.

The founding constraint

The project did not start from a grammar. It started from a refusal: there is no standard library, and there never will be one. The standard library is the warehouse of ready-made functions a language carries with it, from maths to networking. Writing a modern one is more work than writing the compiler, and it is the thing that kills one-person languages. So Heroes keeps the bare minimum and takes everything else from the enormous amount of C that already exists: 

maths beyond arithmetic   → libm          files, sockets  → libc
regular expressions       → PCRE2         HTTP            → libcurl
JSON                      → cJSON         SQL             → SQLite
graphics, audio, terminal → SDL, raylib, ncurses

Without that file, nothing at all would verify what you declared. And look at pow(base:, exponent:): the two values it takes are the same type, so the call has to name them. The rule holds here at the C boundary too, which is where swapping two arguments costs the most.

That “nothing else” needs one qualification: the language does carry about thirty names, always the same ones. They are print, len, push, slice, sort, the conversions between types, and map, filter, fold. They all fit in a list you can read in a minute, so when you meet a function you never wonder where it came from. That list changes only by a recorded decision, never by accumulation.

Leaning on all the C that is already written makes a one-person language workable, and it has a consequence the rest of the design obeys. How comfortable the C boundary is ranks alongside how clear the language is, not below it. A library Heroes cannot connect to is C code its author has to keep writing by hand, which is exactly what this refusal exists to prevent.

Why the compiler emits C

Heroes does not produce machine language directly: it translates your program into C first, and lets a C compiler turn that into an executable. The reason is the one above. If you borrow a function from C, that function has to be checked against the real library's own file, not against a description the Heroes compiler invents and hopes is right. Going through C means clang does that checking on every build, for free: declare a function wrongly and you hear about it now, instead of discovering it once the program is running. An earlier design aimed straight at machine code, and it was dropped the day someone noticed the founding constraint had already decided the question.

Speed did not decide this choice: it is neither a goal of this project nor an excuse in it.

Seven words can begin a top-level line

A file is a list of declarations, one after another, and each starts with the word that says what you are declaring: a fixed value with constant, a function with function, a group of data with named fields with record, a value that comes in several forms with variant. Three more heads exist and declare nothing about your data: use for another file, test for a test, extern for what comes from C. The list ends there. There are no classes, no interfaces, nothing that quietly changes what the next line means, and nowhere in the language a global variable anybody can modify.

The order you write declarations in never matters, and two functions that call each other need no announcement in advance: nothing depends on where it sits in the file. Further down, the language is smaller still. What the compiler really handles is seven constructs: name a value, define and call a function, build and read a record, build and take apart a variant, repeat with a loop, return a result, and the basic operations like adding and comparing. Everything else you can write reduces to those seven before the compiler is through with it, so it costs nothing in the type checks or the translation. A small core, under a surface where no two spellings mean the same thing, is what makes the compiler something one person can finish.

Memory, and why nothing collects it

Every value behaves as a copy: b = a means b is its own thing, independent of a, and that holds for a record, a list and a map alike. That is the meaning. Underneath, though, nothing is copied until it has to be: the program keeps count of how many holders a piece of data has, and the real copy happens only when somebody tries to modify it while somebody else is still using it. If you are the only holder, it is modified in place.

The language has no value that merely says where another piece of data is, so you cannot keep one in a variable or in a field. The consequence is that every value is a tree: a name in the program at the root, and everything that value contains below it. You cannot build circles, two pieces of data referring back to each other, and those are exactly the case where counting holders would fail. So the language needs no garbage collector, no annotations to get right to break the loops, and no pause for tidying up. Swift ships the same machinery and does need those annotations, because Swift also has shared data. Heroes takes the half that works and declines the half that brings the complication.

Freeing is not guesswork either: the compiler writes the counting into the program as real instructions, and each function has a single exit path for cleanup, so whichever route the code takes, what it took is given back. Everything underneath this is 4,500 lines of C.

The language has one explicit goal: a program must not crash and must not wreck memory. The operations that go wrong quietly in C go wrong loudly here. A number that overflows its space is always checked, remainder is guarded like division, an index past the end of a list stops the program: always at the same place, on every run, instead of carrying on with an invented value. And this is not asserted, it is measured: with the tools that watch memory while the program runs, with a check that reports at exit anything not given back, and with the deliberately damaged programs. One hole remains, and it is declared: when you hand data to a C function, what that function does with it is still C's business. Running out of stack used to be the second hole, and it is closed. A program that recurses deeply enough now stops with panic: stack exhausted in main.down, naming the function, where it used to be the operating system killing it without a word. On Windows the line names the failure and not the function. Build with --sanitize and the sanitizer names the function and the line instead.

The rules it lives by · fashion ·

  • What counts is understanding a line by looking at that line. Its meaning is decided by the line itself and the function around it, never by something written three files away. No inheritance, no macros, no exceptions, no automatic conversion between types, no null.
  • One way to write anything. A command that puts code back into its single canonical shape, one word for loops, no automatic conversion between types, and argument names required where types are not enough to tell them apart. The mistakes models actually make become errors the compiler actually raises.
  • Errors written to be read by a machine. Every message carries everything needed to fix the program in one go: what the compiler expected, where the thing it clashes with was declared, and the repair, tagged certain when it is sure and guess when it is a suggestion. And writing ??? leaves a declared gap and asks the compiler what belongs in it.
  • A program must not crash. Where two designs are both acceptable and one of them can be made to fall over, the other wins, whatever it costs in elegance or in words. The section above has the argument and the one hole it leaves open.
  • Small enough to compile itself. The whole specification measures 3,718 tokens against a hard ceiling of 4,096: five pages, written to be handed to a model rather than shelved.

The obvious objections · quicksand, avoided ·

Why no null, and no exceptions?
Both produce the one kind of trouble no compiler can flag: the case you forgot to handle. Here a value that might be missing is declared in the type (i64?), an operation that went wrong returns a value saying so (fail(code, msg)), and when that failure is passed up to your caller you see it on the line, marked ?. Anything that jumps the program from one place to another without showing it is banned wholesale: exceptions, inheritance, macros, operator overloading. The reader has that line and nothing else, and cannot go hunting for a definition three files away. The chapter on this →
Why do arguments need names when two parameters share a type?
Swapping two arguments of the same type is a model classic, and since the types match nobody notices: the program compiles and copies backwards. Writing copy(from: a, to: b) costs four characters and spends them exactly where that error lives. Where the types already tell the arguments apart, as in save(42, "mario"), names stay optional.
Why refuse one integer type, and then ship eight widths?
In C, the rules for how one kind of number becomes another are the number-one source of trouble, and they are also the bulkiest thing to write down: for a long time the answer here was one integer type and nothing else. Then the different sizes were asked for anyway, and the expensive half turned out to have been paid already. What makes eight number types dangerous elsewhere is the conversion that happens on its own, and those had been banned here from day one for an unrelated reason. So i8 through u64, plus the two types with a decimal point, cost about a paragraph of specification: every conversion is still written by hand, and the word int became an error that lists the sizes to choose from.
Why is the formatting rigid, exactly 4 spaces, tabs are errors?
So that “nearly right” is a compile failure instead of a silently different program. A canonical formatter removes every style decision from the writer: any textual difference between two programs is a difference in meaning.
Why is every assignment a copy?
So that a piece of data never has two names. If nobody else can be holding the same data you are holding, no function changes it behind your back, and two parts of the program running at once cannot trample each other. Nor can you build those circles where two values keep each other alive, which is what makes it possible to free memory by counting holders, with no garbage collector. On top of that, understanding a line takes only that line. The price is real, though, and the spec writes it down rather than hiding it: + on str copies both sides, so a concatenation loop is quadratic, and join and repeat exist to build in one pass; xs @ xs.push(4) grows in place while nothing else holds xs.
What is missing, and what is this language bad at?
Four things, said here rather than left for you to find on the way. You cannot do two things at once: the design document calls it the largest gap, and a deliberate one. There are no anonymous functions, the kind written inline inside a call: a function you pass to another function is an ordinary declared function, with a name. Adding pieces to a string in a loop costs more and more as the string grows, because the whole thing is copied each time (growing a list does not have this problem). And functions can work across several types of data, but with no conditions attached to those types and never written out at the call. The other half of the honesty is what happens while the program runs: a number that overflows, an index past the end of a list and a division by zero all stop the program, always the same way, instead of letting it carry on with a meaningless value.
How does a line end, if there are no semicolons?
The compiler puts the semicolon in for you, but only when the line can be over, meaning it finishes with a name, a value, a closing bracket, or one of a short list of words. A line ending in + is visibly half-said, so the sentence continues below. Long expressions break inside brackets, where indentation stops counting; outside brackets every indent counts, because it is what says where a block starts and ends. The rule is taken from Go, and the first version written here was wrong: the list of words had been copied incompletely, so break alone on a line never ended its statement.
What can a string hold?
Inside a string, some characters are written with a backslash in front: \n for a new line, \t for a tab, \r, \\ for the backslash itself and \" for a quote, and \' in place of that last one inside a character literal. There are six in total and no others, so every character has exactly one spelling. Any other letter after the backslash is a compile error, with the correction attached. Before this check existed, "a\nb" compiled happily and printed a backslash, which is exactly the sort of quiet wrong answer this language exists to make impossible. One limit remains, and we say so: "C:\temp" still contains a tab, because \t is a legitimate spelling and no compiler can read your mind.
Can the same variable be passed twice to one call?
No, not when both parameters can write into it. An argument a function may modify is marked @ at the call as well, and it is copied in at the start and copied back out at the end. Point two of them at the same variable and the result depends on which copy is written back last, an order nothing specifies. Ada lived with that for three decades and then made it illegal in 2012, for the reason this language is built around: an answer that changes with the order the machine does things in is nearly always a bug. Rejecting it is what makes the promise that a piece of data never has two names actually true.
And the spec is capped at 4096 tokens. Why cap it at all?
Because the spec is the text you hand a model before asking it for a program, and space in a prompt runs out. Everything the language adds has to pay rent in there, and a language whose whole definition fits in a few pages is also a language one person can implement. It currently measures 3,663 tokens, leaving 433 to spend. The number is counted, not eyeballed: the old word count made the specification look one-third smaller. Two separate programs count it now, and where they disagree the larger number binds.
