“Heroes”

A small compiled language, designed for the reader that reads most code today: a language model.

pre-alpha · being built in the open · where are we now? ↓

The thesis

A language designed so that every plausible LLM mistake is a compile error will produce working programs in fewer total tokens than a conventional language — even if each program costs more tokens to write.

Nothing here is taken on faith: the claim is measured, continuously, against a control build of the same compiler with the safety rules switched off.

What it looks like · sound and vision ·

# A comment adjacent to a declaration is its documentation.
# Squared distance. Avoids sqrt to preserve precision.
dist2 = function: (a: Point, b: Point) -> int
    dx = a.x - b.x
    dy = a.y - b.y
    return dx*dx + dy*dy

Point = record
    x: int
    y: int

test "3-4-5 triangle"
    assert dist2(Point(x: 0, y: 0), Point(x: 3, y: 4)) == 25

The rules it lives by · fashion ·

  • Locality is the currency. The meaning of a line is decided by that line plus the enclosing signature — never by something defined three files away. No inheritance, no macros, no exceptions, no implicit conversions, no null.
  • Exactly one way to write anything. A canonical formatter, one loop keyword, one integer type, mandatory named arguments where types could be confused. Errors that models actually make become errors the compiler actually raises.
  • Errors written to be read by a machine. Every diagnostic carries everything needed to fix the program in one turn — expected type, definition site, concrete fixes. Typed holes (???) let a program be built skeleton-first.
  • No standard library — on purpose. A minimal runtime, native binaries, no GC (refcounting + copy-on-write), and everything else through a C FFI where clang verifies every signature against the real header.
  • Small enough to compile itself. The whole specification fits in ~1500 tokens. The language is finished for v1 when its compiler is written in it — and the bootstrap compiler is retired.

Why these choices · quicksand, avoided ·

One formula drives every decision: real cost = program tokens × (1 + rewrite rate). A clever compact construct saves a few percent of a file's tokens; a single correction round-trip — model reads the error, re-reads the file, rewrites, recompiles — costs 500–2000. One correction round wipes out ten syntactic optimisations. So Heroes never shortens anything at the price of a plausible silent error. Some consequences, each an answer to a real mistake models make:

Why no null, and no exceptions?
Both produce the one class of bug that raises no compile error: the unhandled path. Absence is a type (int?), failure is a value (fail(code, msg)), and propagation is visible on the line (?). Invisible control flow is banned wholesale — exceptions, inheritance, macros, operator overloading — because a model reads locally and cannot jump to a definition three files away.
Why do arguments need names when two parameters share a type?
Swapping two same-typed arguments is a classic model error — and the types match, so nothing catches it. copy(from: a, to: b) spends tokens exactly and only where that error lives. Where types already protect (save(42, "mario")), names stay optional.
Why one integer type?
Conversion rules are the most expensive item a spec can carry and the number-one error source in C. One int, no implicit conversions, no width bugs — and a whole family of ambiguities never exists.
Why is the formatting rigid — exactly 4 spaces, tabs are errors?
So that “nearly right” is a compile failure instead of a silently different program. A canonical formatter removes every style decision from the writer: any textual difference between two programs is a difference in meaning.
Why no standard library?
A modern standard library is more work than a compiler — it is what kills one-person languages. Heroes ships a minimal runtime; maths, files, JSON, HTTP arrive from C libraries through an FFI where the C compiler verifies every declared signature against the real header. A wrong FFI type is a compile error, not a runtime disaster.
Why does the compiler emit C?
Chosen for the boundary, not for speed: emitting C makes the FFI nearly free (headers, macros, verification included) and gives real debugging via #line. The original backend (QBE) was dropped when the founding constraint won the argument — the whole debate is in the repo, verdicts included.
Why value semantics — every assignment a copy?
No aliasing means no function can modify your data behind your back, no data races by construction, and reference cycles cannot exist — so refcounting with copy-on-write is complete memory management, no GC. Locality becomes total: what a line means is decided by that line.
And the spec fits in ~1500 tokens. Why so hard a cap?
Because the spec is the prompt. Every feature pays rent in it, and a language whose entire definition fits in two pages is also a language one person can implement — the two constraints are secretly the same one.

The build log · changes ·

The journey, newest first — one entry per milestone. The full diary (decisions, adversarial reviews, predictions and what broke) lives in the repo; this is the postcard version.

  1. 2026-08-03 · M0 — day zero Foundations, and four programs written before the compiler. Git, a Rust workspace, a golden-test harness green with zero tests, and the language spec frozen at ~1500 tokens as the measurement baseline. Then four hand-written C programs — the exact shape the compiler must one day emit — including a recursive tree with reference counting, verified leak-free under AddressSanitizer. The machine found the first design bug before any human did: an unused-label warning that changed how every generated function will begin.
  2. 2026-08-03 · before the code The plan meets five hostile experts. Before a single token was lexed, the build plan was reviewed by five adversarial reviewers — language design, compiler engineering, simplicity, LLM ergonomics, didactics. Three said object. The thesis metric gained a control arm, two missing compiler passes were discovered, and the backend switched from QBE to C emission — for the FFI, not for speed. The plan that survived is revision 2.
  3. 2026-08-03 · the beginning A 2000-line design document and one question. The language arrived as a long design conversation: a compiled language with no standard library, built for the reader that isn't human. The first engineering decision — which language writes the language — was overturned within the hour by a one-line question about the backend. Everything since has been argued in writing.

Follow the build · station to station ·

The compiler is an assembly line — lexer to parser to types to IR to C — and it is being built in the open, one documented station at a time: design decisions, adversarial reviews, measurements and all. github.com/giuseppearici/heroes-lang.

The name is an homage to David Bowie's “Heroes” (1977) — the quotation marks are his. The lightning bolt is borrowed from 1973, worn at a respectful angle. The section nods are song titles, nothing more: the irony lives in the packaging, and the language keeps its keywords plain — you will never meet Bowie in an error message.
