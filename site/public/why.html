Why Heroes

· rebel rebel ·

Two constraints, both older than the grammar: no standard library, and the reader is a machine.

The founding constraint

The project did not start from a grammar. It started from a refusal: there is no standard library, and there never will be one. A modern standard library is more work than a compiler — it is the thing that kills one-person languages. So Heroes ships a minimal runtime and gets everything else from the enormous amount of C that already exists: 

maths beyond arithmetic   → libm          files, sockets  → libc
regular expressions       → PCRE2         HTTP            → libcurl
JSON                      → cJSON         SQL             → SQLite
graphics, audio, terminal → SDL, raylib, ncurses

That is not laziness, it is the leverage that makes a one-person language viable — and it has a consequence the rest of the design obeys: the ergonomics of the C boundary rank alongside comprehension, not below it. A library Heroes cannot bind is C code its author has to keep writing by hand, which is the one thing this refusal exists to prevent.

Which is why the compiler emits C

A program that borrows a C function should be checked against the library's own header — not against a description the compiler invents and hopes is right. Emitting C means clang does that checking, on every build, for free: a wrong signature is a compile error rather than a corrupted value at runtime. An earlier design emitted machine code through a small intermediate language, and it was dropped the day someone noticed the founding constraint had already decided the question.

It is not a decision about speed. Speed is explicitly not a goal of this project — and explicitly not an excuse either.

The reader that reads most code · sound and vision ·

The second reason is newer. Most code written today is written by a language model, and models fail in specific, catalogued, reproducible ways: they swap two arguments of the same type, forget a case, mutate a name they never declared, invent a keyword from another language. A language can treat those as accidents or treat them as the design brief.

A language designed so that every plausible LLM mistake is a compile error will produce working programs in fewer total tokens than a conventional language — even if each program costs more tokens to write.

That is a claim, and it is empirical rather than aesthetic, so it is measured: take working programs, inject one plausible mistake into each, and count how many produce a compile error rather than a program that runs and is silently different. Then run the same corpus against a control build of the same compiler with the thesis rules switched off. The gap between the two columns is the whole measurement.

One formula decides the trade-offs

real cost = program tokens × (1 + rewrite rate)

The two factors differ by orders of magnitude. A clever compact construct might save five percent of a file's tokens. A single correction round-trip — the model receives an error, re-reads a file, rewrites a function, recompiles — costs five hundred to two thousand. On a three-thousand-token program, one correction round wipes out ten syntactic optimisations.

The instinct says shorten everything and be careful. The formula says eliminate errors, and only shorten when it is free. So Heroes is verbose where you declare and terse where you use, and it never spends a token in a place where no error actually lives.

The rules it lives by · fashion ·

  • Locality is the currency. The meaning of a line is decided by that line plus the enclosing signature — never by something defined three files away. No inheritance, no macros, no exceptions, no implicit conversions, no null.
  • Exactly one way to write anything. A canonical formatter, one loop keyword, no implicit conversions of any kind, mandatory named arguments where types could be confused. Errors that models actually make become errors the compiler actually raises.
  • Errors written to be read by a machine. Every diagnostic carries everything needed to fix the program in one turn — expected type, definition site, concrete fixes tagged certain or guess. Typed holes (???) let a program be built skeleton-first.
  • A program must not segfault. That is a goal of the language, not a quality of its implementation — and where two admissible designs disagree and one of them can be made to crash, the other wins, whatever it costs in elegance or tokens.
  • Small enough to compile itself. The whole specification is measured at 3512 tokens against a hard ceiling of 4096 — five pages, and it is not documentation, it is the prompt.

The obvious objections · quicksand, avoided ·

Why no null, and no exceptions?
Both produce the one class of bug that raises no compile error: the unhandled path. Absence is a type (i64?), failure is a value (fail(code, msg)), and propagation is visible on the line (?). Invisible control flow is banned wholesale — exceptions, inheritance, macros, operator overloading — because a model reads locally and cannot jump to a definition three files away. Why do arguments need names when two parameters share a type?
Swapping two same-typed arguments is a classic model error — and the types match, so nothing catches it. copy(from: a, to: b) spends tokens exactly and only where that error lives. Where types already protect (save(42, "mario")), names stay optional.
Why refuse one integer type, and then ship eight widths?
Conversion rules are the most expensive item a spec can carry and the number-one error source in C, so for a long time the answer was a single int. Then the widths were asked for anyway — and the expensive half turned out to have been paid already: what makes several number sizes dangerous elsewhere is the implicit conversion, and implicit conversions had been banned from day one for an unrelated reason. So i8 through u64 plus f32 and f64 arrived at roughly the size of a paragraph, every conversion still written out by hand, and the word int became an error that names the widths.
Why is the formatting rigid — exactly 4 spaces, tabs are errors?
So that “nearly right” is a compile failure instead of a silently different program. A canonical formatter removes every style decision from the writer: any textual difference between two programs is a difference in meaning.
Why value semantics — every assignment a copy?
No aliasing means no function can modify your data behind your back, no data races by construction, and reference cycles cannot exist — so refcounting with copy-on-write is complete memory management, no garbage collector. Locality becomes total: what a line means is decided by that line.
How does a line end, if there are no semicolons?
The compiler adds the ending itself, but only when the line can be over — when it finishes with a name, a value, a closing bracket, or one of a short list of words. A line ending in + is visibly unfinished, so it continues. Long expressions break inside brackets, where indentation stops meaning anything; outside them, every line's indentation is structural. This is Go's rule, and the first version of it here was wrong: the list of words had been copied incompletely, so break alone on a line never ended its statement.
What can a string hold?
Five escapes, and no more: \n, \t, \\, plus \" inside a string and \' inside a character literal — so every character has exactly one spelling. Any other letter after a backslash is a compile error carrying its own correction. That second half is the point: until it existed, "a\nb" compiled happily and printed a backslash, which is the kind of quiet wrongness this language exists to make impossible. One honest limit survives: "C:\temp" still means a tab, because \t is legal and no compiler can read intent.
Can the same variable be passed twice to one call?
No — not when both parameters can write to it. Mutable arguments are marked @ at the call site and copied in and out, so two of them aimed at one variable would make the result depend on the order the copies are written back — an order nothing specifies. Ada lived with that for thirty-three years and then made it illegal in 2012, for the reason this language was built around: an answer that depends on evaluation order is usually a bug. Rejecting it is what makes the promise “no aliasing exists anywhere” actually true.
And the spec is capped at 4096 tokens. Why cap it at all?
Because the spec is the prompt. Every feature pays rent in it, and a language whose entire definition fits in a few pages is also a language one person can implement — the two constraints are secretly the same one. It currently measures 3512, leaving 584 to spend. The number is measured, not estimated, and that distinction cost the project two days: the budget was defended with a word-count rule of thumb until someone actually counted, and found the spec a third larger than believed. It is counted now with two published tokenisers, offline; where they disagree, the larger one binds.
