Errors

· always crashing in the same car ·

A diagnostic is a deliverable here, not plumbing. Every one of these is real output, copied from the repository.

A model does not have the project open. It receives one message and must fix the program from that message alone — or spend a whole round-trip re-reading files, which the cost formula says is the most expensive thing that can happen. So every diagnostic carries three things: the span, the other end of the story, and the repair.

The classic inversion

Two parameters of the same type, arguments the wrong way round. It type-checks perfectly in most languages and does the wrong thing. Here the names are mandatory precisely because the types cannot help: 

error[needs_label]: two of `copy_text`'s parameters are `str`, so every one of them is named at the call site — this one is `from`
  at tests/golden/check/swapped-arguments.hero:16:21
     |
  16 |     print(copy_text("a", "b"))  #~ needs_label needs_label
     |                     ^^^
  fix (certain): write `from: `

error[wrong_label]: `copy_text` has nothing called `to` at this position — it is `from`
  at tests/golden/check/swapped-arguments.hero:18:21
     |
  18 |     print(copy_text(to: "b", from: "a"))  #~ wrong_label wrong_label
     |                     ^^
  fix (certain): write `from:`

The #~ needs_label notes are in the source on purpose: they are how the test suite checks that the underline lands where the message says it does. And the caret is the span, not the line — in a long call the wrong argument is pointed at rather than described.

Two kinds of fix, and only one is machine-applicable

A fix tagged certain is one the compiler computed rather than guessed — the missing annotation the checker just inferred, the single in-scope candidate for a typo'd name. heroes check --apply applies those and the result compiles; continuous integration asserts exactly that. A fix tagged guess is prose for the reader, and no tool may ever apply it. Guessing a repair that a model would apply blindly is worse than explaining.

The same diagnostics come out as JSON — stable machine-readable codes, spans, notes and fixes — when the thing doing the reading is a program.

Words from other languages, refused with the answer attached

The likeliest mistake from a model on autopilot is a keyword imported from somewhere else. Each one is a compile error carrying its own solution, which makes it a single-turn repair rather than a conversation: 

tests/golden/check/reserved-words.hero:2:1: error[reserved_word]: `struct` is not a word in this language — use `record`: `record Point`
tests/golden/check/reserved-words.hero:3:1: error[reserved_word]: `let` is not a word in this language — bind with `=`: `x = 5`
tests/golden/check/reserved-words.hero:4:1: error[reserved_word]: `const` is not a word in this language — use `constant`: `constant MAX: i64`
tests/golden/check/deleted-int.hero:23:8: error[reserved_word]: `int` is not a word in this language — an integer says its width: `i64`, and also `i8` `i16` `i32` `u8` `u16` `u32` `u64`

That is the one-line-per-diagnostic form, which is what the golden tests pin; the fuller rendering above is what the command prints. Three of those four carry a certain fix, so --apply migrates a whole file of borrowed keywords in one pass.

An unfinished program is not a broken one

??? is a legal expression anywhere. The compiler type-checks everything around it and then reports what belongs in the gap — the expected type, what is in scope, and which functions return it. It produces no binary, and it exits zero, because a skeleton under construction is not an error: 

hole at examples/gallery/09-holes.hero:26:74
  expected type: str
  in scope:
    entries: [Entry]
  functions that return it:
    summary_of(entries: [Entry])
      # The hole can be one argument of an otherwise finished line.
    library.hero_args_at(index: i64)
    library.hero_file_read(path: cstr, @status: i64)

That is what lets a program be written skeleton-first: sketch the shape, let the compiler tell you what each gap needs, fill them in. The hole is a question the compiler answers, not a failure it reports.

How this gets measured

None of the above is worth anything as an assertion, so it is a number. heroes mutate takes working programs and injects one plausible mistake at a time — swapped arguments, a dropped label, a lazy catch-all, a shadowed name — then counts how many the compiler catches. The same corpus then runs against a control build with the thesis rules switched off, and the difference between the columns is the only part that means anything.

On the last full run: 502 of 529 injected mistakes caught, 96% — against 79% for the control. The gap concentrates exactly where the design predicted. Dropped argument labels go from 90% to zero, and a lazy catch-all over a variant from 100% to 39%, because nothing else in a conventional language is looking for either.
