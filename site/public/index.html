A compiled programming language

“Heroes”

Small enough to fit in a prompt, real enough to compile itself.

Made for the machines that write code, and clear to the people who read it. The whole language fits in five pages: hand them to a model and there is still room for the program. What you write becomes an executable, with nothing else to install. And the mistakes models make most often do not compile here.

Native binaries, no runtime to install · sound and vision ·

That is a tree that contains itself. And it does it in a language with no pointers: the values that hold no data of their own and only say where the real data sits. Here the only way to refer to another thing is a list, which is why the branches of that tree live in one. So the whole tree copies the way a number copies: pass it to a function and that function gets its own.

Every code block on this site is cut from a real file that lives in the public repository and that compiles and runs, including that one.

Run it

There is no installer and nothing to install. The repository carries the compiler already translated into a single C file, so all your machine needs is a C compiler, which on a Mac or on Linux is usually there already: 

$ git clone https://github.com/giuseppearici/heroes-lang
$ cd heroes-lang
$ clang -I runtime seed/heroes.c runtime/runtime.c -o heroes
$ ./heroes run examples/gallery/03-fallible.hero
read 42
failed: not_a_digit (expected 0-9)
20

Nobody typed that C file by hand: it is Heroes translating itself into C as it compiles itself. So the command above builds Heroes out of Heroes alone: nothing else to install, and no toolchain to assemble first. If something goes wrong, ./heroes doctor tells you which piece your machine is missing.

That middle line saying failed is not the build breaking: it is the example program meeting a character it cannot read and saying so, the way it was asked to. The chapter on it walks through that program line by line.

Then write your own. The file needs nothing around it: no import lines at the top, no project file listing the other files. It only needs a main inside it, which is the function the program starts from. 

$ printf 'function main()\n    print("we can be heroes")\n' > hello.hero
$ ./heroes run hello.hero
we can be heroes

heroes run turns that file into an executable and launches it, from any directory, leaving its working files in a build/ folder beside you. Everything the language can do goes through that one command: lex, parse, check, build, run, test, fmt, doctor, mutate, measure, this. Every example on this site is a file in examples/, waiting to be changed.

Three things that make it different

  • Mistakes are compile errors

    Two arguments of the same type, swapped. A case left out of the forms a value can take. A name changed without being declared. A keyword stolen from another language. None of these compile here, and the error arrives with the repair already written in. Elsewhere the program runs and gets it quietly wrong.

    See a real error

  • No standard library, on purpose

    Heroes carries no warehouse of ready-made functions. Maths, files, networking, JSON, databases and graphics all come from the C libraries the world has been using for fifty years, and a few lines connect them to your program. The C compiler checks those lines against the library itself and stops you when they disagree.

    The founding constraint

  • It compiles itself

    The Heroes compiler is written in Heroes: 155 files, 38,004 lines. Ask three generations of it to write the same program out and the three results match to the byte. The language it was first built in is no use to anyone now and has left the repository.

    How it compiles itself

A small surface, no collector, and no crash

In a Heroes file, a line starting at the left margin can begin with four words and no others: constant, function, record, variant. Those are a fixed value, a function, a group of data with named fields, and a value that can take several forms. The list ends there: no classes, no interfaces, no global variables anybody can change. And the order you write declarations in never matters, so two functions can call each other with nothing announced in advance. Further down, what the compiler really handles is seven constructs: everything else reduces to those before the compiler is done with it, which is how one person finishes the job.

Memory frees itself, and without a garbage collector, meaning without the service that in other languages runs alongside your program and pauses it now and then to tidy up. It works like this: every value behaves as an independent copy, and underneath the compiler keeps count of how many holders a piece of data has and frees it when the last one is gone. Since a value cannot hold on to another, you cannot build circles where two pieces of data refer back to each other, and that is exactly the case where counting would fail. And a program must not crash or quietly wreck memory, which is a stated goal of the language rather than something its implementation happens to get right: a number that overflows, an index past the end of a list, a division by zero, each stops the program on the spot, always at the same place, instead of carrying on with an invented value. The claim · quicksand, avoided ·

A language designed so that every plausible LLM mistake is a compile error will produce working programs in fewer total tokens than a conventional language, even if each program costs more tokens to write.

A token is the scrap of text that measures what it costs to put a model to work, roughly a word. The claim is that Heroes spends fewer of them overall, even though a single program is longer to write, because you are not spending your time correcting it. It is a claim, not a slogan, so it is measured. The heroes mutate command takes programs that work, plants one realistic mistake at a time (two same-typed arguments swapped, a case left out, a name reused) and counts how many the compiler stops. Then it does the same run with the thesis rules switched off, and the distance between the two runs is the result, kept mistake by mistake: some only Heroes catches, some any language would catch, and one nothing catches yet. An average would hide exactly that, so there is none.

Heroes is built in the open and it is not packaged yet: no installer and no releases, so the way in is a C compiler and one command. The record of every decision, panels and measurements included, is public in the repository.

The name is an homage to David Bowie's “Heroes” (1977), and the quotation marks are his. The lightning bolt is borrowed from 1973, worn at a respectful angle. You will never meet Bowie in an error message.
