The language, page by page, for a reader who has not read the specification, and should not have to.

How to read this

Heroes has a specification, and it is deliberately not a teaching text: it is the control instrument, budgeted to the token so that the whole language fits in a prompt. Reading it teaches you the rules the way a rulebook teaches a game. These pages are the other thing, one idea at a time, in order, with the reasoning left in. Until they are all written, the rulebook is also the only complete answer: the whole language, 229 lines.

Every code block in this documentation is a slice of a file in the repository that compiles and runs. Nothing here is typed into the page and hoped for. Each block names its file underneath, so you can open it, run it, and change it.

Errors, which are part of the language

A diagnostic here is a deliverable rather than plumbing, so it is documented like everything else: what the compiler prints, the repairs it can apply to your file for you, the holes it still has, and the measured catch rate for each kind of mistake. Every error shown is real output, copied from the repository and not trimmed to look better. Errors, and how to read one →
