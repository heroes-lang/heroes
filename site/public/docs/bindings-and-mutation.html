Bindings and mutation

One symbol marks everything in a program that can change.

Two lines out of three in most code do not change anything. The trouble is that they look exactly like the ones that do, so finding the part of a program that moves means reading all of it. Here the moving parts carry a mark, and there is only one.

= binds once. @ declares something that changes

x = 5              # a name for a value, forever
v: i64 @ 0         # a cell that may change — the type is required
v @ v + 1          # changing it

= gives a value a name and that is the end of it. @ does three jobs with one symbol: it declares a cell, it marks every line that writes to one, and — later on this page — it marks a function that changes what it is given. There is no separate assignment operator, so a line that changes something can never be mistaken for a line that introduces something.

The type on a cell is not optional, and that is deliberate: a name whose value will change over time is a name whose type a reader cannot infer from one line. Try to change a plain binding and the compiler explains the difference: 

$ heroes check mutation.hero
error[not_mutable]: `start` was bound with `=`, which binds once, forever — a cell is declared with its type: `start: <type> @ <value>`
  at mutation.hero:31:5
     |
  31 |     start @ start + 1
     |     ^^^^^
  fix (guess): declare `start` as a cell: `start: <type> @ <value>`

That fix is tagged guess rather than certain, because the compiler cannot know which of the two you meant — you may have wanted a cell, or you may have written to the wrong name. Only certain fixes can be applied for you.

A name means one thing while you can see it

Reusing a name that is already in scope is not allowed, even when the new one would be a different thing: 

$ heroes check mutation.hero
error[shadowed_binding]: `start` is already in scope, bound at line 30 — shadowing is an error here: a name means one thing for as long as it is visible
  at mutation.hero:31:5
     |
  31 |     start = r.pos + 1
     |     ^^^^^

Shadowing is the mistake that produces no symptom: the code compiles, runs, and quietly uses the wrong one of two things with the same name. It is also near the top of what a model writing code gets wrong, which is why the compiler treats it as an error rather than a warning nobody reads.

Every value is a copy

b starts as a copy of a, and pushing onto it leaves a alone. This holds for arrays, maps, strings and records alike, at any depth: nothing in this language aliases anything, so no change made over here can appear over there. Under the surface the compiler shares the memory until somebody writes, and copies only then — but that is an implementation detail you are never asked to think about.

Note also b @ b.push(4). push hands back a new array rather than changing one in place, so the result has to be put somewhere, and the @ is where it goes.

When a function does need to change its argument

Copies everywhere would make a cursor over some text impossible to write, so there is one exception, and it is spelled out on both sides of the call. A parameter marked @ is changed by the function:

And the call site says so too, or it does not compile: 

$ heroes check mutation.hero
error[marker_mismatch]: `advance` changes this argument, so the call site writes `@` too
  at mutation.hero:26:17
     |
  26 |         advance(r)
     |                 ^
  fix (certain): mark the argument: `@x`

This is the difference between reading a call and reading a function. In most languages, whether advance(r) modifies r depends on advance, on the type of r, and sometimes on the platform. Here the answer is in the character you are looking at.

The meaning is copy in, copy out: the function works on its own copy and the caller's value is replaced when it returns. That happens on every exit, early return included, so there is no path where half the changes arrive.

A function may change its argument and return something, as this one does: the reader moves past the word, and the word comes back. One thing it cannot do is be called as a method: r.word_at() is not allowed when the first parameter is @, because that spelling would hide the mark this whole chapter is about.

A binding nobody reads is an error

$ heroes check mutation.hero
error[unused_binding]: `spare` is bound and never read — remove the binding, or read it
  at mutation.hero:53:5
     |
  53 |     spare = 5
     |     ^^^^^

An unused name is usually a leftover from an edit, or a line whose result was supposed to be used and is not. Both are worth stopping for. When you really do want to throw a result away, say so with _ = f(x): the discard is written down rather than implied, and _ binds nothing so it can be repeated.
