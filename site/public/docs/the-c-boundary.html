The C boundary

Everything the language does not have, and where it comes from.

Heroes has no standard library, and it never will. Everything you have seen in these chapters — numbers, strings, arrays, maps, printing — is the whole inventory. Files, sockets, JSON, databases, graphics, maths beyond arithmetic: none of that is missing, and none of it is coming. It arrives from C, through one mechanism, and this chapter is that mechanism.

A group names its header

Three C functions, usable from the next line on. The header name is not decoration and the whole design turns on it: clang reads that header and checks every declaration in the group against it. A binding is the one place a program can reach an address nobody checked, so this is the place the language spends its care.

What that check catches

Misspell a name and you do not get a link error at the end of a long build. You get this, on your line, with the header’s own answer attached: 

$ heroes build ffi.hero
error[ffi_unknown_name]: `math.h` declares no `flooor` — clang read the header and could not find it
  at ffi.hero:15:5
     |
  15 |     function flooor(x: f64) -> f64
     |     ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
  note: an `extern` names what the header already has (§4.19): check the spelling, or name the header that does declare `flooor`
  fix (guess): the header declares `floor`

That last line is worth a second look. The compiler did not guess from a list it keeps: it asked clang, which had the real header open, and clang knew what you meant.

Get a type wrong and the answer comes from the same place: 

$ heroes build ffi.hero
error[ffi_return_type]: `puts` does not return `cstr` — that is what `stdio.h` says, and clang read it
  at ffi.hero:22:5
     |
  22 |     function puts(s: cstr) -> cstr
     |     ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
  note: an `extern` is checked against the real header (§4.19): correct the result type, or name the header that declares this `puts`

In most languages a foreign declaration is a promise nobody verifies: get it wrong and the program builds, runs, and corrupts something. Here the promise is checked against the library that has to keep it.

The boundary is visible in the types

cstr is a C string and ptr is an opaque pointer. Neither is a str, and no conversion happens behind your back: s.cstr() lends a Heroes string to C to read, and c.to_str() copies one back. Test c == nullptr first, because converting a null one stops the program.

So a value that came from C is marked as such everywhere it goes, and the line where it stops being foreign is a line you can see.

Using them

A C function is called like any other, and the mandatory-label rule from chapter 2 applies to it too. That matters more here than anywhere: C’s numeric interfaces are full of same-typed pairs, and pow(base:, exponent:) is exactly the shape where getting the order wrong would be silent.

No number changes type on its own. to_f64 always works, so it gives a value; to_i64 can fail, because the float may not fit, so it gives an i64? and this line answers that with .must().

Where the library lives is the machine’s problem

link "m" names a library to link against. When that is not enough — and for anything with system dependencies it is not — a group can name a package instead: 

extern "raylib.h" package "raylib"

That asks the system where the headers and libraries are and what else the library needs: frameworks on macOS, -lGL -lX11 on Linux, in one spelling that is the same everywhere. If the answer contains anything this compiler will not pass on, it is refused, and the message says what the package asked for.

A group can also declare a constant, whose value comes from the header rather than from your file, and a record that mirrors a C struct field for field. Both are checked the same way, by clang, against the real thing.

The program

$ heroes run examples/gallery/08-ffi.hero
the 16:9 diagonal of a 1920-wide screen: 2202.9071700822983

Two C libraries, four declarations, no wrapper and no binding generator. The repository binds SQLite, curl, SDL and raylib the same way: a group, a header, and the declarations that program needs.

That is the language

Twelve chapters, and you have seen all of it: four words that can start a top-level line, one way to take a value apart, one way to fail, one way to change something, and one door to everything else. What is left to learn is not more language, it is what you can build with it.
