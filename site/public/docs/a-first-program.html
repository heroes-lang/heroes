A first program

A file, a main, and nothing around it.

Most languages ask for some ceremony before your first line runs: an import of the thing that prints, a class to hold the function, a project file that says which files exist. Heroes asks for none of it. A program is a file, and a file that can run is one that declares main.

The whole program

$ heroes run examples/gallery/00-first.hero
20

function main() declares where the program starts. It takes nothing and gives nothing back, which is why there is no arrow and no type after the brackets: a function that returns something says so with -> i64, and one that does not stays silent about it. print is built into the language rather than imported from anywhere; it writes its arguments one after the other and ends the line.

What is not in that file

Every absence below is a decision, and the reason is always the same one: the fewer places a fact can hide, the fewer ways a reader, human or model, can be wrong about it.

  • No import or include line. print, len and the rest of the built-ins are simply there.
  • No class and no namespace block. A file is already the unit.
  • No semicolons and no braces. A line ends at the end of the line, and a block is what is indented under it.
  • No project file, no manifest, no build script. The compiler is given a file, not a configuration.
  • No forward declarations. Declaration order never matters, so two functions can call each other without either being announced first.

The indentation is the structure

A block is four spaces deeper than the line that opens it. Not three, not eight, not a tab: exactly four, at every level. That is rigid on purpose, and the compiler tells you so rather than guessing what you meant: 

$ heroes check hello.hero
error[indentation_not_multiple_of_4]: indentation must be exactly 4 spaces per level; found 2
  at hello.hero:2:1
    |
  2 |   print("hi")
    | ^^

A tab is its own error with its own message. The point of the rule is that there is exactly one way to write any program, so two files that do the same thing look the same, and a difference in a diff is a difference in meaning. heroes fmt prints that one form for you if you ever drift from it.

One file is one module

When one file is not enough, another file beside it is a module you can name. use brings it in:

That binds eval.hero, in the same directory, to the name eval, and everything it declares is then written with that name in front: eval.calculate(text, env). There are no aliases and no wildcard import, so a qualified name always says where it came from, and every module you use needs its own use line. Looking up an unfamiliar name is reading, never searching.

The verbs

One binary does everything, and each subcommand answers a different question about the same file: 

$ heroes check program.hero    # names and types, no binary
$ heroes run program.hero      # compile and execute
$ heroes build program.hero    # compile only
$ heroes test program.hero     # run the file's tests
$ heroes fmt program.hero      # print the canonical form

test is the interesting one, because tests are part of the language rather than a library you choose. The points file above carries two of them: 

$ heroes test examples/gallery/01-points.hero
ok   "the 3-4-5 triangle"
ok   "a rectangle keeps its size when it moves"
2 tests, all passed
