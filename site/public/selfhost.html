Written in itself

· a new career in a new town ·

The compiler now exists twice: once in the language it was built with, once in the language it builds.

A language is a toy until it can express its own compiler. That needs a tree with heterogeneous nodes, symbol tables, lists, recursion, error handling and multiple files, so if a language can write that, the argument about whether it is real is over. It was the finish line from the first day, and the test for it is not a test suite.

It is this: ask both compilers to write out the same program in C, and compare the results letter by letter. Then compile the letters the new compiler wrote, and ask that compiler to write the program a third time. 

sha256  373f454482831a9fc23942b8675cfc68e450a61cb49f34f45b7dbeac81173e63

  gen1b.c   the bootstrap, written in Rust
  gen3.c    heroes, written in Heroes
  gen4.c    the compiler that came out of gen3.c

  20,886,539 bytes · 724,245 lines · three compilers · one hash

Read the three names as a chain: the C the bootstrap emits, the C emitted by the compiler that C built, and the C emitted by the compiler built from that. A thing that reproduces itself exactly, twice over. What it took, measured:

  • 143modules of Heroes
  • 34,812lines
  • 0workarounds left
  • 2,570outputs compared, no divergence

That is the whole compiler, not a subset: lexer, parser, resolver, type checker, the intermediate representation and its verifier, monomorphisation, the ownership pass, the C backend, the FFI checks, diagnostics, the printer, the formatter, and the command line.

The best part is what went wrong

Pointed at its own source, the new compiler refused it, claiming that a piece of its own structure contained itself, which was false. That one wrong complaint was the thread, and pulling it produced five real faults in the new compiler and, more surprising, four in the old one. Including this: the underline that shows a reader where an error is was covering the little note written on that same line for the sole purpose of checking that underline. The child corrected the parent.

A compiler pointed at its own source is a corpus no test suite reproduces: 34,812 lines holding every shape the language has, in the proportions real code has them. That corpus is how five of the port's faults were found, and they were one trap worn five ways: a loop jump inside a match arm skipped the line that keeps a hand-maintained index up to date. The Rust original walks the same list with an iterator: there is no index to forget, so it could never have made this mistake.

Twenty million letters behind three words

The very last thing standing between the two files being identical was a message the old compiler had written down for whoever would do this work, in three separate places:

this list comes out in order here, and the new one will owe an explicit sort

Three sorts, unpaid. The result was 20.8 megabytes of C whose lines all matched and whose sequence did not, on 3,330 lines out of 724,197. A map has no order: the language says so, and measurably means it, so the note was correct on the day it was written and stayed correct for months until somebody needed it.

What it costs, since a hash is not the whole story

The project measured itself against ten other compiler source trees, and the uncomfortable row is tinycc: 68,000 lines for all of C, where the Rust bootstrap spends 30,000 on a subset and delegates every backend question to clang. Per unit of language covered, this compiler is expensive. The counterweight is in the same table and is the reason the port was possible at all: a comment ratio of 0.51, comment lines against code lines, nearly double the next highest of them.

What is left

Not a measurement. Two things: the generated C has to be shown building from a clean checkout with nothing but a C compiler, which is how Go shipped 1.4 and how Zig ships its bootstrap, and then the Rust bootstrap gets archived and never maintained again. After that the whole picture is Heroes → C → native binary, with no third language anywhere.
