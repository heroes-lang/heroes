2026-08-12 | **A narrowing asks the value, never the world** (author instruction, after sweep 001). Two of the sweep's twenty defects were protected by a comment that *argued correctly for a world that had changed*: `spans_lines` was narrow on purpose, with the reason written out — a reason about source **a person writes**, which stopped being true the day the 88-column rule made the formatter write source too; and `case_fields_are_counted` returned `false` under a valid argument from a premise that had died. Both had been read by reviewers who agreed with them, which is the whole finding: **a convention about comment style cannot catch this, because the comment is not wrong.** What can catch it is the shape of the question. Both repairs turned out to be the same one — ask the value's own extent, ask the declaration's own fields, instead of asking what kind of thing people write or what the program happened to mention. A fact about the value in hand cannot expire | the rule is now CLAUDE.md §11, with two obligations where a premise is unavoidable: state it as a falsifiable claim rather than a justification, and give it a **test that fires when it dies**, whose failure message names its dependants. `a_declared_type_cannot_contain_a_type_parameter` is the first — §4.12's "generics on functions only" is silently load-bearing in `emit/ctype.rs::mentions_generic`, `ir/mono.rs::contains` and `types/table.rs::poisoned`, all three of which walk `Array\|Fallible\|Map\|Func` and answer `false` for a `Ty::Named`. Nothing connected the three to the rule, and the rule itself is enforced **by accident**: a type parameter is unresolvable in a field because the parameter list lives on the function, not because anyone wrote "a declaration may not be generic".
