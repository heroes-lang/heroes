# Issues — every item this project tracks, one file each

One file is one GitHub issue: a **defect**, a **decision** (a question with the
default it leaves running, a sitting's ratification, or a decision taken), a
**feature** or a **task** of a milestone. A question of comprehension is not an
issue: it is a file of `docs/learn/` (the author's *1a 2a*, 2026-10-05). The rules
are `.claude/rules/records.md` § The issues, their one home; `records/cards`
and the checks beside it are their executors.

**Where a file lives never changes.** `issues/YYYY-MM/DD/YYYY-MM-DD-HHMM-<slug>.md`,
the folder being the day its name carries. A new issue's stamp is the minute it
is filed, so the names read in order are the issues in the order they were born.

**A card opens every file**, eight lines and a blank one: `kind`, `area`,
`milestone`, `filed`, `commit` and `github`, the address of the issue it became
or `none` until then.

**Open and closed stand side by side.** An issue is open while it holds an
unticked item, `- [ ] `, whose line stands first under its card; closing it
ticks that box where it stands, adds what closed it, and fills `commit`: nothing
moves, so a link to the file stays good. A decision recorded as taken holds no
box and is closed the day it is filed. A closed issue is a record below its card.

**Filing one** is a new file in today's folder with its card and its item: a
defect's slug opens `defect-NNN-`, the number one above the highest any issue
states, read and never remembered.

Every file that lived in `docs/records/done/` or `docs/records/log/` until
2026-10-04 keeps its name here, in its name's day's folder.
