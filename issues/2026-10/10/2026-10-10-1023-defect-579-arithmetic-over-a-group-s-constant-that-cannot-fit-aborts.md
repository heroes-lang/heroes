- [ ] **579 — arithmetic over a group's constant that cannot fit aborts at run time, its value known only to clang and the platform** | panel 206's ffi-pragmatist: `x: i32 = PATH_MAX * 600000` builds and prints `614400000` on this Mac (`PATH_MAX` 1024) and aborts 134 on Linux arm64 (4096); `RAND_MAX + 1` and `INT64_MAX + 1` abort 134 everywhere; a build probe of one `__int128` `_Static_assert` per step built only from constants refuses at the `.hero` line on exactly the platform where the run aborts (inserted by hand into two units, Windows unrun) | the emitted probes of a group's constants, `selfhost/emit/`; panel 206 R4, for a sitting of its own · **class: improvement**

    **Origin:** filed by the coordinator at 10:23 on 2026-10-10 from panel 206 (`docs/panel/206-a-constant-s-written-body-that-cannot-be-computed-is-a-compile-error-and-arithmetic-in-a-function-still-aborts-where-it-runs.md`, R4), the ffi-pragmatist's measurement, not re-run by the coordinator.

    **Class: improvement**, 2026-10-10 (`.claude/rules/verification.md` § Bounded discovery): the program aborts cleanly where the value does not fit; a compile-time refusal is hardening, an emitter change for a sitting.

    Measured 2026-10-11 (lane b20-check) with the trunk's compiler at `42656199` (built from its seed through `selfhost/`), on this Mac (arm64, `PATH_MAX` 1024 in `sys/syslimits.h`) and in the Linux arm64 container (Debian clang 22.1.8, the tree by `git archive`), each program built and its binary run under `timeout 10`. `x: i32 = PATH_MAX * 600000` in `main`: the Mac prints `614400000` at `-O0` and `-O2`, Linux aborts 134, `panic: integer overflow`. `x = RAND_MAX + 1` (an `i32` constant) and `x = INT64_MAX + 1` after a `print(1)`: `1` then abort 134 on both, at `-O0` and `-O2` on the Mac; Windows unrun, where the UCRT's `RAND_MAX` is 32767 and the first would fit (an inference). The same step as a written constant's body, `constant BIG: i32` holding `PATH_MAX * 600000`, read after a `print(1)`: the Mac prints `614400000`, Linux `1` then abort 134 where `BIG` is read, the shape `tests/golden/run/fixedbugs-577-a-group-s-constant-in-a-step-aborts-where-it-is-read.hero` pins with `INT64_MAX + 1` (panel 207's R3 witness for this kind). A function never called holding `INT64_MAX + 1` builds and exits 0 on both. `heroes check` exits 0 on every one: it runs no clang (an `extern` declaring `abs` `-> f64` checks 0 and builds 1 `ffi_return_type`, measured the same day). So a value that does not fit aborts where it is computed, on the platform whose header makes it not fit, and nothing that fits is refused: panel 207's R3 as ratified.

    The route that would tell it at compile time with no quota, priced and unbuilt, so its sizes are estimates: for each step of a constant's written body that the walk leaves unknown only because an operand is a group's constant, one `_Static_assert` in the unit, the step re-spelled over `__int128` (`unsigned __int128` for an unsigned width) and held to its width, guarded by `__builtin_constant_p` so a group constant that is no integer constant expression in C (a `static const` object) asserts nothing. Measured by hand in C alone, `clang -std=c11 -fsyntax-only` on four such asserts: the guarded `static const int` asserts nothing on both clangs, `INT64_MAX + 1` fails on both, and `PATH_MAX * 600000` held to `i32` passes on the Mac and fails on Linux (with `-D_GNU_SOURCE`, without which glibc's `limits.h` names no `PATH_MAX`). Clang evaluates it for the target being built, so a cross build reads the target's header (route C's flaw at panel 207 is absent), and an integer constant expression holds no loop, so it ends by its structure, never a quota (design.md Part 6's compile-time evaluation paragraph; it is §4.19's own *the preprocessor evaluates*, which every unit's `__builtin_constant_p` assert already uses). The failed assertion's spelling would be read back by the build's clang-answer reader as `int_out_of_range` at the step's `.hero` line, as `ffi_return_type` is. Its cost: one emitter module over the steps the checker records, about 80 to 120 lines by analogy with `emit/extern_assert.hero`; one spelling in `emit/assert_spelling.hero` and its mapping; about six goldens (`INT64_MAX + 1` refused everywhere, division by a group constant equal to zero, a non-constant group constant asserting nothing, a fitting step building, and the platform-valued shapes judged where their header is); the Windows leg's `__int128` unrun. It would stay a build-only refusal (`check` still accepting, the FFI's existing gap) and leave function bodies to panel 206's R2. It changes what panel 207's R3 lists as aborting where it runs, so it is the sitting panel 206's R4 named, not a lane's repair.
