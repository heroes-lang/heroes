**Status:** `provisional — author ratification pending`.

## The proposal, verbatim

Heroes has never ruled on reflection. Three questions, ruled in one sitting
because the author's own question split from them.

(i) **Run-time reflection** — a value that carries its type and can be asked for
its fields while the program runs.
(ii) **Compile-time derivation over a record's fields** — a `to_str`, a JSON
rendering or a `hash` generated by walking fields, the way the emitter
**already** generates `eq` and `hash`.
(iii) **A general annotation mechanism** — user-defined tags on declarations,
Java's shape, read by the compiler or by other code.

Each verdict is one of three, and each carries a date: it **ENTERS** (with its
own milestone, because a form lands in every tool that reads the language), it
is **REFUSED** as a design.md Part 6 row naming the program or compiler fact
that would make it wrong (CLAUDE.md §12), or it is **DEFERRED** with a return
condition written as a falsifiable claim.

## The through-line: three refusals are sound and three of their reasons are false

This sitting was convened to write down rulings that had never been written. What
it found is that the grounds the record was ready to write down are **wrong**, one
by one, and each was falsified by a seat that went and looked.

### 1. *"Reflection requires runtime dispatch, i.e. an interpreter"* — false

design.md's Ruby row (`:2537`) refuses on that ground and panel 039's C4 row files
reflection under it. **Go is statically compiled to native code and has
`reflect`.** The historian sourced the real cost from the language that shipped
run-time reflection and then removed it: **Rust RFC 0379, *Remove Reflection*,
2014-10-13**, whose three stated drawbacks are *"noticeable increases in compile
time and binary size"* from per-type metadata, formatting that was *"inherently
not speedy"*, and recompilation complexity — and which says reflection became
obsolete **because `deriving` was better**. `std::marker::Reflect` was deprecated
by 1.14.0. TinyGo, a compiled Go, ships an incomplete `reflect` where
`encoding/json` compiles and then panics, and its documented advice is *"use code
generation or manual serialization"*. Nim's own `std/typeinfo` says its RTTI
*"will evolve and may eventually be deprecated"*.

**So the conclusion holds and the reason must be replaced by one Heroes can
measure**: emitted per-type metadata, and the loss of dead-code elimination.

### 2. *"A user-defined tag set cannot be closed by construction"* — false

That clause came out of panel 114 R7 and it was the hinge the brief handed the
sitting. **The distinguishing property is not user-defined against built-in. It is
whether the tag is a name subject to resolution or a string.** A Java annotation
is a type declaration; an undeclared `@Foo` does not resolve. Go struct tags are
strings, and the historian read the primary source: `checkFieldTag()` entered
`govet` **in the same 2011-06-29 commit that introduced the convention**, and
**fifteen years later** `structtag.go` still emits only three diagnostics — none
of them checking that the key `json` is not spelled `jsn`, none checking
`omitempty` against `omitEmpty`. golang/go#41769, filed in 2020 by somebody who
had written `json:"omitempty"` meaning `json:",omitempty"`, was closed
`FrozenDueToAge`.

**So (iii) is refused on cost and blast radius and not on impossibility**, because
a Part 6 row resting on a false impossibility is exactly the row CLAUDE.md §12
forbids.

### 3. *"The recursion cliff dissolves — the walk is `eq`'s walk"* — false, and it was panel 117's own load-bearing sentence

Panel 117 adopted its sixth option and the author ratified it the same day. Its
adoption rested on four claims, and it said of itself, in its own words, *"It is
unrun. No seat compiled it, because no seat was asked about it."* Three things
were owed before it could land. **This sitting ran all three, and two of the four
claims do not survive.**

**The prototype exists**: `selfhost/emit/differ.hero`, **160 code lines** in
`suite_layout.hero`'s own unit, type-checking clean inside the real module graph.
**160 is a floor, not the cost** — it omits TyId-keyed array and map satellites
(because `HeroDesc` carries no field names, so the runtime cannot walk into a
record), the `_case_name` tables (nothing in the compiler turns a variant tag back
into a case name), four runtime entry points that `grep` finds zero of, and the
routing through `abort.hero`, whose `builtins.to_str_entry` refuses **every**
aggregate today. Realistic total **350-450 code lines across six modules and the
runtime**, against `structural.hero`'s **seven** remaining lines and
`ctype.hero`'s **370** already over the ceiling.

**The map case, run.** For the yes-or-no answer the walk is order-independent, and
that half of panel 117 holds: it looks each key up rather than pairing positions.
Then the seat ran the case nobody had asked for. Two `==`-equal left operands
against one right operand:

```
p == q: true          keys(p): b a c      keys(q): b c a
p vs t -> m["a"]: 1 != 10
q vs t -> m["c"]: 3 != 30
```

**Two equal values, two different messages.** The leaf named is a function of
insertion history rather than of the value. That is panel 117's own refusal ground
for map *rendering*, reproduced one level down in the thing it adopted instead.
Sorting would repair it and is unavailable for the reason 117 already recorded:
`runtime/parts/sort.c` dispatches by descriptor pointer identity over twelve
scalar descriptors, so a map with record keys has no order at all.

**The depth case, run.**

```
depth     5  : first differing leaf: v.kids[0].kids[0].kids[0].kids[0].kids[0].tag: 1 != 2
depth  3600  : leaf reported, path is 28 813 characters
depth  3700  : panic: stack exhausted in node_diff        (exit 134)
depth 100000 : panic: stack exhausted in node_diff        (exit 134)

today, at every one of those depths: assert failed: a == b, at exit 0
```

**And the premise is false at the source.** `HeroEqWork`
(`runtime/parts/array.c:185-190`) is `{a, b, elem, len}` — no path, no parent, no
index base — and the outermost call drains **LIFO**, so the first `false` the
drain finds is not the first differing leaf in any order a reader can predict.
`eq`'s worklist cannot carry the walk without a fifth field and an order change in
the one function panel 076 landed. **Panel 076's compiler-engineer condition —
*the emitter veto lifts at release depth > 1000, or on a program whose `==`
recurses unboundedly without passing through `[T]`/`{K: V}`* — is unmet, and
unlike 2026-08-24 this proposal does put a per-field continuation in the emitter.
The veto is engaged.**

**The sixth option's remaining two claims do hold**, and the record keeps them: no
`HeroDesc` member is needed, because records and variants are reached statically;
and it is not a second copy of what the language is. They are not enough.

### And the fourth thing the sitting falsified, which was its own brief

**The brief asked the wrong question for (ii), and the split in the verdict table
is the evidence.** Three seats adopted and two objected, and reading them together
they are not disagreeing — they are answering two different questions. The drafts
the brief carried render **Heroes' own construction call**: `Point(x: 3, y: 4)`.
That is a *display* mechanism. The precedent and the pressure are about a *per-type
walk a program directs at a foreign notation*, which is a different thing.

The warden ran the Principle 0 question nobody had asked — *name one renderer a
derived `to_str` would delete* — over 56 functions, and the answer is **zero**.
The compiler seat reached the same number independently over the 31: `shown(Date)`
gives `1969-07-20` zero-padded, `shown(Count)` gives `12 34 567`, `shown(Amount)`
converts cents, and `examples/json/value.hero:47` sorts its keys, escapes its
strings and emits `null`. A construction-call derive replaces none of them.
**Both seats are right, and their finding is fatal to the drafts and says nothing
about derivation.**

Meanwhile the FFI seat wrote `encoding/json` by hand for three records — **120
lines, both directions, round-tripping** — and then changed `f["width"]` to
`f["witdh"]`. One character.

```
heroes build  ->  exit 0, zero diagnostics
output        ->  {"rooms":[{"name":"hall","tags":["warm"],"witdh":3.0}]}
```

It was caught only because that program round-trips. **A program that only
marshals — that writes a request body, the common case — never finds out, and the
wrong key ships.** Under a derivation whose key comes from the field, `"witdh"` is
unspellable. That is not ergonomics; it is CLAUDE.md's founding line, and **the
two seats that objected were never given it**, because it was produced in a
parallel chair.

## Disagreements, stated rather than smoothed

- **The ergonomist and the two objecting seats do not disagree.** The ergonomist,
  reading only the spec, found the thing a construction-call render is actually
  for and it is not JSON: *a hand-written printer rots*. Add a fifth field to a
  record and the printer still compiles, still reads the value, and silently never
  mentions it again — and §5's unused rule cannot catch it, **because a read is a
  use and a field is not a binding**. That is a display argument and it stands
  beside the warden's serialisation measurement without touching it.
- **The ergonomist vetoed the middle option and the sitting records why**, because
  it is the kind of compromise CLAUDE.md § 4 forbids by name. *"Takes any value
  but a map"* makes `print(c)` a line whose legality cannot be settled without
  opening `record Config`, which §1 permits to live in another file behind a
  `use`. Excluding maps moves the non-locality from meaning to legality without
  removing it.
- **The warden and the FFI seat disagree about what `partial` proves, and both
  measurements stand.** The warden says the drafts cannot survive `record Font
  partial`, which names only some fields and therefore has no honest construction
  call. The FFI seat agrees and goes further with a run: `struct passwd` is 72
  bytes of which 12 are declared, and two records differing in `pw_gid` **render
  identically** while `memcmp` says they differ. Its resolution is that a derived
  render over a `partial` must **abort**, joining `_eq` and `_hash`, which already
  do — the sitting adopts that as a standing constraint on any future derivation
  and not as a verdict on (ii).
- **The compiler seat and the FFI seat reached the same conclusion about (i) from
  opposite ends, and neither knew of the other.** The FFI seat measured that
  `strip -x` deletes the descriptor symbol while `dladdr` still returns success
  with the name at NULL — so a release build would report empty type names in
  silence — and that metadata in the value takes raylib's `Vector2` from 8 bytes
  to 16, moves `offsetof(y)` from 4 to 12, and **changes the register class**:
  `take_plain` receives its floats in `s0`/`s1`, `take_reflect` packed in `x1`.
  The compiler seat measured that a descriptor is emitted **per TU and only when
  the type is used as a container element** — a two-record program with no
  container emits zero user descriptors — so a value cannot reach one. **This
  overturns the 2026-09-06 `nm` finding** that the descriptor's own symbol is the
  type name `HeroDesc` does not carry: it is a link-time artifact, not a run-time
  fact.
- **Both seats re-ran panel 117's `HeroDesc` experiment and both reproduced it**,
  at three members and at one: exit 0, zero warnings under the project's own
  flags, **125 descriptors zero-filling in silence** (C11 6.7.9p21), then `SEGV`
  at address zero on the first read. `hero_desc_map.diff` is NULL, and the map is
  the case the walk exists for.
- **The historian's Zig reading corrects panel 117 and is not fatal to it.**
  `expectEqual` recurses through **struct fields** to a scalar leaf, which is what
  117 took from it; but on optionals it prints the whole payload, on slices it
  compares pointer and length rather than contents, and Zig ships a separate
  `expectEqualDeep` precisely because of that. *"Never renders an aggregate"* is
  false of Zig; *"recurses through struct fields to a scalar leaf"* is true, and
  the record should say the second.

## The resolution adopted, provisionally

**Robust, and it is neither the cheapest option nor a compromise between the
vetoes.** Five parts.

**1. (i) run-time reflection is REFUSED**, as a design.md Part 6 row, unanimous,
with two vetoes engaged — the FFI seat's on ABI breakage and the compiler seat's
on any `HeroDesc` member. **Its ground is the measured one and not the inherited
one**: a Heroes value cannot reach its own type, because a descriptor is emitted
per TU and only for a type used as a container element; putting the type in the
value changes `sizeof`, every `offsetof` and the register class of every call
across the C boundary, which is the marshalling design.md §1.11 refused when it
refused level 3; and the `HeroDesc` route zero-fills 125 descriptors with no
warning and reads NULL. **What would make this refusal wrong**: a natively
compiled language whose field reflection is emitted only for types a program asks
about, with a measured binary-size delta under ~2% on a self-hosting compiler —
Rust's RFC argued against *blanket* metadata and left that door open in its own
words. And the FFI seat's two-part condition, which it must be able to meet
together: nothing in the value, ever, and a short descriptor becoming a compile
error.

**2. (iii) user-defined tags are REFUSED**, as a design.md Part 6 row, unanimous.
**Its ground is inertness, not impossibility.** In Heroes a user-defined tag is
necessarily inert: macros and templates are refused (CLAUDE.md §6), there is no
compile-time execution, closures are refused (2026-09-08) so there is no
decorator, run-time reflection is refused above so there is no reader at run time,
and §10 forbids a second binary so there is no plugin. A general mechanism would
have made the six existing words cheaper to write and **impossible to check**:
`owned sqlite3_free` becomes a string the compiler stores, and the seat compiled
the proof that today it is not — `owned sqlite3_notafunction` gives
`error[unknown_freer]` with two notes naming the repair. *A tag nobody reads is a
comment that looks like a guarantee, which is the one thing an FFI must never
carry.* **What would make this refusal wrong**: name a reader — one consumer that
exists in this tree, reads a tag the user invented, and turns an unlisted one into
a compile error. Both compiling seats searched and found none.

**3. The Ruby row's stated reason is corrected in design.md**, because it is false
and Go falsifies it, and because a Part 6 row is held to the same standard as a
feature (CLAUDE.md §12). A refusal whose reason a reader can disprove in one
sentence is worth less than no refusal, since the next reader re-opens it — which
is what happened here, on 2026-09-06, when the author asked.

**4. Panel 117's sixth option is REFUSED, on the three measurements it itself
asked for.** They were owed precisely so that this could happen, and the record
did its job: the map leg names a leaf that is a function of insertion history, the
depth leg turns a thin message that is correct at depth 100 000 into `exit 134` at
depth 3700, and the premise that made the cliff dissolve — *the walk is `eq`'s
walk* — is false at `runtime/parts/array.c:185-190`, where the worklist has no
path. **The conservative variant the compiler seat named is recorded and not
adopted**: records and variants only, no recursion through `[T]` or `{K: V}`, ~120
of the 160 lines, no cliff and no order dependence. It is refused because it buys
nothing for an array, and the motivating case in the ergonomist's own experiment
is two `[i64]`; and because it buys nothing for the compiler's own ASTs, which are
`[T]`-recursive by construction. `tests/harness/suite_special.hero`'s aggregate
pin therefore **stays**, and it stays correct.

**And panel 117's spec clause is not false-by-standing**, which the warden asked
this sitting to declare one way or the other. *"…until this language renders one"*
is a conditional whose condition is unmet and still being worked toward, because
(ii) is re-sat below inside this same milestone. **It goes false the day (ii) is
refused too**, and on that day it owes a rewrite to a plain narrowing rather than
a deferred promise.

**5. (ii) compile-time derivation is NOT RULED TODAY, and is re-briefed and re-sat
as step 2 of this milestone.** This is the part that is neither cheap nor a
compromise, and the sitting states its reason without hedging: **the brief asked
the wrong question, and two seats answered the brief while three answered the
question.** Ruling either way on that split would write a Part 6 row on evidence
about display and call it a ruling about derivation.

The corrected question, for step 2:

> Can the compiler synthesise, per record type, a walk over that type's fields
> that a program directs at a **foreign notation** — the shape of Swift's
> compiler-synthesised `Codable` (2017) and Erlang's `record_info`, *"a pseudo
> function added during compilation"* with zero run-time metadata — rather than a
> rendering of Heroes' own construction call?

It carries into that sitting, and none of it is re-derived there: the FFI seat's
`"witdh"` measurement as the Part 11 effect the thesis asks for; the warden's
0-of-56 and the compiler seat's 0-of-31 as the proof that a construction-call
render is **not** the answer; the compiler seat's 350-450 lines across six modules
as the floor any mechanism must beat; the FFI seat's `partial` abort as a standing
constraint; the historian's convergence — Rust 2017, Swift 2017, Zig, Erlang,
C++26, none reversed — and its costed warning, that Haskell's `deriving Generic`
is **quadratic in constructor count** (GHC #5642), so the mechanism owes a curve
measured at 8, 16, 32 and 64 fields; and the historian's finding about what
refusing costs, which is that the ecosystem builds a code generator **outside** the
language, as ESA's ASN1SCC is for Ada and C in flight software — **a end-state
CLAUDE.md §10 forbids by name.**

**One spec gap is carried into it rather than left where it was found.** The
ergonomist, reading the document alone, could not determine what `to_str` takes:
§11 says it cannot fail and never says its domain, while §2 defines every `f"{e}"`
hole as *"writes that value as `to_str` does"*. So from the specification it
cannot be settled whether `f"{c.verbose}"` prints `true`. On a record the wrong
guess is a loud compile error; **on a `bool` it is silently different text**. That
gap exists today under every verdict and step 2's sitting settles it.

## What the conservative resolution would have been, so the author can choose it

Rule all three today: refuse (i), refuse (iii), and **refuse (ii) as well** on the
compiler seat's Principle 0 measurement — 0 of 31 renderers deleted, not needed for
self-hosting, 350-450 code lines across six modules. Then panel 117's clause goes
false-by-standing and owes its rewrite immediately, and the milestone closes in one
step instead of two.

**It was not adopted for two reasons, both measured.** The evidence that would
carry that refusal is evidence about a construction-call render, which three seats
never argued for; and the evidence against it — a one-character field-name typo
that compiles at exit 0 and ships the wrong key — is a claim about the thesis that
no seat has yet been asked to weigh against the 350-450 lines. **Refusing on the
wrong evidence and refusing on the right evidence produce the same row and are not
the same act**, and only one of them survives the next reader who asks.

## A defect found beside the sitting, and filed rather than folded in

The FFI seat's boundary experiment produced one finding that is not part of any
verdict, and the coordinator reproduced it on the frozen tree before filing:
`cstr` emits as `const char *` while `struct passwd.pw_name` is `char *`, so the

failed`** at exit 2, a message that accuses the compiler's own internals and names
no repair, where `spec § 13` promises a field that disagrees with the header is
*refused*. A control binding with a `u32` field compiles. Filed as defect **027**.

## Author's verdict

**Ratified as adopted, 2026-09-11**, the author's word given the same evening the
sitting closed: **yes to the two refusals, yes to the withdrawal, and go** (the
Italian original stands in this conversation's git history, CLAUDE.md §11).

**What the yes settles.** Run-time reflection and user-defined tags are refused,
and both design.md Part 6 rows stand with the grounds this sitting measured rather
than the ones the record was ready to write. The Ruby row's correction stands with
them, and so does the correction appended to panel 039. Panel 117's sixth option
is **withdrawn**, which reverses a ratification of 2026-09-07 — it was put as its
own item for exactly that reason, and the author took it. `suite_special.hero`'s
aggregate pin therefore stays, and the § 12 clause *until this language renders
one* stays honest, because its condition is still being worked toward.

**What the yes does NOT settle, and the author chose that too.** Compile-time
derivation is not ruled. The conservative alternative was on the item in full —
rule it today, refuse it on the 0-of-31 measurement, and close the milestone in
one step — and *go* took the other branch: the question is re-briefed and re-sat.
So the milestone stays open on one question, deliberately, and the row it will
eventually write rests on evidence about derivation rather than evidence about
display.
