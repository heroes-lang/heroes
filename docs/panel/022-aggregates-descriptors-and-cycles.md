# Panel 022 — aggregates, descriptors, and a claim about cycles

**Convened** 2026-08-05, before M5c's first line. **Trigger**: CLAUDE.md §4 —
architecture (the descriptor pass) and a proposal that claimed to overturn a frozen
spike. **Status**: `provisional — author ratification pending`.

One veto, and it is the most valuable finding in five panels: **the proposal's COW
was unsound, and nothing in this project could have seen it**. A judge compiled
`h = g` followed by `g.rows[0].cells[0] @ 7`, and `h` changed too — ASan clean, leak
counter zero, exit 0, a green harness on a program that violates the spec's own
sentence. A second judge then *built a reference cycle* out of the proposal's own
instruction ordering.

The proposal also claimed to contradict `tools/spike/04-variant.c`. It does not, and
two judges said so independently: the spike already used a by-value tagged union. The
real contradiction was somewhere else entirely, and it has a test asserting the old
behaviour.

---

## The proposal, verbatim

> M5c: records, variants, arrays and maps reach C. Six points, and the second one
> contradicts a spike.
>
> 1. **The descriptor pass generates C, not IR.** §4.20 says "per-type functions are
>    generated by the compiler, not written in the runtime", so `emit/descriptors.rs`
>    walks the reachable types and emits `h_T_copy` / `h_T_drop` / `h_T_eq` /
>    `h_T_hash` as plain C functions, plus one `static const HeroDesc` per type that
>    the runtime calls through.
> 2. **A record is a C struct by value; a variant is a tagged union by value.** This
>    contradicts `tools/spike/04-variant.c`, which gave a variant a heap block with a
>    refcount, and the contradiction is deliberate: §4.10 says "the array is the
>    language's only indirection".
> 3. **Structural `==` is a descriptor call.** `BinOp::Eq` on an aggregate becomes
>    `h_T_eq(&a, &b)`, generated field by field and case by case.
> 4. **COW is one runtime call at each mutation primitive.** `push`, `xs[i] @ v` and a
>    map insert all begin with `hero_array_unshare(&xs)`. `Op::CowCheck` joins the IR
>    here, and the ownership pass inserts it before every mutation of a counted place.
> 5. **Cycles are impossible, so reference counting is complete.** A store copies
>    rather than aliases, so writing a parent into its own child stores a *copy*, and
>    the recursion terminates because the copy is finite.
> 6. **The map's iteration order is insertion order with a fixed seed** (panel 006):
>    a dense entries array plus a sparse index. `HeroDesc` gains `hash`.

## Where the judges converged, and on what

**Three judges independently rejected the same sentence of the proposal.** Point 2's
"this contradicts `tools/spike/04-variant.c`" is false: line 137 of that file is
already `struct { tag; union { … } }`, and the only refcounted header in it is the
array's. The engineer found it by reading, the ffi-pragmatist by compiling.
**Resolution: the paragraph is rewritten to say point 2 *confirms* the spike**, and
what the spike still decides is stated — the container layout, the descriptor ABI and
the ASan method. It never decided a variant's boxing, because it never boxed one.

**But the real contradiction was found underneath it.** Spike 04's `h_Expr_copy`
**deep**-copies through `hero_array_deep_copy`; point 2's copy is shallow-plus-incref.
Both cannot occupy `HeroDesc.copy`. Under shallow+incref the spike's own `main` prints
`1 1 -42`, and `tools/spike/04-variant.expected` says `1 0 -42` — with a test
asserting it, added at M5a for exactly this reason. **The frozen ABI reference and the
generated code were about to diverge with nothing noticing**, which is the failure the
M5a test's own doc comment describes. Resolution: `HeroDesc.copy` is
**shallow + incref** (COW is what makes deep copying unnecessary), and spike 04 is
updated with its expectation in the same commit.

**And the veto is a measured aliasing leak.** `h = g` then
`g.rows[0].cells[0] @ 7`, with one unshare at the mutation primitive: `h` changes too.
It is *necessarily* wrong rather than accidentally — unsharing level 1 copies its
elements, whose `copy` increfs level 2, so level 2 is shared exactly when level 1 was
copied. Nothing in this project catches it: the leak counter reads 0, ASan is silent,
and no `run/` golden reads a second name after a nested mutation. That is spec line 58
("No aliasing exists anywhere") violated on a green harness.

**Then the ffi-pragmatist built a cycle**, which the proposal called impossible. Not
from value semantics failing, but from the proposal's own point 4: making
`Op::CowCheck` an IR instruction "inserted before every mutation" leaves *before the
argument is materialised* expressible, and in that order the unshare is a no-op and
`xs` ends up reaching itself. Three blocks, ASan silent, only the block counter
catching it. The fix is not a check — it is to make the bad order **inexpressible**:
COW stays inside the runtime primitive, and C's own rule that all arguments exist
before the callee's first statement does the rest.

## Resolution — provisional, author ratification pending

### R1 · Point 2 **confirms** spike 04, and `HeroDesc.copy` is shallow

A record is a C struct by value; a variant is a tagged union by value; `[T]` and
`{K: V}` are the only reference-counted heap things besides `str`. Measured: **16
bytes and 2 heap blocks** for the appendix's five-node tree, against 8+24-per-node and
7 blocks boxed, and 58 generated lines against 97. The type completes only because
`[T]` is a pointer — `struct h_Expr` containing `h_Expr` directly is
`error: field has incomplete type`, isolated three ways.

`HeroDesc.copy` is **shallow plus incref**, and spike 04 is updated in the same commit
with its `.expected` changing `1 0 -42` → `1 1 -42`. `HERO_RUNTIME_ABI` → **3**, and
`HeroDesc`/`HeroArrayHeader` move out of the spike and into the shipped header (the
spike gets 10 errors otherwise, measured, and the M5a test that would have caught it
goes red on purpose).

Four requirements the ffi-pragmatist compiled into existence:

- **No `memcmp`, ever.** `record Flag { n: int, on: bool }` has **7 padding bytes**:
  fieldwise `eq` says equal, `memcmp` says different, and a byte-wise `hash` gives two
  `==`-equal records different hashes. No compile error, no sanitiser report — a
  silent wrong answer generator. `h_T_eq` and `h_T_hash` walk fields, always.
- **`hash` for every type, never NULL.** A generated call through a null `hash` is
  `AddressSanitizer: DEADLYSIGNAL, SEGV on unknown address 0x0, pc 0x0` with **no type
  name and no source line** — the worst diagnostic in the project. `hash` walks the
  same fields `eq` already walks, so the marginal cost is a few lines per type.
  (Go's rule — emit `hash` only for map-key types — is cheaper and reintroduces the
  null; rejected on that ground.)
- **A payload-free case is omitted from the union.** C11 has no empty struct;
  `union { …; struct { } plus; }` is `warning: empty struct is a GNU extension` under
  `-pedantic`, and `Op::Payload` must never target one.
- **`HERO_ALIGN_OK(T)`** — `_Static_assert(_Alignof(T) <= 8)` emitted per generated
  type, because the map's entry stride assumes it and an assumption in a comment is
  not an assumption.

The reachable set is a **worklist, not a walk over the interned arena**: an unused
descriptor is `-Wunused-const-variable` under this project's own flag set, and
`Checked::types` holds types interned only inside `test` blocks, which the emitter
skips. Descriptor names need the `_<typehash>` `mangle.rs` says does not exist yet —
`Ty::Case`, `Ty::Array(Array(int))` and `Ty::Fallible` have no declared name.

### R2 · COW is per-step, with write-back — the engineer's veto

**One unshare per array or map step of the place path**, each writing back the new
block pointer at its level, and the mutation primitives take
`HeroArrayHeader **` / `HeroMapHeader **` rather than returning the new pointer — a
returning signature lets a caller keep the stale block, and it is what makes the bad
order writable.

**The order is part of the rule**: the stored value is increfed *before* the outermost
unshare. Measured both ways on `n.children[0] @ n` — incref-first leaks nothing,
unshare-first leaks one block and, in the hoisted form, builds a cycle.

`xs[i] @ v` needs two things `push` does not: it must `drop` the element it
overwrites, and it must **bounds-check before the unshare**, or a shared array is
deep-copied only to abort. `hero_map_unshare` differs in one way that matters: the
copy must **rebuild the sparse index**, because entry ordinals live in it.

**`Op::CowCheck` does not return to the IR.** That is the change the ffi-pragmatist's
cycle earned: as an instruction it can be hoisted above the argument, and in that
order the unshare is a no-op. Inside the runtime primitive, C's own argument-evaluation
rule makes the bad order inexpressible — which is better than a check, because a check
is something that can be forgotten.

Three obligations from the veto, all adopted: a `Phase::Owned` invariant that every
array or map step of a mutated place is unshared before the write, **with a test that
makes it fire** (CLAUDE.md §9); a `run/` case asserting `print(h.rows[0].cells[0])` is
`0`; and a `run/` case asserting `n.children[0] @ n` leaves `hero_runtime_live() == 0`.
The historian's prediction — that the golden set would contain no case where the stored
value aliases the mutated container — is answered by putting three there.

### R3 · Point 5 is right, and its published reason is not the proposal's

The claim survives, and the historian found it in print: **Racordon, Shabalin, Zheng,
Abrahams and Saeta, "Native Implementation of Mutable Value Semantics"** (ICOOOLPS
'21, arXiv 2106.12678) contains points 1, 2, 4 and 5 of this proposal in four pages —
per-type synthesized copy and destroy functions, refcounted array blocks, a
mutation-time counter check that duplicates only above one, and **no cycle collector
and no discussion of needing one**. Swift has shipped twelve years the same way:
reference counting applies to *classes*, and `weak`/`unowned` exist for them alone.
Nim's ORC is gated on `canFormAcycle` and its documented motivating case is **closures**
— which Heroes does not have.

But **the reason in the paper is not the reason in the proposal.** The guarantee is
*"references cannot be stored in variables or object fields, hence all values form
disjoint topological trees"* — a statement about what a field may hold, not about
copying terminating. Restated that way it becomes checkable, and it exposes two
exceptions worth naming: §4.19's `ptr`/`cstr` sits outside the guarantee, and a stored
closure would end it silently. The paper is also **stricter** than Heroes: it forbids
recursive type definitions outright, where Heroes carries finiteness through `[T]`. That
departure is recorded rather than glossed.

`docs/ROADMAP.md` currently asserts "reference counting **leaks cycles**", which
contradicts design.md §4.10 gift 2. The queued cycle question closes by citation, and
the ROADMAP line is corrected.

### R4 · The map's mutation half is **struck from M5c** — the warden's veto

`hero_map_unshare` and the map's `hash`/entries machinery have **zero reachable call
sites**: the spec's inventory has `has`, `len` and `m[k]`, `push` is array-only, and
`for x in m` is `not_iterable` today with a message that says "walks an array". That is
~180 lines of C no program can reach and no golden can make fire — the same reason
`cow_check` was struck at M5b, applied to the same milestone's other half.

So at M5c a map is **read-only**: a literal, `m[k]`, `has`, `len`, and structural `==`.
The insertion-order *sentence* is re-deferred to the milestone that lands `for k in m`,
and re-priced honestly: **+12 measured** for order-plus-what-iteration-yields, not the
+6 that prices only half of it.

**The closure-list question is put on the record rather than answered**: the map cannot
be added to, so the self-hosted compiler cannot have a symbol table built by insertion.
The bootstrap has 14 `.insert(` sites; `resolve/scope.rs` already ships the
association-vector alternative. Funding `set(m, k, v)` costs **+29 measured** with
`for k in m`; deleting `{K: V}` from the language recovers **−57**. The warden's line
stands: 57 tokens for a container that cannot hold a symbol table is the only
indefensible option, and one of the two must be chosen by M6's closure audit.

### R5 · Three spec sentences land, at +24 measured

| sentence | measured |
|---|---|
| map `==` ignores insertion order | **+7** |
| `to_int` truncates; out of range aborts | **+10** |
| `m[k]`'s error code is `missing_key` | **+7** |

2196 → **2225** binding, headroom 775 — and the difference between that and the +24 the
three separate measurements sum to is worth recording, because it is the third time
this project has met it. **Measured deltas do not compose**: panel 018 found deltas
measured on spec v0 did not transfer to v1, panel 020 found panel 006's "+15 est" text
measuring +39, and here three sentences priced at +7, +10 and +7 land together at +29.
The number that counts is the one measured on the file that ships, which is why the
rule says measured and not estimated. Still comfortably inside the warden's own
combined candidate (2242 for the full package, 2231 without the `.is_err()` row).

Panel 012's rule is satisfied by the second branch rather than the first: each sentence
carries a falsifiable prediction, and the named reserve is design.md §4.6's own
nomination — the `.is_err()` row, **−11 measured**, which §4.6 calls the "weakest
member, first to cut". It is not spent here.

Map equality's silence is the one the warden ranked first and it is worth the
paragraph: with insertion-ordered maps, `h_T_eq` written the cheapest way — a pairwise
walk of the dense entries array — makes `{"a":1,"b":2}` and `{"b":2,"a":1}` unequal.
The ergonomist answered `true` from the spec, at 80% confidence, with nothing to read.

### R6 · The gate note says it is exhaustive

One word, and the ergonomist earned it by reasoning out loud: reading `if, while,
functions`, its first instinct was *"`for` is probably fine too, it's just sugar for
`while`"*. Absence-reading is what models do badly, so the note states that the list
**is** exhaustive — converting four inferences into one read at no cost.

The ergonomist's reserved veto does **not** fire: `push` in this compiler is already
pure (`_ = xs.push(3)` type-checks and returns `[int]`), so no mutation happens through
an `=`-bound name and the `@` marker keeps its meaning. Recorded because the veto was
conditional on a fact, and the fact was checkable.

### What a veto would have compelled

The engineer's, unlifted: a language whose own spec sentence ("No aliasing exists
anywhere") is false for any nested mutation, with every instrument in the project
reporting success — and the self-hosted compiler mutating shared copies of its own
instruction lists at M8, since `own.rs:110` is itself a two-step place path.

The warden's, unlifted: ~180 lines of unreachable runtime, an untestable verifier
invariant, and a spec sentence advertising a form the compiler rejects.

## Watch list

- **The map cannot be added to.** Fund `set` (+29) or delete `{K: V}` (−57), by M6's
  closure audit. Queued since M4, now priced.
- **`T?` is 40 bytes for every `T`**, because `Failure` is two `str`s. Every `m[k]`
  returns through memory (`str xzr,[x8,#32]` rather than `x0/x1`). **design.md does not
  fix `T?`'s C representation anywhere** — M5c states it rather than inheriting it.
  Rust polices the same largest-case tax with two lints (`large_enum_variant`,
  `result_large_err`, whose default threshold is 128 bytes).
- **No infinite-size rule exists.** `record Node { child: Node }` reaches clang as
  `error: field has incomplete type` — wart 13 happening to a program error. It is a
  new diagnostic class, so it needs its own panel trigger.
- **`for x in xs` over a counted element type** is undecided: borrowing is a
  use-after-free if the body mutates `xs`, +1 per element is the safe answer and costs
  a descriptor copy per iteration.
- **A record map key** needs `h_T_hash` recursing into `str` *bytes*, not pointers, or
  `m[k]` misses after a copy.
- **`BinOp::Eq` carries no `TyId`** — `ir/inst.rs`'s comment says it does. Fix the
  comment before M5c cites it.
- **Monomorphisation needs `Types` mutable through M6**, or `[T]`'s instantiations have
  no descriptor. `Checked` is immutable at `emit()` today.
- **A borrowed `cstr` held across `xs[i] @ v`** is a use-after-free at the FFI boundary.
  ASan catches it, so it is a §4.19 binding-vocabulary item rather than a blocker.
- **A fixed hash seed is a collision-DoS surface**, acceptable only because performance
  and security are non-goals — said out loud once, here.
- **`resolve/exprs.rs` walks a `BTreeMap` into diagnostic text with no `// ORDER:`
  marker**, which §4.9 requires. There are zero such markers in the tree.
- **C++11 N2668 banned COW `basic_string`** over escaping interior pointers plus
  concurrency. Out of scope while `str` is immutable and §5 forbids references in
  structs; back in scope the day threads or `ptr`-into-array appear.
