Today a function with an `@` or `lent` parameter is no value (`mutable_parameter_as_value`, `lent_parameter_as_value`), a function type cannot write either mark (`expected_type`, `expected_function_type_params_close`), and Rebel's `web` says so as the reason every program dispatches its routes by hand (`web.hero:19-23`).

    **Default today:** spec § 9 line 321, *"Top-level functions are values, but not one with an `@` or `lent` parameter"*. Measured beside it by the sitting: `build --permissive` of an extra `@` through a value exits 2 (`x1`); a record holding a handler of itself exits 2 (`base_self_field`); an `extern` taking a callback, called through a value, hands C the function without its thunk and a correct program aborts with a false message; on Linux a program reaching Rebel's `math` is refused `ffi_unpaired_release`; each drafted as a defect.

    **Recommendation:** ratify R1 to R12. R1 (built): `TypeArg = "@" [ ident ":" ] Type | [ ident ":" ] Type [ "lent" ]`; the marks a run on the existing type case, empty where every position is by value, so a mark-free program keeps its bytes (248 of 249 marked-type `run` goldens, 248 of 248 sampled mode-free, 55 of 55 examples, the compiler's own 40,972,079 bytes); every function of the program a value; a call through a value writes `@` as its type does. R2 (built): the checker asks the rule of the left of `@` and the two-`@` rule of every call through a value, since the resolver set them aside (`w5`, an `@` on a by-value parameter, aborted the heap at exit 134 without it; `m06` handed one place to two `@`), defect 431's nine messages kept. R3: `lent` fits where `@` is asked (built), and, unbuilt, a table literal's, an `if`'s and a `match`'s function values take the type each fits in any order (today a literal takes its first element's, for names at the base and for marks under the route), the names' fit stated the compiler's way round, and `x @ x` counted as no write. R4 (unbuilt): a mark in an `extern` callback's type is meaningful, C's `T *` for `@` and pointer to const for `lent`, and C reaches a marked function only through a thunk that checks every handle a slot reaches, refuses a null slot and overlapping places naming the callback, writes `const` for a `lent` slot, hands a twin where `const` differs, and is reached through an `extern`'s value too; until then the checker refuses the mark (the ffi-pragmatist's veto lifting on it; the built route, measured on three platforms, let C write freed memory at exit 0). R5 (unbuilt): an `extern` function with `@` or a `lent` record is no value, in true words. R6 (built): `spawn` refuses a marked function, `thread_body`.     ## Prior art

    `docs/panel/261-a-function-type-carries-its-parameters-marks-lent-fits-where-at-is-asked-and-a-callback-c-calls-is-checked-at-its-thunk.md`, the historian's report `docs/panel/261-reports/historian.md`; read 2026-11-26 by the historian, every link to be re-read by the session that files this draft.
    - **Reached first by Swift**: [The Swift Programming Language, Types](https://raw.githubusercontent.com/swiftlang/swift-book/main/TSPL.docc/ReferenceManual/Types.md): "To specify an in-out parameter, prefix the parameter type with the `inout` keyword."
    - **Reached first by Oberon-2**: [The Programming Language Oberon-2](https://cseweb.ucsd.edu/classes/fa00/cse131a/oberon2.htm): two formal parameter lists match where "parameters at corresponding positions are both either value or variable parameters".
    - **Reached first by Modula-3**: [the language definition, procedures](https://softwarepreservation.computerhistory.org/modula3/archive/DEC_SRC/release-3.6-html/m3defn/html/procs.html): covering needs "They have the same number of parameters, and corresponding parameters have the same type and mode."
    - **Reached first by Ada**: [Ada 2012 Reference Manual, 6.3.1](https://www.adaic.org/resources/add_content/standards/12rm/html/RM-6-3-1.html): mode conformance, "corresponding parameters have identical modes".
    - **Reached first by C#**: [ref readonly parameters, the C# 12 proposal](https://raw.githubusercontent.com/dotnet/csharplang/main/proposals/csharp-12.0/ref-readonly-parameters.md): "`in` parameter of the target method is allowed to match `ref readonly` or, gated on LangVersion, `ref` parameter of the delegate.", and for method group conversions "these modifiers are considered compatible (but any allowed conversion between different modifiers results in a warning)".
    - **Reached first by Hylo**: [Functions and methods](https://docs.hylo-lang.org/language-tour/functions-and-methods): "arguments to `inout` parameters must be mutable and marked with an ampersand (`&`) at the call site", and `offset_inout(&v, by: v)` is "error: overlapping `inout` access to `v`;".
    - **Reached first by ISO 7185 Pascal**: [ISO 7185, standardpascal.org's copy](https://www.standardpascal.org/iso7185.html): procedural parameters were changed "to require the use of a procedure or function heading", and "this change was introduced to overcome a language insecurity."
