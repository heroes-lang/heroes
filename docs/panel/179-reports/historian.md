# Panel 179, the historian's report

`precedents`

A. Self-checks that live inside the formatter's binary and run on the SAME input the user gave (the proposal's fixpoint, tree and comment checks all have this ancestry)

1. Prettier `--debug-check`. Flag on the formatter. Added in 0.17.0 by PR #627 (vjeux, merged 2017-02-07), whose whole description is "This let's you run `pp(x) === pp(pp(x))` across an entire codebase quickly" (idempotence only). PR #1337 (vjeux, merged 2017-04-21) added AST verification. Today's `src/cli/format.js` throws `prettier(input) !== prettier(prettier(input))` and `ast(input) !== ast(prettier(input))`, the latter via `__debug.parse` with `massage: true`. Still in the current CLI docs, with "`--write` cannot be used with `--debug-check`". What happened: survived nine years as a debug flag; issue #2983 records it reporting only the first diff. Note the candidate PR #510 of the same name was closed unmerged on 2017-01-30. verified. [PR #627](https://github.com/prettier/prettier/pull/627), [PR #1337](https://github.com/prettier/prettier/pull/1337), [format.js](https://raw.githubusercontent.com/prettier/prettier/main/src/cli/format.js), [CLI docs](https://prettier.io/docs/cli), [PR #510](https://github.com/prettier/prettier/pull/510)

2. Black `--safe` (default) / `--fast`. The 18.3a1 README says "`--fast / --safe` If --fast given, skip temporary sanity checks" and "as a temporary safety measure, Black will check that the reformatted code still produces a valid AST that is equivalent to the original". Today's `src/black/__init__.py` calls `check_stability_and_equivalence` when `not fast`; `assert_equivalent` raises "INTERNAL ERROR: ... produced code that is not equivalent to the source", `assert_stable` raises "INTERNAL ERROR: ... produced different code on the second pass of the formatter". What happened: the "temporary" check is default-on eight years later and keeps firing (issues #950, #1438, #1629, #1663, #1844, #2469). `--check` added 18.3a1. verified (18.3a0 itself unverified: its PyPI page did not load). [18.3a1 README](https://raw.githubusercontent.com/psf/black/18.3a1/README.md), [`__init__.py`](https://raw.githubusercontent.com/psf/black/main/src/black/__init__.py), [#1629](https://github.com/psf/black/issues/1629), [#2469](https://github.com/psf/black/issues/2469)

3. OCamlformat. Runs to a fixpoint INSIDE the binary: `print_check` re-parses and re-formats until output equals previous, erroring "formatting did not stabilize after %i iterations."; `--max-iters` "Fail if output of formatting does not stabilize within N iterations ... default 10"; also "ast changed" and "comment changed"; `--comment-check` "Unsafe to turn off"; `--check` for CI. The AST check existed by 2017-10-21 (issue #21, "Internal Error: formatting changed ast"). What happened: meta-issue #2457 tracks opam packages still failing to stabilize in 10 iterations; the 0.20.0 changelog (2021-12-06) added the opt-out for comment checks. verified. [Translation_unit.ml](https://raw.githubusercontent.com/ocaml-ppx/ocamlformat/main/lib/Translation_unit.ml), [manpage](https://ocaml.org/p/ocamlformat/latest/manpage_ocamlformat.html), [issue #21](https://github.com/ocaml-ppx/ocamlformat/issues/21), [issue #2457](https://github.com/ocaml-ppx/ocamlformat/issues/2457), [CHANGES](https://raw.githubusercontent.com/ocaml-ppx/ocamlformat/main/CHANGES.md)

Ormolu. `--check-idempotence` "Fail if formatting is not idempotent"; `--unsafe` "Do formatting faster but without automatic detection of defects" (AST diff default-on, exit code 5 "AST of original and formatted code differs"); `--mode check`. 0.1.0.0 (Hackage upload 2020-05-25) renamed `--check-idempotency` to `--check-idempotence`. verified. [Main.hs](https://raw.githubusercontent.com/tweag/ormolu/master/app/Main.hs), [README](https://raw.githubusercontent.com/tweag/ormolu/master/README.md), [CHANGELOG](https://raw.githubusercontent.com/tweag/ormolu/master/CHANGELOG.md), [Hackage](https://hackage.haskell.org/package/ormolu-0.1.0.0)

D. Generators of NEW inputs, and where they live (the proposal's departure)

14. Black: Hypothesis plus Hypothesmith, PR #1566 (Zac-HD, merged 2020-08-21; changelog 20.8b0), a separate workflow `fuzz.yml`, not in the binary; the PR's rationale: "There's a long history of this working really well for compilers (e.g. CSmith), and for formatting tools like prettier." Found real bugs (issue #970, `"pass #\r#\n"`). verified. [PR #1566](https://github.com/psf/black/pull/1566), [#970](https://github.com/psf/black/issues/970)

15. clang-format-fuzzer: "A generic fuzzer that runs clang-format on C++ text fragments", a separate binary target built with `-DLLVM_USE_SANITIZE_COVERAGE=On`. verified. [FuzzingLLVM](https://llvm.org/docs/FuzzingLLVM.html)

16. Toolchains that put the mutation engine in the one binary: Go 1.18 (2022-03-15), "first major language with fuzzing fully integrated into its standard toolchain", `go test -fuzz`; Zig 0.14.0 (2025-03-05) "ships with an integrated fuzzer. It is alpha quality", `zig build test --fuzz`, and 0.15.1: "we did not find the time to actively push forward on it during this release cycle". Swift links libFuzzer via `-sanitize=fuzzer` (PR #9450, 2017-08-08). Rust's cargo-fuzz is a separate subcommand needing nightly. verified. [go1.18 blog](https://go.dev/blog/go1.18), [zig 0.14.0](https://ziglang.org/download/0.14.0/release-notes.html), [zig 0.15.1](https://ziglang.org/download/0.15.1/release-notes.html), [swift #9450](https://github.com/apple/swift/pull/9450), [cargo-fuzz](https://github.com/rust-fuzz/cargo-fuzz)

17. The technique itself: Csmith (PLDI 2011) reported "more than 325 previously unknown bugs"; EMI (PLDI 2014) mutates a program by inserting or removing code and checks invariance, 147 confirmed GCC/LLVM bugs in eleven months. Both external tools. verified. [Csmith](https://www.flux.utah.edu/paper/yang-pldi11), [EMI](https://web.cs.ucdavis.edu/~su/emi-project/)

18. Negative claim, as a question: I searched the CLI references of Prettier, Black, rustfmt, gofmt, clang-format, zig fmt, deno fmt, ocamlformat, ormolu and swift-format, and one web search for a formatter flag that generates mutated inputs; none names such a flag. The one hit, pistachio (a Go SQL formatter, PR #655, 2026-09-20), runs `FuzzFormat` through `go test -fuzz`, not through the formatter. Is there a formatter I did not name? [pistachio #655](https://github.com/winebarrel/pistachio/pull/655)

`argument`

Every check the probe runs on one file has a decade of in-binary precedent, and the pattern is uniform: default-on, with the opt-out named unsafe (Black `--fast`, Ormolu `--unsafe`, ocamlformat `--no-comment-check`), and it keeps paying (Black's INTERNAL ERROR issues, ocamlformat #2457). The generator is the departure: no formatter found ships one; generators live beside the formatter (Black, clang-format) or under the toolchain's own test verb (Go, Zig). Precedent thus reads the shape question as: same-input checks are flags on `fmt`; a family-of-inputs run that emits a failing variant is a verb. Zig is the caution: an in-toolchain fuzzer stalled one release after shipping. *Heroes of code* was a route, not evidence, here.

`condition`

A formatter in wide use whose CLI reference documents a flag or verb generating deformed variants of the user's file would overturn item 18 and the prediction; the instrument is the ten CLI pages linked above. A rustfmt changelog line or PR dating the `--write-mode` removal would close item 5's gap. Evidence that Prettier's massaged AST or Ormolu's diff compares plain comments would make ocamlformat less alone in item 12. Scorable prediction: none of those ten pages will list such a generator within the next twelve months, and Black's `--safe` will still be default-on.
