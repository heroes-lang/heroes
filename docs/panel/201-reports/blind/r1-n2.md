# report

## verdict

Refused, on lines 11 and 12.

Both lines pass the generic function `ident` as a value: to `app`'s parameter `f` on line 11, and to `map`'s parameter `f` on line 12. Passing `ident` without calling it means `ident`'s own type parameter `A` has to be fixed. It gets no arguments here, because nothing calls it at that point. The only context is a generic function's parameter, and the specification says such a parameter "asks for none". So `ident`'s `A` has no source and the checker refuses the program. The specification's own example of passing a function to a generic, `xs.map(double)`, works only because `double` has a concrete signature that supplies the types.

Smallest fix: make `ident` non-generic, at the one type this program uses (`i64`). Then `app`'s `A` and `map`'s `A` and `B` all come from `ident`'s signature. With that change the program is accepted and prints:

```
20
3
```

## program

```
# Apply a function to a value, and the identity.

function ident(x: i64) -> i64
    return x

function app<A>(f: (function(A) -> A), x: A) -> A
    return f(x)

function main()
    ns = [1, 2, 3]
    print(app(f: ident, x: 20).to_str())
    print(ns.map(ident).len().to_str())
```

The only change is line 3: `function ident<A>(x: A) -> A` becomes `function ident(x: i64) -> i64`. On line 11, `app`'s `A` is `i64`, taken from `ident`'s signature. The literal `20` is `i64` either way, because a generic function's parameter asks for no type. `app` returns 20, and `to_str` gives `"20"`. On line 12, `ns` is `[i64]` and `map`'s `A` and `B` are both `i64`. The result has 3 elements, so `len` is 3 and the line prints `3`.

## choice_points

1. **Does the rule "a call that says neither is an error" apply to a generic function passed as a value?** Passing `ident` is a reference, not a call. I read the rule as covering every use of a type parameter, so `ident`'s `A` must come from arguments or from context. Here there are no arguments, and the context is a generic function's parameter, which "asks for none". Other reading: the checker unifies `ident`'s type with `(function(A) -> A)`, where `A` is already `i64` from `x: 20`. On line 12 it would unify with `(function(i64) -> B)`, with `A` taken from `ns`. Under that reading the program is accepted unchanged and prints `20` then `3`.
2. **How to fix it.** I made `ident` concrete at `i64`. The alternative was to add a separate concrete function and use it on both lines. That would leave the generic `ident` unused, and whether an unused top-level function is an error is not stated (the specification only mentions bindings and parameters). The alternative is also a larger change. Either fix prints the same output.
3. **The return type of `len`.** It is not stated. I assume an integer type. `to_str` accepts any number, so the output `3` is the same whatever the type.
4. **Naming a function `ident`.** `ident` is a grammar metavariable, not a keyword, so I treat it as an ordinary name. Treating it as reserved would refuse line 3 as well.
