- Line 11, `app(f: ident, x: 20)`: `ident` is a generic function used as a value, and it is handed to `app`'s parameter `f: (function(A) -> A)`. That parameter is generic because its type mentions `app`'s type parameter `A`. The specification makes this an error.

# program

```
# Apply a function to a value, and the identity.

function ident(x: i64) -> i64
    return x

function app<A>(f: (function(A) -> A), x: A) -> A
    return f(x)

function main()
    ns = [1, 2, 3]
    print(app(f: ident, x: 20).to_str())
    print(ns.map(ident).len().to_str())
```

With `ident` at `(function(i64) -> i64)`:

- On line 11, `A` is `i64`, taken from `f`, and `20` is an `i64`. The call returns 20, so the line prints `20`.
- On line 12, `ns` is `[i64]`. `map` takes `A = i64` and `B = i64` from `ident`'s signature, the same way `xs.map(double)` does in the spec. The result has 3 elements, so the line prints `3`.

# choice_points

- **Which fix.** I made `ident` itself non-generic (`i64`). Two alternatives:
  - Keep the generic `ident` and add a separate non-generic wrapper such as `function ident_i64(x: i64) -> i64` used on lines 11 and 12. That is accepted and prints the same output, but it is a larger change.
  - Pin `ident`'s type through a typed local such as `f: (function(i64) -> i64) = ident`. The specification lists only "a non-generic parameter, a record field or a declared return" as sources, and a local annotation is not among them, so I would not rely on it.
- **Whether lines 11 and 12 are two refusals or one.** The rule applies to each call independently, so I report both lines. A checker that stops at the first error would name only line 11. The fix covers both either way.
- **Return type of `len`.** The specification does not state it. I assumed it is a number (`i64`) and therefore accepted by `to_str`. Any numeric type gives the same output.
- **Unused generic function.** This does not arise in my fix, because `ident` stays used. With the wrapper alternative, the generic `ident` would remain unused. The specification refuses only unused bindings and parameters, not unused functions, so that alternative would still be accepted.
