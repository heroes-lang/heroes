```
# Points and rectangles.

record Point
    x: f64
    y: f64

record Rect
    corner: Point
    width: f64
    height: f64

function dist2(a: Point, b: Point) -> f64
    dx = a.x - b.x
    dy = a.y - b.y
    return dx * dx + dy * dy

function area(r: Rect) -> f64
    return r.width * r.height
```

Diagnosis: `main.hero` calls `geom.area(r: r)`, but `geom.hero` declares no `area`, so the qualified name does not resolve. Everything else in `main.hero` checks out against the spec. The record construction names every field (section 9). The float literals take `f64` from the fields (section 2). `to_str` gives a `str` that `print` takes (section 11). `main` takes nothing and produces nothing (section 1). The fix is to add `area` to `geom`. Its signature is fixed by the call: one parameter named `r` of type `Rect`, returning a number that `to_str` renders. It returns `width * height`, so the program prints `12.0`.

# choice_points

1. **Where `area` lives.** I put it in `geom.hero`, because the call is qualified as `geom.area`. The alternative was to define `area` in `main.hero` and change the call to `area(r: r)`. That builds too and prints the same thing, but it edits the caller instead of supplying what the caller names, and it puts rectangle geometry outside the geometry module.
2. **Return type of `area`.** I chose `f64` to match the fields and `dist2`. Returning another type, such as `i64` through `to_i64`, would need a conversion that can fail (section 11, `to_i64` on a float truncates). It would also print `12` instead of `12.0` and lose fractional areas.
3. **Parameter name.** The spec does not force a named argument for a single parameter (section 9 makes names mandatory only when two parameters share a type). However, the call writes `r:`, so the parameter must be called `r` for the name to match. Any other name would make the call's argument label name a parameter that does not exist.
4. **Meaning of area.** I used `width * height` with no `abs`. A version taking the absolute value would give the same result for this input but differ for negative widths or heights. Nothing in the program suggests that negative dimensions are meant.
5. **Leaving `main.hero` alone.** `print` takes an `f64` directly (section 11), so `.to_str()` is redundant but legal. I kept it, since changing it is not needed. Removing it would print the same `12.0`.
6. **Doc comment.** I added no comment above `area`, matching `dist2`, which has none. Adding one would only document it (section 1).
