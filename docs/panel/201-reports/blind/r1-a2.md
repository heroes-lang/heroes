# Apply a function to a value, and the identity.

function ident<A>(x: A) -> A

function app<A>(f: (function(A) -> A), x: A) -> A

# choice_points

1. **A generic top-level function used as a value.** The spec says "Top-level functions are values" and does not exclude generic ones. It also says a type parameter takes its type "from the type the context asks for". I read that as instantiating `ident`'s `A` from the function type the parameter expects. The other reading is that only non-generic functions are values. Under it, lines 11 and 12 are refused. The smallest fix would then be a non-generic `function ident_i64(x: i64) -> i64` used in both places, and the output would be the same.
2. **Inferring `B` in `ns.map(ident)`.** `map`'s `A` comes from `ns` (`i64`). `B` has to come from `ident`'s result once `ident` is instantiated at `i64`. I read that as allowed, because the spec's own example `xs.map(double)` "takes both from `double`'s signature". The other reading is that a generic function's signature does not fix `B`. Under it, line 12 is "a call that says neither", which is an error. The fix would be a non-generic identity on `i64`, or binding the result with a type annotation, `ys: [i64] = ns.map(ident)`.
3. **The literal `20` in `app(f: ident, x: 20)`.** The context asks for `A`, which is not yet fixed, so I took the fallback "otherwise `i64`". If the literal could not settle `A`, the call would say neither and be refused. That reading seems unlikely given the fallback rule.
4. **Named arguments where no two parameters share a type.** `f` and `x` have different types, so names are not mandatory. The `Arg` production allows them anyway, so I took `f:` and `x:` as permitted. If names were forbidden there, line 11 would be refused, and the fix is `app(ident, 20)`.
5. **A function named `ident`.** `ident` is a metasymbol in the grammar, not a quoted keyword, so I took it as an ordinary name. If it were reserved, lines 3, 11 and 12 would be refused, and renaming it (for example to `identity`) fixes them.
6. **Parameter `x` in both `ident` and `app`.** These are separate function scopes, so I did not count this as shadowing.
