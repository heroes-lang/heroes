```
# Points and rectangles.

record Point
    x: f64
    y: f64

record Rect
    corner: Point
    width: f64
    height: f64

function dist2(a: Point, b: Point) -> f64
    dx = a.x - b.x
    dy = a.y - b.y
    return dx * dx + dy * dy

function area(r: Rect) -> f64
    return r.width * r.height
```

# choice_points

- **Where the missing function goes.** The build fails because `main.hero` calls `geom.area`, and `geom.hero` declares no `area`. The call is qualified with `geom.`, so the function has to live in `geom.hero` (section 1). I added it there and left `main.hero` alone. The alternative was to compute `r.width * r.height` inline in `main` and drop the call. That also builds and prints the same thing, but it ignores what the call site plainly asks for.
- **Signature of `area`.** The call names its argument `r:`, so I named the parameter `r`. The value is a `Rect`, and the result goes to `to_str`, so the parameter type is `Rect` and the return type is `f64`. The spec allows a named argument even where naming is not mandatory (section 9, `Arg = [ ident ":" ] ...`). It does not say outright that the name has to match the parameter, but matching is the only safe reading. A different parameter name would most likely be refused at the call. Returning another type, such as `i64`, would need conversions that `main` does not show (section 3, no implicit conversions).
- **What "area" computes.** I used `width * height`. The other option was `abs(width * height)` for negative extents. Heroes has no `abs` built-in, and nothing in the program suggests negative sizes, so I did not add one. With this input the two agree.
- **Printing.** I kept `print(geom.area(r: r).to_str())`. `print(geom.area(r: r))` would also work, because `print` takes a number directly and `to_str` writes the same text (section 2), so the output would be identical.
- **Doc comment.** I added no comment above `area`, to match `dist2`, which has none. With a comment, the code would behave the same and only the documentation would differ.
