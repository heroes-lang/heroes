# sentences

- "Generics: on functions only, no constraints, always inferred, never written at the call site: `function map<A, B>(xs: [A], f: (function(A) -> B)) -> [B]`."
- "A type parameter takes its type from the arguments, else from the type the context asks for; a call that says neither is an error."
- "`xs.map(double)` takes both from `double`'s signature."
- "Top-level functions are values: `xs.fold(0, add)`."
- "A literal takes the type its context asks for — `b: u8 @ 255`, and `b + 1` is a `u8` — otherwise `i64`."

# choice_points

1. Passing a generic function (`ident`) as a value. The spec says top-level functions are values and does not exclude generic ones; `xs.map(double)` shows a function argument's signature feeding inference. I chose: allowed, with `ident`'s `A` fixed by the function type the parameter asks for. The other reading (a generic function cannot be a value at all) would refuse lines 11 and 12, and the smallest fix would be a non-generic `function ident_i64(x: i64) -> i64` used in both places.
2. Line 11, the type of `app`'s `A`. `x: 20` is a literal whose context asks for an unresolved `A`, and `ident` says nothing concrete, so I chose that the literal falls back to `i64` ("otherwise `i64`"), giving `A = i64`. The other reading (the literal waits for a context that never comes, so the call "says neither") would refuse line 11; the fix would be binding `n: i64 = 20` first and passing `x: n`.
3. Line 12, `map`'s `B`. `A = i64` comes from `ns`; `B` comes only from unifying `ident`'s signature `A -> A` with `(function(i64) -> B)`. I chose that this counts as taking `B` "from the arguments" (as "`xs.map(double)` takes both from `double`'s signature" suggests), so `B = i64`. The other reading (`ident`'s own signature names no concrete `B`, and `.len()` asks for no element type, so the call says neither) would refuse line 12; the fix would be binding the result with a type, `ys: [i64] = ns.map(ident)`, then printing `ys.len().to_str()`.
4. The name `ident`. In the grammar `ident` is a token class, not a keyword, so I chose that it is an ordinary name. Treating it as reserved would refuse line 3 and every use.
