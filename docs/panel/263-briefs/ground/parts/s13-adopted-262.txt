A signal handler of C's ends, for the callbacks of its thread, when it returns, or when C jumps out of it by `longjmp`, `siglongjmp` or `_longjmp` back into a call the signal interrupted, unless this runtime cannot tell that the jump left it (on a system whose C library it cannot read, say), and C jumping back into its frames starts it again; a callback called on that thread before it ends, from inside it or after C left it any other way (by a jump no function of the C library makes, a `setcontext`, a `swapcontext`, or a jump into a coroutine the signal did not interrupt, say), may abort, saying the handler was not seen to end, or that C called it from inside one. Where C jumps out of a signal handler whose signal interrupted this runtime's allocator, or its record of what is lent to C, the program aborts: at the jump, saying so, where this runtime saw the handler begin and the jump, and else where the program next uses that code; on a thread where no signal handler of C's has run (counting a signal with `hero_signal_watch` runs none), no coroutine switch or jump of C's makes a callback abort in these words; and a callback C calls on a thread of its own aborts, saying it ran on a thread this program did not start.
