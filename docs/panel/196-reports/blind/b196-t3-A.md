# program

File `hostname.hero`:

```
extern "unistd.h"
    function gethostname(name: ptr counted_by namelen lent, namelen: u64) -> i32

extern "hostbuf.h"
    record HostBuf
        name: u8[256]

function main()
    buf: HostBuf @ HostBuf(rest: zero)
    rc = gethostname(name: buf.name.ptr(), namelen: 256)
    if rc != 0
        print("gethostname failed")
        exit(code: 1)
    match buf.name.validated_bytes()
        .ok host => print(host)
        .err e => print(f"host name is not text: {e.msg}")
```

# choice_points

1. **How C gets the buffer.** The spec offers two routes: a `@` fixed-array
   out-parameter (`@name: u8[256]`), which it reserves for the case where "no
   argument says how many", and `f.ptr()` lending a field to a `ptr` parameter
   declared `counted_by n`. `gethostname` has a length argument, so I chose
   `name: ptr counted_by namelen` and `buf.name.ptr()`. The other route would
   probably be refused, since an argument does say how many. If it were
   accepted, it would compile and do the same thing, with the length passed by hand.
2. **Where the buffer comes from.** A field can only be lent from a binding's
   field. I needed a record with a 256-byte field that I could build without
   writing out 256 elements, so I used a group record, which allows
   `rest: zero`. That requires a C struct, so I wrote `hostbuf.h`. The
   alternative is an ordinary record `record HostBuf` with `name: u8[256]`
   outside any `extern`, built with a literal of exactly 256 zeros. That
   compiles, and I believe it does the same thing, but it is unwieldy. Writing
   `rest: zero` on an ordinary record is a compile error ("only a group's record has it").
3. **Struct naming in the header.** I used a `typedef` so the C name equals the
   record name and needs no `tag`. With a plain `struct HostBuf { ... };`, the
   declaration would need `record HostBuf tag HostBuf`. Without the `tag` it
   would be a compile error, because clang would find no type `HostBuf`.
4. **Element sign.** The header says `unsigned char`, so the field is `u8`.
   With plain `char` in the header, the field would have to be `i8`. Then
   `u8[256]` would be refused (a compile error), because fields must match the
   header's width and sign. I chose `u8` because `validated_bytes` is described
   for bytes.
5. **`lent` on `name`.** I chose to include it. Without it, the call would be a
   compile error: "a lend reaches only one so declared".
6. **Type of `namelen`.** It must be `u64`, because C says `size_t`. Using
   `i64` or `i32` would be a compile error, since a parameter that disagrees is
   refused and C does not convert those exactly.
7. **Result type.** I chose `i32`, C's own width. `i64` would also compile and
   behave the same ("a result may be wider than C's").
8. **Mutable binding.** I declared `buf` with `@`. If I bound it with `=`, the
   program would compile, but C's writes would not come back ("C writes back
   through the lend only where the binding is a `@` name"). It would then print
   an empty line.
9. **Named arguments.** The two parameters have different types, so names are
   optional. I wrote them for clarity. Positional `gethostname(buf.name.ptr(), 256)`
   would compile and do the same.
10. **Separate extern groups.** I put `gethostname` under `unistd.h` and the
    record under `hostbuf.h`. One group under `hostbuf.h`, with that header
    including `<unistd.h>`, would compile and do the same.
11. **Buffer size.** I chose 256, which fits the usual 255-byte host name
    maximum plus a zero. A smaller size compiles but may truncate. Because
    `validated_bytes` reads the whole field when no zero is found, a truncated
    name still prints, just cut short.
12. **Failure handling.** If `rc` is nonzero, the program prints a message and
    exits with code 1. If the bytes are not text, it prints the error message
    through a `match`. Using `.must()` instead would compile, and on bad bytes
    it would abort rather than print. Dropping the `rc` check would compile, and
    on failure it would print whatever is in the zeroed buffer, which is
    probably an empty line. The `rc` binding must be used, or the program
    would not compile (unused binding).

# confidence

I believe the program compiles and prints the host name. These are the parts
I am least sure of, most uncertain first:
- whether `counted_by namelen` is checked against the field at run time (256
  equals the field's length, so it should pass) or must be statically provable;
- whether `rest: zero` with no fields named is accepted on a record that has
  no union;
- whether `buf.name.validated_bytes()` is the correct spelling for a field of
  a `@` binding, rather than something that needs `buf.name` bound first.

The `_LIBC_COUNT` annotation in the C prototype should not matter, since clang
checks the types.
