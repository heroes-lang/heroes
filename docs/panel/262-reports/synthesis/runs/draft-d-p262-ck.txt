### What happens

`ck` (`docs/panel/262-reports/programs/critic/ck.h` and `ck.hero`): a coroutine `makecontext` made on a heap stack raises `SIGUSR1`; the handler, on the coroutine's stack (`CK_ON=0`), leaves by `siglongjmp` (`CK_HOW=0`) or by a `setcontext` to a context `getcontext` took (`CK_HOW=1`) to the save the runner made before it switched in (`CK_TO=0`), and the runner calls the program's function twelve frames down: exit 134, 3 of 3 each, *"panic: ck.answer was called while a signal handler of C's that this runtime saw begin had not been seen to end: either C called it from inside that handler, or C left the handler in a way this runtime does not follow (an inline `__builtin_longjmp`, a C++ exception, a jump inside a system library)"*, where the function is called after the jump, by the runner, and both exits are ones the runtime follows; the same jump back into the coroutine (`CK_TO=1`) prints `result (70 is right): 70`, and with the handler on an alternate stack (`CK_ON=1`) the jump to the runner runs too

### Where to look

`runtime/parts/sigentries.c` (rule 4, a jump ending a handler only where its target lies above it on the same range) and Darwin's `runtime/parts/rebind_entries.c`, `runtime/parts/sigguard.c` (STANDING's words)
