A signal handler of C's ends, for the callbacks of its thread, when it returns, or when C jumps out of it by `longjmp`, `siglongjmp`, `_longjmp` or a `setcontext` to a context `getcontext` took, back to a call the signal interrupted, where this runtime can tell that the jump left it; a callback called on that thread before then, from inside the handler or after C left it any other way (by a jump no function of the C library makes, a `swapcontext`, or a jump into a coroutine the signal did not interrupt or into the handler's own frames, say), may abort, saying the handler was not seen to end, or that C called it from inside one. Where a handler jumps out of code the signal interrupted inside this runtime's allocator, or its record of what is lent to C, the program aborts, at the jump or where it next uses that code, saying so; on a thread where no signal handler of C's has run (counting a signal with `hero_signal_watch` runs none), no coroutine switch or jump of C's makes a callback abort in these words; and a callback C calls on a thread of its own aborts, saying it ran on a thread this program did not start.
