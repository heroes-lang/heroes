# Your brief

You repair a program in a small programming language. Your input is the
files of this directory and nothing else: `spec.md`, the language's
specification (read it in full first); `main.hero`, the program; and
`output.txt`, what the language's tools printed when the program was built
with `heroes build main.hero -o main` and, if it built, run as `./main`. Read
no file outside this directory and use no tool but reading and writing files
here; you cannot run anything.

**The task**: make the program build and do what it evidently means. Change
what you must.

Write `report.md` in this directory as you go, with exactly these headings:
`program` (the whole program as you would build it), `choice_points` (every
place the specification or the tools' output left you a choice, the choice you
made, and what the other choice would produce), `confidence` (whether you
believe the program builds and does what it means, and what you are least sure
of), and `context` (whether anything other than this directory's files reached
your context, and what). English, no em dashes.
