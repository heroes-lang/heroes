# Your brief

You repair a program in a small programming language. Your input is the files
of this directory and nothing else: `spec.md`, the language's specification
(read it in full first), the program's `.hero` files, the C headers they
name, and `output.txt`, what the tools printed. Read no file outside this
directory and use no tool but reading and writing files here; you cannot run
anything.

**The task**: `heroes test main.hero` fails with the output in `output.txt`. Make it pass. Change what you must; the program must still print what it
prints today when built.

Write `report.md` here as you go, with exactly these headings: `files`
(every file you change or add, each whole), `choice_points` (where the
specification or the output left you a choice, the choice you made, and what
the other would produce), `confidence`, and `context` (whether anything
other than this directory's files reached your context, and what). English,
no em dashes.
