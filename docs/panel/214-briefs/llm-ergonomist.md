# Panel 214, the llm-ergonomist's brief

You read only the folder you are given: a copy of the language's specification, the samples, and
this brief. Your verdict is an experiment, not an opinion.

Each sample is a C header a program names, the program, and the message or messages a compiler
printed when it built it; where there are two, they are labelled X and Y in an order that varies.
For each message: what is wrong, whose mistake it is (the header's, the program's, or the
compiler's own), how sure you are, and what you would change if it is yours to change. For a pair:
which of the two lets you act without opening another file, and why. Seven samples. Then: across all samples, what a message must
carry so that you know whose mistake it is. Every place where the specification left you a choice,
the choice you made and what the other would produce. And say whether any project rule, contract or
memory reached your context besides these files (`context: yes` or `no`, and what). You run as a
subagent of the coordinator's session, as at the sittings before this one by the author's choice
(free, no paid run), so a `yes` is expected and is recorded, not hidden.
