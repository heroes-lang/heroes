## verdict

**object (advisory), narrowly.** The objection is to Q1's lane recommendation as written: it
treats `-Wattribute-warning` as advice like deprecation, and glibc uses that attribute to report
buffer overruns (row 1.19). The objection also covers critic routes (a) and (c), because they
repeat the blanket `-w` that Vala's own tracker described as hiding genuine warnings (1.3), and
route (c) also meets GCC's *no effect in the primary source file* (1.11). Q2's door-only rule
and Q3's pairing by construction or provenance both have long precedent behind them, and I
approve both readings.

## argument

Q1: every C-emitting language read here quiets clang wholesale (Nim, Vala, cgo's analysis
compiles), and Vala's tracker called that hiding genuine warnings. Deprecation is advice that
moves with the SDK (macOS 13's `sprintf`, GLib's versioned macros), which supports panel 208's
outcome. glibc, though, uses the `warning` attribute for buffer overruns, so
`-Wattribute-warning` belongs with the undefined-behaviour words. Q2: Go and Swift refuse every
C `...` and require a fixed-arity wrapper; Swift's overlay has one per `open`, `fcntl` and
`ioctl` shape. Fedora and Debian made `printf(foo)` an error, repaired with `"%s"`. Q3: no
general tool checks the pairing; pkg-config, Homebrew, MacPorts, CMake and Cargo pair by
construction, and only single libraries (OpenSSH, curl, SQLite) check it.

## condition

- **Q1**: the objection is withdrawn if a page shows that the warning attribute carries only
  advice on every libc the CI's legs build against, for example a clang build of glibc never
  attaching `__warnattr`. It is also withdrawn if a C-emitting language is found that quiets
  `-Wattribute-warning` in user-written glue and documents no memory fault hidden by it. A Linux
  measurement of `fgets` with an oversize length inside the region would settle the first
  (unrun: Linux is the CI's).
- **Q2**: the door-only reading would change if a system were found that binds `...` directly
  and guards a run-time format soundly without the compiler reading formats. Cyclone comes
  closest, with compiler-built tagged varargs, but its run-time check is unverified on its own
  pages and it needs a form Heroes does not have. It would also change if Go or Swift had
  admitted direct variadics later and recorded why.
- **Q3**: a general build tool that checks a header against its library without per-library
  knowledge, for example by provenance as P1 does, would be prior art for P1. None was found
  (see `search`). OpenSSH's and curl's checks are per library.

## candidate prior-art lines, per route

These are drafted for the session that files the sitting. Each link is the URL that was read;
each line must be re-read on its page before it is filed. A link to another project's issue goes
through `redirect.github.com` (`.claude/rules/records.md` § The issues).

**Q1, if the advice words are quieted and the undefined-behaviour words spoken or raised (route b)**
- **Reached first by Vala**: [GNOME bug 732531](https://bugzilla.gnome.org/show_bug.cgi?id=732531): a 2014 request that valac's C suppress the specific warnings Vala triggers rather than users passing `-w`, deprecation among them since valac emits its own.
- **Reached first by folks**: [GNOME bug 710869](https://bugzilla.gnome.org/show_bug.cgi?id=710869): pragmas in a header disabling as many of the GCC warnings on Vala's generated C as possible.
- **Reached first by GCC**: [Porting to GCC 14](https://gcc.gnu.org/gcc-14/porting_to.html): warnings that were easily ignored, resulting in difficult-to-diagnose bugs, reported as errors with no output file.
- **Reached first by GLib**: [Compiling GLib Applications](https://docs.gtk.org/glib/compiling.html): deprecation warnings turned off by defining `GLIB_DISABLE_DEPRECATION_WARNINGS`.

**Q1, if `-Wattribute-warning` is kept spoken in the region**
- **Taken from glibc**: [stdio2-decl.h](https://codebrowser.dev/glibc/glibc/libio/bits/stdio2-decl.h.html): the fortified `fgets` carries the warning attribute *"fgets called with bigger size than length of destination buffer"*.

**Q1, if route (c), the region as a system header, is taken or refused**
- **Taken from GCC**: [System Headers](https://gcc.gnu.org/onlinedocs/cpp/System-Headers.html): all warnings but `#warning` suppressed in a system header; `#pragma GCC system_header` has no effect in the primary source file.

**Q2, a variadic reached only through a door**
- **Reached first by Go**: [cmd/cgo](https://pkg.go.dev/cmd/cgo): calling variadic C functions is not supported, and a C function wrapper circumvents it.
- **Reached first by Swift**: [Using Imported C Functions in Swift](https://developer.apple.com/documentation/swift/using-imported-c-functions-in-swift.md): C functions using `...` are not imported; those taking a `va_list` are.
- **Reached first by Swift**: [Platform.swift](https://raw.githubusercontent.com/swiftlang/swift/main/stdlib/public/Platform/Platform.swift): fixed-arity overlays of `open`, `openat`, `fcntl` and `ioctl`, one per argument shape.
- **Reached first by Rust**: [External blocks](https://doc.rust-lang.org/reference/items/external-blocks.html): passing an unexpected number or type of arguments to a variadic may lead to undefined behaviour, and `safe` is only for a function that never accesses its variadic arguments.

**Q2, the run-time string written through a literal format**
- **Taken from CERT C**: [FIO30-C](https://cmu-sei.github.io/secure-coding-standards/sei-cert-c-coding-standard/rules/input-output-fio/fio30-c): untrusted input goes as a variadic argument of a fixed format, or through `fputs`, never as the format.
- **Reached first by Fedora**: [Changes/FormatSecurity](https://www.fedoraproject.org/wiki/Changes/FormatSecurity): `-Werror=format-security` for all packages from Fedora 21, the repair being `printf(foo)` read as `printf("%s", foo)`.
- **Reached first by Debian**: [dpkg-buildflags](https://manpages.debian.org/testing/dpkg-dev/dpkg-buildflags.1.en.html): the `format` feature, enabled by default, adds `-Wformat -Werror=format-security`.
- **Reached first by Clang**: [Attributes in Clang, `format`](https://clang.llvm.org/docs/AttributeReference.html): no `-Wformat-nonliteral` where the format comes from a parameter of a function annotated with a compatible attribute.

**Q2, `open`, `fcntl`, `ioctl` and the class past format functions**
- **Taken from CERT C**: [EXP37-C](https://cmu-sei.github.io/secure-coding-standards/sei-cert-c-coding-standard/rules/expressions-exp/exp37-c): `open` is variadic, and creating a file with its third argument omitted may create it with unintended access permissions.
- **Reached first by glibc**: [fcntl2.h](https://codebrowser.dev/glibc/glibc/io/bits/fcntl2.h.html): `open` with `O_CREAT` or `O_TMPFILE` and two arguments is a compile-time error when the flag is constant, and a fortify failure at run time otherwise ([open_2.c](https://codebrowser.dev/glibc/glibc/io/open_2.c.html)).

**Q3, pairing by provenance or by prefix (P1, P2)**
- **Reached first by Homebrew**: [super.rb](https://raw.githubusercontent.com/Homebrew/brew/main/Library/Homebrew/extend/ENV/super.rb): the include paths and the library paths a build gets both come from each keg-only dependency's own prefix.
- **Reached first by MacPorts**: [macports-dev, 2013-11](https://lists.macports.org/pipermail/macports-dev/2013-November/025000.html): `CPATH` and `LIBRARY_PATH` set together for all ports in all phases.
- **Taken from Nix** (if P2 is refused): [multiple-output chapter](https://raw.githubusercontent.com/NixOS/nixpkgs/master/doc/stdenv/multiple-output.chapter.md): a package's outputs reside in separate store paths, headers in `dev` and libraries in `lib`.

**Q3, a check of the pairing, or a refusal when the halves come by two routes**
- **Reached first by OpenSSH**: [configure.ac](https://raw.githubusercontent.com/openssh/openssh-portable/master/configure.ac): *"whether OpenSSL's headers match the library"*, fatal unless `--without-openssl-header-check`, and a run-time `fatal` on a mismatch ([entropy.c](https://raw.githubusercontent.com/openssh/openssh-portable/master/entropy.c)).
- **Reached first by curl**: [curl-users, 2016-04](https://curl.se/mail/archive-2016-04/0004.html): curl's configure warning *"OpenSSL headers and library versions do not match"*, the library found through `PKG_CONFIG_PATH` and the header elsewhere.
- **Reached first by SQLite**: [sqlite3_libversion](https://www.sqlite.org/c3ref/libversion.html): an `assert` that the library's version equals the header's ensures matching library and header files.
- **Taken from libcurl** (for the harm 2448 rests on): [curl_version_info](https://curl.se/libcurl/c/curl_version_info.html): accessing a struct field newer than the struct's age may cause undefined behaviour and possibly crashes.

**Q3, the note naming both halves (P4)**
- **Reached first by Homebrew**: [caveats.rb](https://raw.githubusercontent.com/Homebrew/brew/main/Library/Homebrew/caveats.rb): the keg-only caveat names `LDFLAGS -L<opt>/lib` and `CPPFLAGS -I<opt>/include` together.
