# Panel 234, the proposal

M-core-packages writes the core packages as ordinary Heroes modules in Go's tree,
with no language form and no built-in. Before the first one, this sitting rules:
what a package may hold under §1.11 (A); where packages live and how a program
reaches them (B); the conventions every package keeps, names by the author's rule
*a Go name only where the contract is Go's* (C, `conventions-draft.md`); thin or
thick over C, by a reader test (D); an interface card per package (E); where the
platform's C lives, one runtime or a platform layer beside it (F); the byte buffer
(G); contextual words and a C symbol spelled as a keyword (H); a group's header
(I); `alias` and Part 7 item 10 (J); issue 970's repairs (K); `write_file` (L);
`sort_by` (M); and how the packages' effect on a model is measured (N).
