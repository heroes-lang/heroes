## What you decide

1. **Which zeroing is dead, over the whole compiler.** For every declaration
   the emitter writes with `= {0}` in the seed your compiler emits for itself
   (`./heroes build selfhost/main.hero --emit-c -o self.c`), classify it:
   read or released on some path from the entry before any write (the zeroing
   is needed), or written before every read and every release (the zeroing is
   dead). Say how you decided, and name the instrument: the IR's own dataflow
   (`emit/unread.defs`, the verifier's dominance), or a C-level check. Count
   both classes, for values and for slots separately.
2. **Price the routes**, each in files and lines of `selfhost/`, prototyped in
   your copy far enough that the number is real:
   - **(a) zero only what a release or a read can reach unwritten**: a
     definite-assignment answer per value and per slot, computed once per
     function beside `unread.defs`, and `= {0}` printed only where it is owed;
   - **(b) one destination for a `match`'s arms**: the lowering writes each
     arm's value into one slot, so the per-arm synthetic slots, their zeroing
     and their exit releases go; say what `ir/own.hero`'s rule 5 becomes and
     what it would break;
   - **(c) an arm's slot released where the arm joins** rather than at the
     function's exit;
   - **(d) both (a) and (b)**, or any route none of these names.
   For each prototype: regenerate your seed and verify the fixpoint (build
   twice, `cmp`); run the compiler's own tests and the net's `run`,
   `emission`, `determinism`, `ir`, `emit` and `canonical` suites in your copy
   (`./heroes run tests/harness/main.hero -- ./heroes <suite>`, one at a time),
   and say which break and why. `emission` blesses emitted C byte for byte, so
   a route that changes the C changes those blessings: say how many, and that
   they are regenerated by the suite's own procedure, never by hand.
3. **Robustness.** For each route, the path on which it could read or release
   an uninitialised value, and the instrument that would catch it: ASan in
   `run`, clang's `-Wuninitialized` and `-Wsometimes-uninitialized` on your
   whole emitted seed (`clang -fsyntax-only -Wuninitialized
   -Wsometimes-uninitialized -I runtime self.c`), the IR verifier.
4. **The time.** With `/usr/bin/time -p`, on a quiet machine or with the load
   reported: `heroes fmt` on a large file (sixteen copies of
   `selfhost/check/walk.hero` concatenated reproduce `00-shared.md`'s 36,672
   lines), `heroes check selfhost/main.hero`, and `build --emit-c` on
   `selfhost/main.hero`, each with the trunk's compiler and each route's; and
   the same `fmt` with each compiler built at `-O2`, so the unoptimised number
   is not the only one.
