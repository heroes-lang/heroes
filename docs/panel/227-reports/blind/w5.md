function after_colon(line: str) -> str
    for j in range(from: 0, to: line.len())
        if line[j] == ':'
            return line.slice(from: j + 1, to: line.len())
    return line

function show(n: i64, line: str)
    print(repeat(" ", to_u64(n).must()), after_colon(line: line))

function main()
    argv = args_checked()
    if argv.len() != 1
        exit(code: 2)
    path = match argv[0]
        .ok p => p
        .err _ =>

1. **Argument access.** I used `args_checked()` rather than `args()`. Choice: a non-UTF-8 argument makes the program exit 2, which the task does not list. The other choice, `args()`, would abort on such an argument instead.
2. **Empty `k`.** An empty digit string exits 2. The task does not say whether it counts as "written only with digits". The other choice would treat it as 0 and print a blank line and an empty `=` line.
3. **Digit check and overflow.** I check each digit as it is read, and exit 2 as soon as the value exceeds the text's byte length. Once `k` is at most the length, the next step cannot overflow `i64`. The other choice, accumulating the whole number first, could abort on overflow for a very long digit string instead of exiting 2.
4. **`k` lands inside a multi-byte character.** The spec makes `slice` abort there, and `print` takes only whole `str`, so the program can print no partial bytes. I let the abort stand. The alternative, exit 2, would contradict the task's list of exit-2 conditions. This is a real gap in the task-versus-spec match.
5. **Type of `len`.** The spec does not state what `len` returns. I assumed `i64`, because `k` and the range bounds are `i64`. If `len` returns `u64`, the comparisons and `range` calls would not type-check.
6. **Digit values.** I compared bytes with the character literals `'0'` and `'9'` and converted with `to_i64(b).must() - 48`. The other choice, a `to_str` round-trip, is clumsier and gives no advantage.
