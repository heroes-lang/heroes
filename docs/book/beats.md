The 1500 ceiling had been breached the day it was written, and nobody could see it. The design document had said from its first draft: count it with a real tokeniser, not by estimation.
2026-08-04 | M2 | The parser's first act was to discover that the language could not write down the type of a function. `fn` was in the registry of foreign words — an error with the repair pre-written — and also in the spec's own syntax for a function type, so `(fn(int) -> int)` failed to lex and every function-typed parameter in the language was unwritable, `map` and `fold` included. Five judges were sent the question with a recommendation attached, and four of them refused it: the project's own §4.17 lists `fn` among the mistakes the registry exists to catch, seven ancestor languages spell a function type with the word that declares a function, and the tokeniser measures the two spellings identically. The recommendation lost to the evidence, which is what the panel is for.
2026-08-04 | M2 | Then the acceptance program — the calculator in the appendix, written months of conversation before any compiler existed — was fed to the parser for the first time. It found the same class of bug from the other side: a variant case called `.var`, a name the registry had quietly reserved. Two lines later it found a form nobody had specified, `=> assert false`, used in eight places. A 317-line program that had never been compiled turned out to be the best test in the repository, because it was the only one written without the parser in mind.
2026-08-04 | M2 | The formatter turned "canonical" from a slogan into three decisions with prices. Minimal parentheses need associativity, the half of the precedence table nobody writes down. Long lines can only break inside brackets, because panel 007 left nowhere else. And the blank line between a comment and the declaration below it cannot be normalised at all — that gap is what makes the comment documentation, so a formatter that tidies it changes what the program means.
2026-08-04 | M2 debrief | The author sent the arm-body question to the panel and got back something nobody had asked for. The judge whose job is cost did not estimate the change — it *built* it in a scratch clone, and in doing so found that the status quo it was supposed to defend was shipping two disasters: `heroes fmt` printed an arm's `if` and silently deleted the branches under it, and `heroes parse` looped forever on a file that looked fine. Both had one cause, and it was exactly the special case the proposal wanted to delete. The question had been "is this form worth one spec token"; the answer was "the form is free, and the thing you were protecting was on fire".
2026-08-04 | M2 debrief | A second judge, holding nothing but the spec, killed the argument for the status quo from the other side: forbidding `=> assert false` on one line forbade nothing, because the same valueless arm was always legal one line lower inside a block. The guard everyone assumed existed had never existed. What was actually missing was a rule nobody had written — a `match` used as a value must have arms that produce values — and it belongs to the type checker, not the grammar. Two judges, opposite inputs, same hole.
2026-08-04 | M3a | The resolver's five rules went to the panel, and the answer came back with the price list inverted: four of the five cost nothing to specify, because a rule whose violation ends in a compile error is *stated by that error*. The only rule that had to be paid for was the only one that failed quietly — a file's own `map` silently replacing the language's. Two judges killed it in the same hour without seeing each other's evidence: one because the meaning of `xs.map(f)` would depend on a line you cannot see, the other because it was an exception to a sentence the spec already contained. The rule that shipped is shorter than the rule that was proposed.
2026-08-04 | M3a | One judge reasoned from the spec alone — no methods, no overloading — and proved that `x.f(y)` can be resolved with no types whatsoever. The reasoning was airtight and the conclusion was wrong: the design document says the dot looks for a *field* first, and a field can hold a function. The judge holding the actual code didn't argue, it compiled the counterexample and watched the prototype reject a legal program twice. What settled it was a test neither had proposed: report the unknown function only when no record in the whole file has a field by that name. No types, no false rejections, and it still catches the misspelling the first judge had itself made while writing Heroes from the spec.
2026-08-04 | M3a | The 317-line calculator refused to resolve, at exactly two lines: it declares its own `map` and `fold`, and the language reserves both names. Third time that program has caught a rule nobody knew they had written — a variant case called `.var`, an `assert` in an arm, and now a name. It has never been compiled and it is still the best test in the repository. Meanwhile it turned out to be calling `.str()`, a built-in that is in the design document's inventory and missing from the spec: without it the language cannot put a number into a sentence, and nobody had noticed because nobody had tried.
2026-08-04 | M3a | Making an unused parameter an error is a rule with exactly one shipped precedent, and the judge that writes Heroes for a living found the reason nobody else ships it: told "the parameter you never read is an error", its own most likely repair was to *delete the parameter* — a wrong signature that compiles, the silent bug merely relocated. Every language that enforces the rule ships the same escape hatch, `_`, and Heroes already had it by accident: `_` never binds anything. The rule that looked like a new restriction was mostly a valve that was already open.
2026-08-04 | M3b | Three ways to type a jump went to the panel, and the judge whose job is cost did not argue about them — it built all three and ran them. Typing `break` at all turned out to reject every function whose body ends in `return`, which is most functions in this compiler; Rust's own RFC had recorded that exact wrong turn a decade earlier, in the compiler's words. Then the judge who only reads precedent objected to the winner on a completely different axis — its cost is one rule per branching construct, and Heroes already has two — and named the condition under which it would withdraw: write the rule once, as a shared routine, with divergence as data. That file is 84 lines. Two judges, opposite inputs, and the design that satisfied both was proposed by neither.
2026-08-04 | M3b | And design.md was caught contradicting itself, one bullet apart: a `match`'s type comes from the arms that can produce a value, said the third bullet of §4.7; every arm must produce a value, said the fourth. The same program, legal and illegal, six commits after both sentences were written by the same panel. The rule that survived is the one with the executable evidence behind it, and the other now says "or jump".
2026-08-04 | M3c | The calculator refused to type-check on one line, and the line was in the panel record's own list of things it had fixed. Panels 002 and 006 had rewritten eleven sites to `ok(...)` "when applying the rule exhaustively"; there were twelve. Four milestones, four defects in a program that has never been run — a variant case the registry had quietly reserved, an `assert` where the grammar allowed only an expression, two library functions whose names the language reserves, and now a missing `ok`. It remains the best test in the repository for the same reason each time: it was written before there was anything to test it with.
2026-08-04 | M3d | The thesis got its first number, and the useful part is the column that shows nothing. 379 mutants, 94% caught — but the same compiler with the thesis rules switched off catches 76%, and *that* is the measurement: 18 points, concentrated in three operators. The lazy catch-all goes from 100% caught to 13%. Shadowing and dropped argument labels go to zero, because nothing else in the language looks for them. And typos score 100% in both arms, which means they are caught by names and types like anywhere else — a fact that would have been very easy not to write down.
2026-08-04 | M3d | Two mutants survived on purpose and nobody had planned for it: turning a mutable cell into a plain binding is only a mistake if something later writes to it, so where nothing does, the mutation means exactly what the original meant. A panel had asked for a meaning-preserving counter-arm to keep the catch rate honest. It turned up inside an operator, uninvited.
2026-08-04 | M3d | The spec had been telling models to write a compile error for four milestones. A panel ratified the function type's spelling at M2; the frozen spec kept the old one, which the language rejects on sight with a fix attached — and the assistant reads that spec at the start of every session. The freeze was protecting a measurement that had already been published twice. It lifts here, and the document is now held to the compiler by four tests, one of which simply asks whether the spec uses any word the lexer refuses.
2026-08-04 | M4 | The panel that decided the compiler's middle end spent its most valuable half-hour not arguing. One judge was told to write the C that each proposal implied and compile it — and it compiled fourteen programs, two of which decided the design. In the first, a Heroes function called `open` reaches C with its own name and quietly replaces the one in libc: clang says nothing, the program prints 7 instead of a file descriptor, and `open` is not on the language's list of reserved words. In the second, assigning the result of a function that returns nothing is not a warning but a hard error, and the graphics library everyone eventually binds is almost entirely made of such functions. Neither fact is in any design document. Both are now in the instruction set.
2026-08-04 | M4 | The choice between the textbook representation and the plain one was settled by the institution with the most to lose by settling it that way. LLVM — whose whole existence is single-assignment form — tells the authors of new languages not to build it: use stack slots and loads and stores, it says, and let a later pass clean up, because that is what clang itself does. QBE says phi nodes are not necessary. Rust's own middle representation chose the plain form in 2015 for the sake of error messages rather than speed and has not changed in eleven years. Every migration anyone could verify was made to produce faster machine code — the one thing this project has formally renounced. The simpler answer had a decade of evidence behind it and nobody had gone looking.
2026-08-04 | M4 | A judge was handed two spellings of the same lowered function with the labels stripped off, and asked what it returned before it was asked which it preferred. It got both right, then counted what each had cost: one re-reading for the plain form, three for the fashionable one — and the expensive one was not verbosity. A line that names a value defined by jumps elsewhere in the function cannot be read as a line at all; you have to find every jump first. It also noticed, in passing, that the sample's blocks had exits nobody had drawn: arithmetic that overflows and an index out of range both stop the program, so three of five blocks had a hidden way out. A pass written on the assumption it had read correctly would have been wrong and would have compiled.
2026-08-04 | M4 | Everyone cites the Haskell compiler as the reason to build a second tree before lowering. Read the source and the payoff was never the tree — it was the checker they could run over the small representation afterwards, which its own authors say makes it surprisingly hard to write a transformation that type-checks and means the wrong thing. So the check shipped without the tree, and it earned itself back the same afternoon: it is what now guarantees that every path out of a function writes back the arguments it promised to modify, including the one that leaves through an error. That obligation had been named four milestones earlier as the place this project would actually stall.
2026-08-04 | M4 | The loop that reads `for x in xs` becomes four blocks, and only three of them are obvious. The fourth exists because `continue` has to increment the index too — and a version that skips it produces a program which compiles, passes every test, and hangs forever on the first element it skips. No type system can see that. The 320-line calculator, which has caught a defect at every milestone since the parser, caught nothing this time: every line of it lowered and verified on the first attempt. Two bugs turned up anyway, both in the same shape, and both found by reading the dump rather than by running a test — the underscore that means "I am not using this" was quietly given a variable of its own.
2026-08-04 | M5a | The compiler produced its first binary, and the argument that took longest was about a number between zero and two. When a program is correct and the compiler simply is not finished, what should it say — and more to the point, what exit code should it use? Two says "the tool could not do its job", which is literally true. One judge was handed that message and asked what it would do next: it checked the compiler's version, ran the diagnostic command, searched the whole repository for the internal identifier it had been shown, and then told its user the toolchain looked broken — a sentence it reported afterwards as false. Another went to look for precedent and found that the C compiler everybody uses has had a special diagnostic for exactly this since 1994, printing the word "sorry", and then read one line further: it exits with the ordinary failure code. The evidence that looked like it argued for two settled the question at one.
2026-08-04 | M5a | The instruction to point generated code back at the author's file had been in the design document for months, and it was not implementable as written. The directive that does it anchors the *next* line and then the compiler counts upward on its own — so a source line that becomes five lines of generated code drifts by four, and the drift accumulates as you read down the file. The hand-written target that had frozen the shape of the whole backend advertised line 2 in its own header comment and delivered line 6, which is blank; worse, the error it printed showed the generated text underneath the name of the author's file. Nobody had noticed because nobody had made an error there on purpose.
2026-08-04 | M5a | A judge whose only job is to compile the C that a proposal implies found the hole that mattered by writing four declarations by hand. The language can already name a function from a C library, and nothing yet attaches the library's header — so the compiler would have to invent the C declaration from the Heroes one, which makes it self-consistent by construction and checked by nothing. Asking for the absolute value of a number slightly too large for 32 bits returned a wrong answer at exit zero, with one warning that is not an error; opening a database returned success in total silence, under every warning flag the compiler has. With the real header present both are hard errors. The founding constraint of the language is that everything comes from C libraries, and its guarantee turned out to live entirely in the `#include`.
2026-08-04 | M5a | A directory called `runtime` is one of the commonest names in a source tree, and the compiler looks for its own in the current one. So somebody put a decoy there: the generated program compiled with zero warnings under every diagnostic the compiler offers, ran, and printed a hexadecimal number where thirty was expected. The repair is a single line asserting a version constant that only the real header defines — after which the same program will not compile at all. The interesting part is that the search order was already written down, reviewed, and approved; what was missing was somebody willing to lie to it.
2026-08-05 | M5b | The compiler learned to count references, and the check that watches the counting refuted its own design twice in an hour. The rule was: a value that owns a string is released at the end of the block that created it. The first refutation was harmless and instructive — an assertion carries the text of what it asserted into the failure path, and that text is a string, and it crosses a block boundary, and it is perfectly safe there because a literal is never freed. The second was fatal. Ask for the half of a number and then use it in a sentence, and the sentence's first half is built in one block and finished in another, because asking for the half opens a branch in the middle of the expression. Not a corner case: that is what every expression containing a fallible call looks like. The repair was to stop letting temporaries own anything at all — put the reference in a named cell the moment it exists, and let the cells be swept. Which is exactly what choosing cells over the fashionable representation had been for, one milestone earlier, in an argument nobody had yet had to cash.
2026-08-05 | M5b | The leak detector everyone reaches for does not exist on this machine, and it took two judges measuring it independently to notice. Ask the sanitiser to look for leaks and it answers that leaks are not supported on this platform, and aborts. Do not ask, and a program that loses 999 blocks of memory exits with success in complete silence. So the milestone that introduced reference counting would have shipped behind a configuration that looked exactly like a leak gate and was not one. What replaced it is twelve lines: count the live blocks, check the count is zero when the program ends, and name the number. It caught a real bug on its first run — a plus sign between two strings reads like arithmetic and is a constructor, and the type of the result is the only thing that says so.
2026-08-05 | M5b | Two judges investigating different things produced a better answer than either had. One objected that the project must not promise "the shortest decimal that round-trips", because the smallest number a double can hold renders as sixteen digits under the chosen method and round-trips perfectly well. The other, checking a citation, found that the widely-shipped implementation of that same method starts its search at one digit rather than fifteen when the number is very small — a branch the proposal's description had dropped. Put the branch back and the counterexample evaporates: the tiny number prints as five characters, exactly as Python does. The correction to the wording stands anyway, because what is guaranteed is the round trip and not the brevity, and the difference is what a compiler shipped wrong for eighteen years.
2026-08-05 | M5b | The promise "our runtime never changes the locale" turned out to be worth nothing, and the demonstration is more convincing than the argument. Set a locale that writes decimals with a comma — which any of a dozen C libraries does on startup — and the number formatter emits a comma, then notices there is no decimal point, then appends one, producing something that is not a number in any locale. And the self-check cannot see it, because the same setting corrupts the reader as consistently as the writer. The precedent is twenty years old and exactly this shape: Python never touched the locale, the graphical toolkit it was embedded in did, and Python broke anyway.
2026-08-10 | M5c | A tree that contains itself, in a language with no pointer. There is no box type, no reference type, nothing to put in a field that stands for "somewhere else" — and yet the example the design was written around is a tree of expressions holding its own children. The answer, decided years of reading earlier, is that the *array* is the one indirection there is: an array is a pointer whatever it holds, so a shape that recurses through one has a finite size and still copies like a value. This milestone is where that stopped being a claim. The program compiles, prints fourteen, and ends with every allocation accounted for. What makes it work is not clever: freeing one node runs a function the compiler wrote for that node's type, which releases an array, which releases each element through a descriptor, which calls the function the compiler wrote — a recursion assembled from one generated function per type and one runtime that drives it. And the reason it cannot leak is a sentence about what a field may hold, not about how the freeing works: a field cannot contain a reference, so every value in the language is a tree, and a counter that frees at zero is complete.
2026-08-10 | M5c | Six bugs in one milestone and every single one was a missing row rather than wrong reasoning. The compiler is built out of exhaustive tables, so adding a capability breaks compilation until every table admits it — which works, and is why nobody wrote logic that was actually wrong. What it does not cover is adding a capability to the list of *types* and forgetting it in a walk over *fields*, because that walk already has a last arm for everything else. Three of the six landed exactly there, and the interesting part is what the last arm said. It emits a loud failure rather than doing nothing — so a container inside a variant aborted on its first run instead of quietly losing memory. The usual argument for enumerating every case is that additions become loud. The other half, which this milestone taught, is that what the *final* arm does decides the failure mode of everything the enumeration forgot.
2026-08-10 | M5c | Twice, a program printed every correct answer and was wrong once, at the end. Build a pair from two records that each hold a piece of text, print all seven lines, watch them all be right, and then watch the program free the same memory twice on the way out. Assign a new list into a field, read it back correctly, and leak exactly one block. Neither is visible in the output, at any input, ever — the answers are right because the *values* are right; only the bookkeeping is wrong, and bookkeeping has no output. Both were found by twelve lines that count live allocations and complain if the count is not zero when the program ends. The sanitiser everyone reaches for agreed with both after the fact and found neither on its own. A milestone about memory turns out to need an instrument whose subject is the balance rather than the result.
2026-08-10 | M5c | The rule that was invented to protect the generated code caught the file that invented the rule. A panel had insisted that every type's hash function must exist even where nothing hashes it, because calling a missing one crashes with no type name and no line number to go on. So the array constructor was made to refuse any type description lacking one — and the first thing it refused was the hand-written experiment that had frozen the type-description format in the first place, two milestones earlier, and had never needed a hash. The experiment was right about the format and incomplete about the rule it would later be judged by. A check with an instrument beats a check in a comment, demonstrated on the comment's own author.
2026-08-10 | M5d | The last two types in the language were entangled, and one of them may not survive. Looking a key up in a map returns "the value, or an error", so the map could not be built before that type existed — and that type turned out to be reference-counted even when it holds a plain number, because its error side carries two strings. So `int?` owns memory. The other half of the tangle is a judgement nobody has made yet: an earlier review found that the map cannot be added to, which means the compiler this language is meant to compile cannot build a symbol table with one, and deleting the whole container from the specification would give back more budget than finishing it costs. The container was built anyway, on the author's instruction, with the disagreement written down rather than smoothed over. If the audit deletes it, this work goes with it, and the record will say that was known in advance.
2026-08-10 | M5d | A rule adopted two milestones before anything could use it, and the first thing it did was reject the file that inspired it. The requirement was that every type must have a hash function even where nothing hashes anything, because calling a missing one crashes with no type name and no line number. There was no hash table in the language at the time. When one finally arrived, the rule's justification arrived with it — and in between, the constructor enforcing the rule had already refused the hand-written experiment that froze the format in the first place. Adopting a rule before its use is usually a smell. This one was right for a reason that does not depend on timing: the cost of getting it wrong is a crash with nothing in it to read, and that cost does not shrink by waiting.
2026-08-10 | M5d | A leak that only exists when the value was computed. Look a key up in a map, take the answer or a default, and one block of memory is lost — but only if the value in the map was built by joining two pieces of text, never if it was written as a literal. The reason is that a literal is laid out by the compiler with a negative reference count, so failing to release one changes nothing at all. The bug was in a single word: one table said the lookup borrows its result while the code that emitted it made a copy. What the episode really settles is how to write a test for this class: allocate on purpose. Every case in the milestone that touches counting now joins two strings rather than writing one, because the cheaper spelling would have passed.
2026-08-10 | post-M4 | The project had a home for every kind of writing except the kind it was mostly made of. Explanations had one, decisions had one, questions owed had one — and each of the three had been created, at some point, because something valuable was disappearing at the end of a conversation. What was still disappearing was the middle: not the explanation that finally worked, but the route taken to reach it, and the questions still standing when the chat ended. The request that fixed it was one sentence — «uso questa chat per capire», with the offer of a folder attached almost as an afterthought — and the first thing the new folder had to be told was what it was forbidden to become: not a second glossary, not a way to change the language without the panel, and not a record of who understood what.
2026-08-11 | M6 | Three design arguments were settled this milestone and not one of them was settled by argument. A judge was asked whether the runtime's per-type description should gain a sixth entry so that sorting could work on everything; it wrote the header, compiled the unchanged runtime against it, and found that C fills a short initialiser list with zeros — so every existing description would have carried a null pointer, silently, under every warning flag the project uses, and the call is a crash with no type name in it. Another was asked whether the language's small library could be compiled once and shipped; it wrote the only shape that is possible for a generic function compiled ahead of its uses, passed a text-handling function where a number-handling one belonged, and got no diagnostics at all and then a crash. A third was asked whether the mangled names of generic instances should be readable rather than hashed; it found two perfectly legal programs that spell the same name. Three vetoes, three compilers' worth of evidence, and none of it reachable by reading.
2026-08-11 | M6 | The specification had contradicted itself for eleven weeks and implementing one function is what found it. It says ranges are written `range(a, b)`. It says that when two parameters of a function share a type, the caller must name them. And it says `range` is written in the language itself. Any two of those are fine; all three cannot hold, because a built-in escapes the naming rule and an ordinary function does not. Nobody could see it because `range` had never had a body — the rule and the exception had never been in the same room. The resolution was to obey the rule the language already had, which turns the habit every programmer brings from elsewhere into a compile error with the repair attached.
2026-08-11 | M6 | A pass that has already decided is worse than one that declines to. The plan said the generic-expansion pass must run before the reference-counting pass because the second cannot decide anything while types are still unknown. It can, and it had: asked whether a value of an unknown type owns memory, the compiler answers no — which is right when that type turns out to be a number and a leak when it turns out to be text. The dump showed the two side by side in one function: an array getting its increment, a value of unknown type getting nothing. So the ordering in the plan was right for a reason nobody had written down, and the reason is not that the pass is helpless but that it is confidently wrong.
2026-08-11 | M6 | Adding a feature made an old defect reachable, which is a shape worth naming. Folding a list into a value requires knowing two things the specification never said: which direction, and which way round the two arguments go. Where the running total and the elements have the same type — adding numbers, joining strings, taking a maximum, which is most real uses — every combination type-checks, and four different programs are spelled identically and print different answers. It had never mattered because the function had no implementation, so nothing could run. The step that gave it one is the step that had to fix it, and the fix is nine words in the specification.
2026-08-11 | M6 | The check a panel asked for as insurance is the one that found the fire. The language's small library is appended to every program the compiler sees, so both live in one text — and a panel worried that an error inside library code would point at a line the author cannot open, and asked for a guard that refuses to report one. It fired the first time the library contained a function with local variables of its own. The library's folding function has a variable called `total`; a user program with a top-level declaration of that name was told, in effect, that their own code was shadowed by something invisible. The guard was written for a hypothetical and caught the real thing on contact.
2026-08-12 | M8a | The cheapest change the language ever made was a verb. Splitting a program into files needs rules: what happens when a file's own name collides with the name of a file it imports, and what happens when an import is never used.
