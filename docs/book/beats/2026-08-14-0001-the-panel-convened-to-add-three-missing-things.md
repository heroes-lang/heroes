2026-08-14 | M-binding-fidelity | The panel convened to add three missing things, and measurement removed two of them. The first was a 32-bit number type: a foreign function taking one had been called with a wider number, and the wide number was thought to be arriving damaged. It is not — it arrives bit-for-bit identical to what a C program would send, and the number that looked wrong was simply what a 32-bit float contains. The second was a way to declare a function that takes an open-ended list of arguments. There is a real rule saying that calling such a function through a fixed declaration is undefined, a real processor where it goes wrong, and three real projects that were broken by it. The project was not, and the reason was a decision taken a milestone earlier for an unrelated purpose: the compiler never re-states a foreign function's signature, it includes the real header and lets the call go through that. The declaration in the program is read by the front end and never reaches C. What remained after both were struck was smaller and true, and one judge left a standing veto behind it: never re-state the signature, because the version that does is silently correct on one of the two machines the project tests on.
