2026-09-02 | M-corpus-coverage | The job was to write twenty more programs in the language, chosen so that between them they use every part of it. The first one found a hole in the compiler. Not a subtle hole: a program that the checker said was fine, and that then refused to build, with the compiler blaming itself rather than the person who wrote it. The program was three lines of the most ordinary thing anybody does with a list — take each item, turn it into a number, add the numbers up — written the way the language's own one-page description teaches it. And that spelling had never once been written down in this project. Not in the compiler, not in the examples, not in the tests: the six little helpers the language ships for exactly this work were called by a single test file, one of them by nothing at all, and the shorthand the documentation uses to explain them appeared in zero programs. So the first program to use the language the way the manual does was also the first to press on a piece of machinery nobody had pressed on. What was wrong underneath is the kind of thing that only shows in a chain. When you write `list.transform(f).total(g)`, the compiler records what each of those two calls is working on by remembering **where in the file it starts** — and a chain like that starts, for both of them, at the same character. The second recording overwrote the first, so the inner call was compiled as though it handled the type the outer one produced. Two different files in the compiler each carried a comment asserting this could not happen, and the second one blessed the first: two documents saying one thing is not two witnesses. The repair rests on the same asymmetry that caused it — a chained call starts where its receiver starts, but it *ends* at its own closing bracket, so the ends are always different. Nine places, one word each. Then nineteen more programs, and the language corrected the person writing them seven times: a container of anything cannot be a record here, two arguments of the same type must be named where you call them, the formatter deleted a pair of brackets that in C are the difference between working and broken, and a conditional cannot be squeezed onto one line at all. The seventh was found by a failing test rather than by the compiler — an escape rule that protected one bracket and not its partner. Seven lessons in a corner of the language, none of which a checklist of features would have produced, all of which came out of writing programs somebody might actually want.
