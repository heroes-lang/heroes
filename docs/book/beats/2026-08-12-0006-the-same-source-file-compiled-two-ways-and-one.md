2026-08-12 | M8a+ | The same source file, compiled two ways, and one of them leaked. A reviewer running the test suite from a different starting file found a failure that nobody could reproduce from the usual one: identical bytes, and memory lost only when that file was compiled by itself. The reason is that the compiler asked the wrong question about a type. To decide whether a value carrying text needs releasing, it consulted a table that is only filled in when some program somewhere *takes apart* such a value — and the file in question builds them and never takes one apart. So the release function came out as an empty switch, while the same declaration compiled next to the file holding the pattern match came out correct. Ninety test programs missed it, because catching it needs a value carrying text that is *computed* rather than written down, and never taken apart in the same compilation; every existing test that builds one also takes one apart. The fix is to ask the fields, which do not move between compilations, instead of the table, which does.
