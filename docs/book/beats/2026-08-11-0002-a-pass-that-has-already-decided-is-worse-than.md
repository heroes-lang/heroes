2026-08-11 | M6 | A pass that has already decided is worse than one that declines to. The plan said the generic-expansion pass must run before the reference-counting pass because the second cannot decide anything while types are still unknown. It can, and it had: asked whether a value of an unknown type owns memory, the compiler answers no — which is right when that type turns out to be a number and a leak when it turns out to be text. The dump showed the two side by side in one function: an array getting its increment, a value of unknown type getting nothing. So the ordering in the plan was right for a reason nobody had written down, and the reason is not that the pass is helpless but that it is confidently wrong.
