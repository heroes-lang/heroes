2026-08-15 | M-struct-passing | A third of everything a real C library offers had been out of reach, because a bundle of values travelling as one thing had no way to cross. The obvious fix is to describe the bundle on both sides and then check that the two descriptions agree in size and in the position of each part. That fix is wrong, and the way it is wrong is the reason this project exists: on the machine this is being written on, two bundles can have exactly the same size, exactly the same positions, pass every check anyone could write — and still arrive as garbage, because the processor carries whole numbers and fractional numbers in two different sets of registers, and the check cannot see the difference between them. The answer was to stop describing the bundle at all. The compiler now writes nothing about it and uses the library's own description, so the arrangement is never its to get wrong. What it does check is each part, one question at a time, and the question is *is this exactly the same kind of thing* rather than *is it the same size*. Before that check existed, declaring one part as a whole number four times too wide compiled, ran, and printed the correct answer — right up until a value came along that did not fit, at which point it would have printed a different one and said nothing.
