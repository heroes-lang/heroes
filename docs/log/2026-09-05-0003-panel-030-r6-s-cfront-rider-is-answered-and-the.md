It is not a bet. Stack switching and CPS are what green threads and coroutines need, and Part 7.13 refuses both by name (`design.md:2566-2573`); an OS thread is a C function call. Measured: pthreads binds, links and runs from Heroes at exit 0; `function worker(arg: ptr) -> ptr` emits `void * h_main_worker(void * h0_arg)`, which **is** `void *(*)(void *)`, and passing it straight to `pthread_create` with **no cast and no trampoline** compiles under `-Wall -Werror` and prints from the other thread at exit 0. So the scheduling item's *"the emitter owes one generated trampoline per spawned function type"* is false for this shape, and what is missing is a **permission**: the compiler refuses to declare what it already knows how to print (`selfhost/emit/ctype.hero:379`, whose own comment says the two are the same eight bytes). **What the model does cost is the runtime**: four threads allocating at once give `hero_runtime_check_leaks()` 2586, 1836 and 3141 live blocks in three identical runs, exit 134, a leak that is not one, and ThreadSanitizer names the entire race as `hero_live_blocks` at `alloc.c:113` — **inside the single allocation point**, which is exactly what §4.20 said the invariant would buy, six hours after step 0 made it true and gave it an instrument.
