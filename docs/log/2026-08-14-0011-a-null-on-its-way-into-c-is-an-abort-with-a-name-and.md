2026-08-14 | **A null `cstr` on its way into C is an abort with a name, and `nullptr` takes the type its context asks for** (`docs/panel/053`, provisional — author ratification pending; five judges, and a criterion that arrived mid-sitting and re-ranked it). The sitting was convened on a verified gap: `v == nullptr` on a `cstr` was `expected cstr, found ptr`, and declaring the binding `-> ptr` bought the comparison at the cost of ever reading the string — **you had to choose between checking for null and reading it**. Four options were proposed and **the sitting's own premise was false**: `to_str` on a null `cstr` never dereferenced anything, because `runtime/parts/str.c` guards it and panics with its own name, identical at `-O0`, `-O2` and `--sanitize`. That path was a *diagnostic* gap. **The safety gap was a null `cstr` handed straight back to C** — `strstr(haystack: getenv(UNSET), needle: "y")` — where `to_str` is never called and the pointer reaches libsystem unexamined: `AddressSanitizer: SEGV on unknown address 0x0`. Three of the four options were structurally blind to it. What landed is **E**, which nobody put on the ballot, and **A**: `hero_cstr_nonnull` on every `cstr` argument of an `extern` call, and `nullptr` joining the contextual forms at +19 in two files | **E is the strongest argument of the sitting because it is not a language change at all.** It is a backend obligation of exactly the class CLAUDE.md §7 already states — *"Arithmetic aborts via `__builtin_*_overflow` — never C UB — and `%` is guarded like `/`"* — so `hero_cstr_nonnull` is to a null `cstr` what `__builtin_mul_overflow` is to signed overflow: zero spec tokens, no new type, no new surface. The narrowing is the callee's **declared parameter type**, deliberately not provenance, because *"this value came from an extern"* is a premise about where a value has been and this compiler has no flow-sensitive narrowing to rest one on (CLAUDE.md §11); the price is that a `cstr` from `s.cstr()`, which cannot be null, is checked too — one predictable branch, against §12's rule that safety outranks speed. **A moved from cheapest to necessary** under that same rule: without it the null test is unwritable, so the guard would fire on programs whose authors had no means to prevent it. A makes the check writable, E makes its omission survivable.
