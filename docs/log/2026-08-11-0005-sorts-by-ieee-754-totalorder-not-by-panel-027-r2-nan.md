2026-08-11 | **`[f64]` sorts by IEEE 754 totalOrder, not by `<`** (panel 027 R2). NaN appears in neither design.md nor the spec, and it is reachable — "division by zero aborts" is implemented for integers, so `0.0 / 0.0` is a NaN — and a `<`-based sort with one in the input yields an unspecified permutation. Rust gives `f64` `PartialOrd` and not `Ord` for exactly this reason, and Go had to **fix** `slices.Sort`, whose predecessor documented that it "may fail to sort correctly" with NaNs | determinism is an M8c fixpoint requirement, not a nicety, and totalOrder agrees with `<` everywhere the spec is observable — so it costs zero spec tokens | §4.14, Part 8 | 027 |
