# 010 — The spec-budget ledger

**A dated record, moved rather than rewritten** (panel 086 R1, 2026-08-19). Every
row below was written in `crates/heroes/src/measure/gate.rs`'s doc comment, one
per amendment to `spec/heroes-spec.md`, and every number and citation is here
byte for byte as it was written there. CLAUDE.md §14 does not rewrite a record;
this file is what "moves in the same commit as the spec" now means, because that
Rust file has gone to `archive/bootstrap-rs/` and a ledger nobody maintains is a
fossil (the sitting's own words for option C).

**What enforces it is not this file.** The figure is what `heroes measure`
computes from the spec; `tests/harness/suite_spec.hero` pins it, re-derives it on
every run, and — since panel 086 R2 — checks this record against it three ways:
the row count matches `LEDGER_ROWS`, the newest row's figure matches
`SPEC_TOKENS`, and `SPEC_TOKENS` matches what the compiler measures today. The
warden's rule, adopted with the move: **a number may live in a second place only
if it is checked or dated.** A row is dated. A pin is checked. Nothing here is
neither.

**How to append.** In the same commit as the spec change, with the delta and its
payment — a named removal, or a prediction naming an instrument that exists today
and the milestone at which it is scored (panel 012 as amended by panel 046). Then
`SPEC_TOKENS` and `LEDGER_ROWS` in `tests/harness/suite_spec.hero`, or the harness
goes red with the three numbers side by side.

The spec's measured size, `max` over both vendored instruments — the binding
number, never an estimate.

Every change to this constant belongs in the same commit as the spec change
that caused it, with the delta and its justification in the commit body.
