# DECIDE — the decisions the compiler is waiting on

Read by **`/decide`**. Every item here asks **what should be true**, and until it
is answered the compiler goes on behaving some way by default. That default is
the cost of leaving an item open, so each item names it.

**Only open items live here.** The moment one is answered it is ticked with the
verdict written into it and moved to `docs/work/DONE.md`. A file that keeps its
own closed items stops being a list of what is owed — this one held **138 ticked
items and zero open ones** on 2026-08-26, under eighteen headings still titled
`## Open`, which is why the rule now lives in `/decide` itself instead of in
prose about `/decide`.

**One notation: `- [ ]`.** No section headings, no prose sections, no
strikethrough. A finding written as a bare bullet is invisible to every count in
this project, and nine of them sat in exactly that shape under two panel
headings here until 2026-08-26 — **five already closed** and two of those
measurably stale, while the file reported itself empty.

Two rules bind this file, both learned the hard way:

- **Verify before asking.** An entry is a claim from the day it was written, and
  entries outlive their causes. Asking the author about a settled question is the
  one cost this list cannot pay. Of the nine findings recovered on 2026-08-26,
  five were closed and were ticked with what closed them rather than asked.
- **Rank by what it blocks**, never by age, and say the blocker in the question.

Format: `- [ ] <origin> | <what> | <where to look> | <why it matters>`

- [ ] found 2026-08-26 by the instrument `/decide` answer `6a` built | **`heroes run` cannot pass on an argument it cannot read, and it aborts instead of saying so.** Measured: `heroes run prog.hero -- $(printf '\377\376')` is `panic: hero_str_from_bytes: not well-formed UTF-8`, **exit 134** — the COMPILER dying, not the program. `selfhost/main.hero:55` reads its own command line with `args()`, and the arguments after `--` are not its own. The consequence is exact and worth stating: **`args_checked`, the one spelling the spec provides for surviving such an argument, is unreachable through the dev loop** — only a binary built with `heroes build` can use it, which is why the new instrument builds one. **This is a limit to decide rather than a fix that was skipped**: a Heroes `str` IS UTF-8 (spec:52), so the compiler cannot represent that argument in order to hand it on. **Three ways out**: (a) `main` reads `args_checked()` and refuses a malformed argument with a diagnostic at exit 2, naming its position and telling the author to build the binary — honest, and the most `run` can ever do; (b) the same, but the refusal fires only for the compiler's OWN arguments and everything after `--` is passed through by some route that never becomes a `str` — new machinery at the C boundary; (c) leave it, and let the dev loop die on an argument the shell chose. **The default while it waits**: (c), and the abort names a runtime function rather than the author's command line | selfhost/main.hero:55 · tests/harness/suite_special.hero (the case, with the measurement in its comment) · spec:186 · docs/panel/089, 090 (the same shape one department over: the compiler could be killed by an environment variable) | §12 says a build tool's worst outcome is a wrong answer, and its second worst is dying on input it was only asked to carry

- [ ] **PANEL BRIEF, instructed 2026-08-26, REWRITTEN the same day after its central premise was measured FALSE — author answers `1c` + `2a`, one sitting** | **C variadics: what `...` would have to buy, now that the hole it was going to close does not exist.** **THE CORRECTION FIRST, because a sitting briefed on a dead premise is this project's named failure (CLAUDE.md §1).** The item this replaces said *"a C variadic bound at a fixed arity compiles, runs, and its width is checked by nothing... an `int -1` reads `-1` on arm64 and `4294967295` on x86-64, the same program, two answers, no diagnostic."* **That is false, panel 052 ratified the opposite, and the emitted C settles it.** `heroes build --emit-c` on `printf(format: cstr, value: i32)` with `-1` produces `int32_t t3; t3 = INT64_C(-1); (void)printf(hero_cstr_nonnull(t2), t3);` — the call goes through `<stdio.h>`'s own prototype with **no re-declaration**, so an `int32_t` in a variadic slot stays `int` everywhere clang runs. 052's ratified words: *"A variadic bound with a fixed arity is correct, because §4.19 refuses to re-declare and the call goes through the header's own prototype; the Heroes declaration never reaches C."* **So there is no ABI hole and this sitting is not a repair.** **What is actually open, measured 2026-08-26.** (1) `...` does not parse: `error[expected_parameter]` at the dot. (4) **New, and nobody had it at 051 or 052**: the compiler CAN see that a header declares a function variadic. `__builtin_types_compatible_p(__typeof__(printf), int(const char *, int))` is **0** while the same test against `int(const char *, ...)` is **1**, and `strlen` answers 1 and 0 the other way round — one `_Static_assert` written from the author's own declaration separates them, and this compiler already emits that builtin on every field. **THE TWO STANDING VETOES THE SITTING INHERITS**, both from 052 and both ratified: the llm-ergonomist vetoed `...` outright (*"`...` suspends the spec's strongest FFI protection exactly where C punishes hardest, and every mistake it permits compiles"*), and the ffi-pragmatist holds a permanent veto on **any variadic implementation that emits a re-declared prototype**, measured as silently correct on x86-64 and garbage on arm64. **So the question is: what does `...` buy that the rename clause does not, given that the fixed-arity binding is already ABI-correct — and can it be built without tripping either veto?** Lanes: full five, because `...` is surface syntax, spec tokens and a diagnostic class.
