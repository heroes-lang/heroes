  **What it was.** `shift(a: @n, b: @n)` gave `heroes check` **0**, `heroes run` **0**, and printed **10** — the divergence panel 010 sat over, arriving silently. §4.8's copy-in/copy-out gives last-write-wins, so `b`'s `+ 10` overwrites `a`'s `+ 1`, while the reference semantics every mainstream language installs would give **11**. All four shapes the entry listed passed: the cell, the field, the index, and a three-argument `bump` printing 100. So `spec:80`'s *"No aliasing exists anywhere"* was false of a program the compiler accepted, and §12 says the spec beats the compiler.

  **Why it hid for a month, and it is two accidents rather than one.** design.md's own three examples were written `shift(a @ n, b @ n)`, a spelling `misplaced_mutable_marker` refuses today with a `certain` fix — so anybody who pasted the document's own example got a diagnostic and could read it as the rule firing. And the unlabelled `shift(@n, @n)` fires `needs_label` first, so the alias question is reached only once **both** labels are written, which is exactly the form nothing tested. Panel 010 R6 had assigned the work to *"the routine that already builds the label→argument map for the same-typed-argument rule"*; **that routine does not exist** — `user_call` builds a list of positions whose lowered types coincide and fetches each label on the fly — and the record carried no entry for the assignment in either direction.

  **The repair.** `writes.refuse_aliased_places`, called **once** from `resolve/walk.hero`'s `arguments` after the walk over the arguments, because it compares the places that walk resolved. It lives in `resolve/writes.hero` rather than the checker for three measured reasons: `arguments` is the single funnel for all four call shapes (call, both method forms, variant case); every legal `@` root is a `resolved.Ref.local(at:)` because `.top` and `.builtin` roots are already `no_mutable_globals`, so the test needs no types at all; and `check/walk.hero` is **2071 lines** against `writes.hero`'s 99. The diagnostic is `error[aliased_mutable_arguments]`, and its home is beside the rule for the reason `constant_body`'s is beside `cycles.hero`'s rather than in `errors.hero` — which is also at 229 of the 300 ceiling.

  **PLACES, not roots, and that is the change panel 110 forced.** design.md:1298 said *"comparing roots is a complete alias test"*, and a root test refuses two programs that work: `shift(a: @p.x, b: @p.y)` and `shift(a: @xs[0], b: @xs[1])`. The convener's counter was a memory-safety worry — two `@` pointers into one copy-on-write buffer, where a second unshare could move it — and it was **measured rather than argued**: both programs, with the record and the array *shared* so an unshare must happen, print `1 10` and are clean under `--sanitize`. The first unshare takes the refcount to 1, so the second moves nothing. So §12's robustness rule does not protect the root test and §12's *"a refusal is held to a feature's standard"* condemns it. The walk now stops at the first pair of steps that is **decidably** different — two field names, or two indices written as plain decimal digits — and treats everything else as overlapping: a variable index, a base this pass does not decode (`ast.hero:109` keeps a literal's TEXT and decoding is the checker's job, so `xs[0x0]` is undecided rather than distinct), and a prefix (`@p` against `@p.x`). `f(a: @xs[i], b: @xs[j])` is still refused, which is the over-rejection `design.md:1299` always named.

  **The repair is a `guess` and that is the rule's own argument turned on the fix.** design.md:1288 said `certain` for a month. Panel 110's compiler-engineer built it and ran it: `n: i64 @ 0` / `t: i64 @ n` / `shift(a: @n, b: @t)` prints **1** — a third answer, at exit 0, compiling clean, where the program prints 10 and the reference reading gives 11. CLAUDE.md §9's harness asks an applied `certain` fix to *compile*, not to mean the same thing, so `--apply` would have turned a 10-program into a 1-program with CI green. It also demolished both of the convener's stated reasons: `apply` (`selfhost/cli/check.hero:200-259`) collects every `certain` fix, sorts by span and applies them in reverse, so a multi-span edit **is** already expressible; and the resolver's lack of types does not block a repair keyed on a syntactic root. The tree's own doctrine settles it instead — `d.fixes` is a list of **alternatives** (`number.hero:105-108` ships two `guess` spellings of one literal), and two readings make two guesses. Two `guess` fixes ship: pass a copy, or make the two places different.

  **Verified.** The entry's four shapes are now `check` 1 and `run` 1, and the two programs panel 110 saved print `1 10`. Nine in-module tests in `resolve/walk.hero` (11 → 20 blocks), covering the cell, the field, the index, variable indices, distinct fields, distinct literal indices, the prefix, the undecided base, the three-argument case as two findings, the unlabelled form, and the nested call. **572 tests, all passed.** Eight golden diagnostics read and quoted before their `.expected` was written, each naming the right place — `n`, `p.x`, `xs[0]`, `xs[j]`, `xs[0x0]`, `p.y`, and two `n`. `aliased_mutable_arguments` is deliberately **not** in `is_thesis_rule`, by that function's own stated test: a thesis rule is one *"without which the program has no meaning"* is false, and without this refusal `shift(a: @n, b: @n)` has no meaning — so `--permissive` must not drop it. **And one live claim that had expired was corrected in the same commit**: `tests/golden/run/inout-through-paths-of-a-cell.hero:10` asserted in a comment that two `@` arguments through one cell are *"panel 010's alias refusal, whatever the indices"* — a sentence nothing ran, wrong twice over, since the refusal did not exist and, when it landed, landed as places rather than roots.
