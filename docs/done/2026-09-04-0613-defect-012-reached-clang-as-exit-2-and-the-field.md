  **What it was.** Eight lines, no `???`: `function takes_nothing(_: ()) -> i64`. `heroes check` said **0**, and the emitter wrote `int64_t h_f(void h0_);` — `error: argument may not have 'void' type`, `internal error`, **exit 2**, the compiler blaming itself for the author's program.

  **The cause, and it is a genuinely narrow door.** `refuse` calls `check_type` on a parameter's type and on the result with the **same** function, and `()` as a result is legal — it is C's `void` — so `check_type`'s `.unit` arm returns, exactly as its own comment says it should. Nothing asked the parameter position separately. And `_` is the **one** spelling that reaches the emitter: a named `()` parameter is `unused_binding` when it is not read and `bound_unit` when it is, and `_` binds nothing, so neither rule fires. Measured: `function f(x: ())` with no use is exit 1, with a use is exit 1, and calling `f(g())` with a real `()` value from a `()`-returning function is still exit 2.

  **It is `unit_fields`' sibling, twelve lines away.** That function's own comment records the identical defect for `record Box { u: () }` on 2026-08-12 — *"walked straight past the gate and reached clang as `void f_u;` — field has incomplete type, exit 2, the compiler blaming itself"* — and the parameter next to it was never done. CLAUDE.md §1's *"a repair shipped without its adjacent shapes"*, at twenty-three days.

  **The repair.** Five lines inside the loop that already walks `f.params`, raising `unsupported[unit_parameter]` beside `unit_field` and `unit_element`, plus its own route in `what_the_author_can_do` — *"drop the parameter — `()` carries no value, so a caller has nothing to pass"*, which is the honest advice because dropping it does fix the program. `unsupported` and not a hard error, for consistency with both siblings: the language admits the form and the backend does not express it yet.

  **And the ceiling did its job, which is the point of pinning it.** `selfhost/emit/gate.hero` was at **341 code lines against a pinned 341** — zero room — so the repair could not be written without reading the count. `suite_layout`'s pin goes to **365** against a measured 360, with the reason in the prose above the table, as every earlier raise there has one. The alternative was splitting a gate file to dodge a number, which is the `toolchain.rs` mistake.

  **Verified.** `unsupported[unit_parameter]: `()` as the type of a parameter is not emitted yet` at exit 1 on the reproducer, with its `#~` annotation, in `tests/golden/unsupported/` beside the field case it is the sibling of. `heroes fmt` re-formatted the file and the count was re-measured after the formatter, not before.
