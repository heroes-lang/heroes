- [x] found by the CI's first run | CI run 4, 2026-08-13 | **Does the FFI see the platform's headers as a POSIX system sees them, or strictly as C11? The two platforms disagree, and today the language's own promise is what breaks.** `tests/golden/run/ffi-constant.hero` binds `constant M_PI: f64` from `math.h`. On Darwin it compiles; on Linux the compiler says, correctly, `error[ffi_unknown_name]: `math.h` declares no `M_PI` — clang read the header and could not find it`. Neither side is wrong: **`M_PI` is not in C11** — it is POSIX/XSI — and glibc hides it under `-std=c11`, which defines `__STRICT_ANSI__`, while Darwin's `math.h` defines it unconditionally. CLAUDE.md §7 says the generated C is C11, and §4.19's whole promise is *"clang checks every signature and constant against that header, so a wrong FFI type is a compile error"*. Under strict C11 on glibc, a large part of what anybody actually binds — `M_PI`, `strdup`, `fileno`, `strtod_l` — is simply **invisible**, so the same `.hero` file compiles on one platform and not the other. That is the failure §4.19 exists to prevent, arriving through the flags rather than through the types. Three answers, and it is an architecture question (CLAUDE.md §4 — a panel path, and the panel does not block): (a) compile generated C as `-std=gnu11`, which is what every real C build does and what the headers are written for, at the cost of §7's sentence; (b) keep `-std=c11` and have the emitter define `_DEFAULT_SOURCE`, which is narrower and still a deliberate departure from the standard the project names; (c) keep strict C11 and accept that the FFI can only reach ISO C, which makes §1.11's *"everything comes from C libraries"* false in a way the SQLite acceptance test happens not to notice. **Meanwhile the golden is red on Linux and green on Darwin, and that is left visible rather than papered over** | tests/golden/run/ffi-constant.hero · crates/heroes-cli/src/commands/toolchain.rs (FLAGS) · CLAUDE.md §7 · design.md §4.19, §1.11 | the one promise the C backend exists to keep is the one that does not survive a second platform **CLOSED 2026-08-14 by panel 047, ratified.** Answer (a): `toolchain.rs` names `-std=gnu11`, and the ratification's content was that the dialect is *named* rather than which one won. `gnu11` over `c11` followed from the measurement — one predefined macro, `__STRICT_ANSI__`, identical IR.
