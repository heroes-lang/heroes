2026-08-14 | **Robustness and a complete C boundary become a principle, design.md §1.12** (author instruction: *"metti nei principi del progetto la robustezza, il fatto che possa chiamare completamente qualsiasi programma C, e che sia molto robusto, quindi anche difensivo"*). It sits beside §1.11 because it is that constraint's **consequence** and not a separate wish: if everything a program touches comes from C, the C boundary is where this language's guarantees end, and a guarantee that ends quietly is not one. Two halves. *A Heroes program must not segfault and must not corrupt memory* — a goal of the **language**, not a quality of its implementation. And the boundary is **complete**: any C library must be bindable, because a library Heroes cannot reach is C code the author has to keep writing by hand, which is §1.11 failing at the one thing it exists to do. §1.1's hierarchy gains a fourth force above tokens; CLAUDE.md §12 keeps the operational rule and now cites §1.12 as its argument | **no panel, and the reason is worth stating**: a panel judges proposals *against* the project's goals and cannot judge the goals themselves — Principle 0 is an author decision for the same reason. What the principle does **not** do is suspend §1.0: *"it would be safer"* is not an entry ticket any more than *"it would be elegant"*, and what §1.12 decides is the shape of a form already admitted. The **defensive** half is the one that costs: the compiler checks at the boundary even where the value is known to be good — a `cstr` from `s.cstr()` cannot be null and is null-checked anyway — because the alternative reasons about where a value came from, and provenance is a premise about the world (§11). The precedent is this project's own §7, which already makes arithmetic abort through `__builtin_*_overflow` rather than reach C's undefined behaviour; §1.12 states that obligation as a principle so the next boundary needing one is not argued from scratch.
