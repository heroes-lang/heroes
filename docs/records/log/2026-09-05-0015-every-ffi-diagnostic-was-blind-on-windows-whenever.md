2026-09-05 | **Every FFI diagnostic was blind on Windows whenever the source path was absolute, and one line of arithmetic is the whole cause** (defect 014, M-c-callbacks step 4). `selfhost/emit/ffi_site.hero`'s `location()` parsed clang's `<file>:<line>:<col>: <severity>: <message>` by taking the **first three colons** — and on Windows **the first colon is the drive letter's**, so the file name came out as `C`, the line number as the rest of the path, and the parse refused because that is not a number. `location()` is the gate **every** `ffi_*` classifier passes through, so width, sign, class, arity, format string, writable parameter and callback type all fell through to **exit 2 together** — the compiler blaming itself for the author's declaration, which is §4.19's own named failure — on the platform where an author is most likely to type an absolute path. **Measured on the real box**: the same callback mismatch is exit 1 on macOS and exit 2 on Windows under `C:/Users/…/note.hero`, and exit 1 under a relative path. **Nothing caught it because CI compiles relative paths**, so the Windows leg has never produced a line with a drive letter in it, and nine sittings have touched this function's callers with no Windows box in front of them.
