2026-09-09 | M-cstr-lifetime | Two lines of a program, one brace apart, and one of them was a lie. Both handed a piece of text to a C library. The first handed over a word that had been written into the program by the person who wrote the program, and that word lives somewhere that never goes away, so the library could read it whenever it liked. The second handed over a word the program had just built out of two other words, and that one lives in a place the program tidies up on its way out of the room. The library read it afterwards. Nothing complained. Every single warning the C compiler owns was switched on and it had nothing to say; the program finished and reported success; and the number it printed was zero where the answer was seventeen. Which is the worst kind of wrong, because a crash at least argues with you. So a rule was written to refuse the second line, and the first thing that happened was that the rule refused a program that was perfectly fine — a small, dull, entirely legal piece of plumbing that exists because the language insists on it. Which is how the discussion stopped being about lifetimes and became about where you have to look to know whether a line is allowed. One judge, who is given nothing but the language's own description and never sees the machinery, pointed out that under the first draft two lines that look exactly alike would differ in legality according to something declared in a different file, and refused it on that ground alone. Another, sent to find out what other languages had done, came back with a null result more useful than any example: nobody anywhere decides how long a borrowed thing may live by asking what kind of function is being called. And a third, which compiles rather than argues, built the program the rule was supposed to catch and then built a second one that walked straight through it — the borrowed thing handed to an innocent little helper, which handed back exactly what it was given, and out it went. That hole was closed by refusing something much simpler than a lifetime: no ordinary function may hand one of these out at all, which nobody in the whole body of code had ever wanted to do anyway, so it cost nothing to forbid. Then came the part that turned the milestone around. Two of the judges, working from opposite ends and without knowing it, wrote the same program: every borrowed word handed over exactly where the rule permits, and a C library that simply keeps the pointer instead of reading it and letting go. That one no rule about places can see, because what decides it is not where the words sit in the program but a promise made by the library, in a number passed as its fifth argument, and both possible values of that number look identical from outside. Which meant the thing being fixed had been two things all along, and only one of them was being fixed. And then somebody went looking and found that the project had known for weeks: in a working piece of database code there is a comment above exactly that shape, explaining carefully that it is safe here because every caller happens to do the next thing in the next line, and adding, in so many words, that this is the one place where tidying the code up would break it. A rule written down for a human being to remember is not a rule. So the second half was written on the list of things that are broken, with the two programs attached, and the milestone was finished and deliberately left untagged — because the mark at the end of a milestone means the ground is clear, and it is not.
