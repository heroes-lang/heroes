2026-09-02 | M-documentation-site | The site that explains the language had thirteen chapters and not one of them said where a program's files go. That is the part of the language that had changed most recently: a program can now spread over folders, a line naming another file means the same thing wherever you copy it to, and there is deliberately no way to reach upward out of your own project. A reader arriving at the site could learn how numbers work, how errors work, how to talk to C, and would leave with no idea how to write a program in more than one file. So: a fourteenth chapter, in both languages, and the interesting part is what it is built out of. Every piece of code on the page is a slice of one real program in the repository, quoted with the file name and the line numbers, and checked automatically against the file so that documentation going stale becomes a failing test rather than an embarrassment somebody notices later. Which buys something nobody planned: that program prints one number for the folder at the top and a different one for the folder underneath, so if the rule about where files are found ever changes, the program's expected output changes, the tests go red, and the page cannot quietly become a lie. The three error messages on the page are real output, produced by taking the working program and breaking it three ways on purpose, and one of those three is a rule the compiler learned that same afternoon, from a defect a different piece of this week's work turned up. Four numbers elsewhere on the site turned out to be out of date while this was being written, and the one the plan had complained about was not among them: it had been fixed already, and the one that was actually wrong was a line count that this very evening's repairs had moved.
