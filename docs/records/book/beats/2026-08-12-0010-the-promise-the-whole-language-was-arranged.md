2026-08-12 | M-ffi-ladder | The promise the whole language was arranged around turned out to be false for the pair its own second example uses, and nobody could have found that by reading. The arrangement is this: when a program borrows a function from a C library, the compiler does not describe that function itself — it points at the library's own description and lets the C compiler check the two against each other. That is the reason the language emits C at all. But pointing at a description only checks what you *pass*, never what you get back, so a program that says a square-root function returns a whole number compiles without a murmur, runs, and prints 1 where it should print 1.41. Four wrong borrowings out of six passed in silence. The repair is one line per borrowing, and it costs nothing when the program runs: a question put to the C compiler in a form that asks about a call's type without ever making the call.
