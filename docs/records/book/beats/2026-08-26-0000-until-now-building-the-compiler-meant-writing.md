2026-08-26 | M-separate-compilation | Until now, building the compiler meant writing out one enormous file — nearly eight hundred thousand lines — every single time, even if you had changed a comma. The milestone was to split that into one piece per module, so that touching one file rebuilds one piece. The first attempt failed with twenty complaints from the C compiler, and the failure was worth more than a success would have been: each *section* of a piece had been deciding for itself what it needed, and four sections deciding separately cannot share one file. One of them would name a type that another had decided not to include. The fix was to let a single decision feed all four, and the way to make that decision correctly turned out to be to ask the question the way C reads a declaration rather than the way the compiler stores a type. Then the deeper problem, which is the one this whole milestone existed to find. Reusing yesterday's work is only safe if you can tell that nothing it depended on has changed, and the label used to decide that was the text the compiler had generated. But when a program borrows a number from a C library's header file, the compiler does not write the number down — it writes down the *name*, and lets C fill it in later. So editing the header changes the answer and does not change one character of the generated text. Measured before the repair: a program printed one while the file on disk said two, and then printed one again while it said seven. Exit code zero, no complaint, no crash, a wrong answer wearing the face of a right one. The repair was to stop guessing and ask the C compiler itself, as it works, which files it actually opened — and then to check that every one of them still says what it said. The same hole existed in a second place nobody had looked, where it was worse: it would have let a program be built half against one version of the system's own libraries and half against another. And then, almost by accident, the milestone found where all the time had been going. Checking the compiler's own source took a minute and a half, and a profile said that ninety-nine per cent of it was inside one small function whose job was to answer *which line is this*. It answered by counting from the beginning of the file, every time, and it was being asked once for every declaration and once for every comment, on a file over a million characters long. But nobody wanted to know which line. The question was only ever *is this comment directly above this declaration*, which is a question about two lines that are next to each other. Asking for the distance instead of the position took a minute and a half down to about eight seconds, and three more copies of a related mistake — a list being copied whole every time something was added to it — took it the rest of the way. No design changed. Four instances of one small habit did. The last thing the milestone did was to look at its own instruments and find one lying: the check that makes sure every error message is marked in the program that provokes it, which the project calls its one unforgeable check, can only see two folders — and nineteen of those marks live outside them, in the folder set aside for mistakes that already shipped once.
