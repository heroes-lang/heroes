2026-08-14 | M-binding-fidelity | The description of the language made a promise about the boundary with C: declare a foreign function wrongly, and the program will not build. It was half a promise. What a foreign function *hands back* had been checked since the day the boundary existed; what it *takes* had never been checked at all, and two independent readers demonstrated it the same way — a program that passes a number too large for the slot it is going into, compiles without complaint, runs, and prints a different number. Forty-two per cent of everything anybody actually binds has a slot like that. The check could not be switched on, because the trick that makes the first half free — asking a question the compiler answers without ever running the code — is exactly what stops it seeing a conversion. So the compiler now writes a small function nobody ever calls, whose only purpose is to make the call once, in a place where the C compiler is obliged to look at it, and points its line number at the line the author wrote.
