# M-issue-files: every item one GitHub issue, transcribed from one file each

**Opened 2026-10-04 by author instruction**, at row 83 of the chain and ahead of
every scheduled row (`docs/roadmap/scheduling.md`). The decision and how every
value was derived are
https://github.com/heroes-lang/heroes/issues/1654; the rules
are `.claude/rules/records.md` § The issues, their one home.

**What it delivers.** Every item the project tracks, open or closed, as one
issue of `heroes-lang/heroes`, in the order of its birth. First as one file
each of `issues/` (2026-10-04), in the folder of its name's day, a card on each
saying what GitHub needs, nothing moving when it closed; then transcribed by
`tests/harness/issues.hero` as issues 1 to 2,029 (panel 212, ratified
2026-10-11); and then, by the author's answers of 2026-10-12, **the issues on
GitHub alone**: the folder leaves the tree as this milestone's last work, the
rules, the skills, the hooks and the harness rewritten for GitHub, a new issue
drafted outside the tree and opened, closed and corrected through the program,
its writes asked once, and a check that cannot ask GitHub saying `SKIP`.

**What it deliberately does not deliver**: a verb of `heroes` for the issues,
which panel 212's R1 refused for a program of the harness; and the milestones,
the labels and every other write to GitHub, which stay outward acts, the
author's every time (CLAUDE.md § Hard stops).

**What closes it**: its open `feature` and `task` issues settled or carried
with their reason, the folder out of the tree, the full net green on the
trunk, and the tag placed over a list clean of `blocking` and `systemic`
defects (CLAUDE.md § Verification).
